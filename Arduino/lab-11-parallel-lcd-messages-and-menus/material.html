Parallel LCD Messages and Menus

Give your Arduino a readable desk display, then keep its messages tidy as the user changes a selection.

Lab MaterialPracticePractice Quiz

What you will learn

  • Wire a 5V parallel LCD with contrast and backlight connections.
  • Place text inside a 16×2 layout without leaving old characters behind.
  • Update a small menu only when an accepted action changes it.

On your bench

  • Arduino Uno R3 and USB data cable
  • Known 5V HD44780-compatible 16×2 parallel LCD with its module datasheet
  • 10k ohm potentiometer for contrast
  • 220 ohm resistor for the backlight unless the datasheet specifies onboard limiting
  • Two normally open momentary buttons
  • Breadboard and jumper wires

Meet the components

Recognise the parts in the photos, then follow the labelled task diagrams for connections.

Before you build

  • Upload one standalone task at a time. Disconnect USB before wiring or moving parts. Use USB power and common GND; leave Uno D0/D1 free. This lesson uses the parallel LiquidCrystal library, not an I2C backpack or an address-based library.
  • Verify your module's supply and labelled terminals first. Common 16-pin modules use VSS, VDD, VO, RS, R/W, E, DB0–DB7, and backlight A/K, but do not infer physical orientation from these diagrams. A header viewed from behind reverses its apparent order.
  • Follow all three teaching task 1 figures together. The six signal wires carry control and four-bit data. Ground R/W for writes. Leave LCD DB0–DB3 unconnected. The potentiometer spans 5V/GND with its wiper at LCD VO for contrast.
  • Use the backlight's separate 220 ohm series resistor unless its datasheet confirms suitable onboard limiting at 5V. A lit backlight alone does not prove the controller is receiving data. Adjust contrast gently after a verified upload.
  • For later buttons, choose contacts that connect only when pressed; four-leg tactile switches have internally joined pairs. INPUT_PULLUP buttons connect to GND and read LOW when held. The sketches adopt held-at-start levels without creating a press.

LCD Wiring and Character Positions

Task 1 · Guided build

A two-line desk sign

The LiquidCrystal library handles the HD44780 signalling while your sketch works with characters. Its six-argument constructor lists the Uno pins connected to RS, E, and LCD DB4 through DB7, in that order. Four-bit mode sends each byte in two parts; it still carries ordinary character data. begin(16, 2) initializes this display size. Visible columns run from 0 to 15 and rows from 0 to 1. setCursor takes column first, then row. Each printed character advances the cursor. Keep each message within its intended row rather than relying on automatic wrapping. A character display stores characters after they are written, so a static sign does not need a continuous stream from loop. Separate three jobs while checking the build: supply runs the controller, contrast makes its cells readable, and the backlight illuminates the panel. None substitutes for correctly ordered signal wires. A dark character position can therefore have several causes. Start with a known short message and change one thing at a time, preserving a verified starting sketch for later comparisons.

  1. With power disconnected, complete the supply, contrast, signal, and backlight connections in all three figures. Include LiquidCrystal.h from the official Arduino LiquidCrystal library; install that library through Library Manager if it is unavailable.
  2. Upload the complete sign sketch. Adjust only the contrast knob until both lines are readable. It does not set an application value or change the text.
  3. Locate the first character of each row. Reset the board and confirm that the same complete message returns.
Arduino sketch · guided example
#include <LiquidCrystal.h>
// Constructor order: RS, E, DB4, DB5, DB6, DB7 (Uno pin numbers).
LiquidCrystal lcd(12, 11, 5, 4, 3, 2);
void setup() {
  lcd.begin(16, 2); // Declare the visible column and row counts.
  lcd.setCursor(0, 0);
  lcd.print("DESK READY");
  lcd.setCursor(0, 1);
  lcd.print("Please take note");
}
void loop() {
  // A static sign needs no repeated printing.
}

Observe and check

  • Both messages fit on their own rows. No text depends on a timer or repeated loop calls.
  • If you see only blocks or a blank lit panel, check contrast and the six signal connections with power off before assuming the sketch needs different text.

Experiment

  • Choose two new desk messages, each no longer than sixteen characters, and plan their row and starting column.

Clean Text Updates

Task 2 · Guided build

Choose a short desk break

Writing a shorter word does not erase the rest of a previous word. The row helper first writes sixteen spaces, returns the cursor to the beginning, and prints the new text. Its const char* parameter refers to a text string; the choices array stores three such strings. selected is an index, and the modulo expression wraps it back to zero after the final choice. A 30 ms stable LOW transition advances the selection once. Holding the button creates no repeats. Redrawing only when the choice changes avoids continuous erasing and visible flicker. Debouncing and redrawing belong to different stages. The input stage turns a sufficiently stable electrical change into an event; the application stage changes the selected index; the output stage redraws the changed row. The detector must continue observing releases even when nothing is printed. Keeping those stages separate makes a held button, contact bounce, and a genuinely new press distinguishable. The sixteen-space erase is intentionally limited to one row, preserving the heading and making the replacement independent of the previous word length.

  1. Reuse the complete Task 1 LCD circuit. Add the next button from Uno D7 to GND as shown; D7 is not one of the six LCD signal pins.
  2. Upload with the button released. Read, Stretch, and Water should cycle in that order, beginning with Read.
  3. Hold the button, release it for at least 30 ms, and press again. Watch the shorter words replace longer ones without leaving letters at their right.
Arduino sketch · guided example
#include <LiquidCrystal.h>
// Constructor order: RS, E, DB4, DB5, DB6, DB7 (Uno pin numbers).
LiquidCrystal lcd(12, 11, 5, 4, 3, 2);
// Erase exactly one visible row before printing its replacement.
void writeRow(byte row, const char* text) {
  lcd.setCursor(0, row);
  lcd.print("                "); // Sixteen spaces clear old trailing characters.
  lcd.setCursor(0, row);
  lcd.print(text); // Every supplied message is at most sixteen characters.
}
bool rawButton = HIGH, stableButton = HIGH;
unsigned long changedAt = 0;
bool newPress(unsigned long now) {
  bool reading = digitalRead(7);
  if (reading != rawButton) { rawButton = reading; changedAt = now; }
  if (reading != stableButton && now - changedAt >= 30UL) {
    stableButton = reading;
    return stableButton == LOW;
  }
  return false;
}
const char* choices[] = {"Read", "Stretch", "Water"};
byte selected = 0;
void setup() {
  lcd.begin(16, 2);
  pinMode(7, INPUT_PULLUP);
  rawButton = digitalRead(7);
  stableButton = rawButton; // A button held at startup is not a new press.
  changedAt = millis();
  writeRow(0, "Choose break");
  writeRow(1, choices[selected]);
}
void loop() {
  unsigned long now = millis();
  if (newPress(now)) {
    selected = (selected + 1) % 3;
    writeRow(1, choices[selected]); // Redraw only the changed row.
  }
}

Observe and check

  • Row 0 remains Choose break. Each accepted press changes only the selected word on row 1.
  • A held-at-start button produces no advance until a release and later accepted press.

Experiment

  • Explain why clearing the entire display repeatedly would also erase the unchanged heading.

Column Budgets

Task 3 · Guided build

Plan a small appointment sign

A row is a fixed layout, not a line of a word processor. Before writing, add the starting column and the message length; the last occupied column is one less than that sum. A ten-character heading starting at column two ends at column eleven, leaving space on both sides. Treat each field as an assigned region so one update cannot overwrite its neighbor. This example places a label and time in separate regions on the second row. The time is supplied text, not a running clock. Changing a displayed time string does not add timekeeping to the sketch. Draw the cell ranges first, then use setCursor for each independent field. Avoid relying on the controller to wrap a long string onto the visible next row: internal display memory does not behave like a normal terminal. A layout plan also gives you a simple boundary check when a message changes.

  1. Reuse the complete teaching task 1 circuit and upload this standalone layout.
  2. Count character cells, including spaces, before moving either label.
Arduino sketch · guided example
#include <LiquidCrystal.h>
LiquidCrystal lcd(12, 11, 5, 4, 3, 2);
void setup() {
  lcd.begin(16, 2);
  lcd.setCursor(2, 0);
  lcd.print("WORK TABLE");
  lcd.setCursor(0, 1);
  lcd.print("Starts ");
  lcd.setCursor(7, 1);
  lcd.print("09:30");
}
void loop() {
}

Observe and check

  • The time occupies a separate field without changing the heading.

Experiment

Fixed-Width Number Fields

Task 4 · Guided build

Keep a countdown field tidy

Numbers change width as they cross powers of ten. Printing 99 over 100 without replacing all three cells can leave a false final digit. A fixed-width field prevents that problem: this sketch prints three digits every time, adding leading zeros when needed. The label occupies nine cells and the number occupies columns nine through eleven. Only that field is rewritten, leaving the label and other row intact. The byte value is sufficient for the supplied range zero through 120, but a wider range would need a suitable type and field width. A due-time test decrements once and schedules from the actual update; a late loop therefore does not replay every missed second. This is a small display demonstration, not a precision elapsed-time instrument. Test width transitions explicitly because an ordinary midrange value would not reveal a stale-character defect.

  1. Upload using the teaching task 1 LCD circuit.
  2. Inspect the transitions 100 to 099, 010 to 009, and 001 to 000.
Arduino sketch · guided example
#include <LiquidCrystal.h>
LiquidCrystal lcd(12, 11, 5, 4, 3, 2);
byte remaining = 120;
unsigned long updatedAt = 0;
void showNumber() {
  lcd.setCursor(9, 1);
  if (remaining < 100) lcd.print('0');
  if (remaining < 10) lcd.print('0');
  lcd.print(remaining);
}
void setup() {
  lcd.begin(16, 2);
  lcd.print("Short desk break");
  lcd.setCursor(0, 1);
  lcd.print("Seconds: ");
  showNumber();
  updatedAt = millis();
}
void loop() {
  unsigned long now = millis();
  if (remaining > 0 && now - updatedAt >= 1000UL) {
    updatedAt = now;
    --remaining;
    showNumber();
  }
}

Observe and check

  • The field always occupies three cells and stops at zero.

Experiment

  • Explain what must change before increasing the start value to 1200.

Bounded Text and Padding

Task 5 · Guided build

Replace an entire tray-status row

A reusable row writer can enforce the display boundary rather than trusting every caller to provide a short message. This helper visits exactly sixteen output cells. Before the string ends it writes its characters; after the null terminator it writes spaces. The ended flag is important: once the terminator has been seen, the helper stops reading later string positions. That avoids reading beyond a short character array while still filling the rest of the visible row. Long messages are clipped after sixteen characters. This is deliberate truncation, not automatic scrolling, so choose text that remains understandable when shortened. lcd.write sends one character value, whereas lcd.print can format numbers or strings. Keeping the output width constant makes replacement independent of the old text. Test an empty string, a short word, and a sixteen-character message to understand both the memory boundary and the display boundary.

  1. Reuse the full LCD circuit and upload the complete bounded-row example.
  2. Watch the longer tray message alternate with the shorter word.
Arduino sketch · guided example
#include <LiquidCrystal.h>
LiquidCrystal lcd(12, 11, 5, 4, 3, 2);
void boundedRow(byte row, const char* text) {
  lcd.setCursor(0, row);
  bool ended = false;
  for (byte i = 0; i < 16; ++i) {
    char value = ended ? ' ' : text[i];
    if (value == '\0') { ended = true; value = ' '; }
    lcd.write(value);
  }
}
bool shortMessage = false;
unsigned long changedAt = 0;
void setup() {
  lcd.begin(16, 2);
  boundedRow(0, "Supply tray");
  boundedRow(1, "Return pencils");
  changedAt = millis();
}
void loop() {
  unsigned long now = millis();
  if (now - changedAt >= 2000UL) {
    changedAt = now;
    shortMessage = !shortMessage;
    boundedRow(1, shortMessage ? "Ready" : "Return pencils");
  }
}

Observe and check

  • No trailing letters remain, and the heading is untouched.

Experiment

  • Pass an empty string to row 1 and predict its sixteen cells.

Display Fault Isolation

Task 6 · Explore and measure

Separate contrast from missing data

A lit panel is only one observation. It confirms that some backlight current is flowing, not that the LCD controller has received a valid command. Use the verified two-line desk-sign sketch from teaching task 1 unchanged for this experiment. Keeping the program fixed prevents a wiring or contrast investigation from turning into several simultaneous changes. With power disconnected, check the functional terminal labels, the grounded R/W connection, and the constructor-to-wire correspondence. Then power the circuit and adjust contrast slowly while watching the same message. The contrast control changes cell visibility; it does not change stored characters or the backlight supply path. A readable result should return after a board reset without requiring a different sketch. Do not move powered jumpers to manufacture faults. Record observations in ordinary words, distinguishing what you saw from what it proves, and return to the last verified connection set before trying another correction.

  1. Upload the unchanged teaching task 1 sign.
  2. Follow the power-off checks, then compare visibility at several gentle contrast settings.

Observe and check

  • A visibility change does not imply the stored message changed.

Experiment

  • State one additional check you would make if the heading were readable but the lower row were not.

Text Windows and Array Bounds

Task 7 · Guided build

Show a longer leaving reminder

A text window displays a selected part of a longer stored message. The string remains unchanged while the starting index moves. Each update copies exactly sixteen consecutive characters, so the row is completely replaced and needs no separate erase. The last valid starting index equals the character count minus the window width. sizeof on this local character array also counts its null terminator, which is why the calculation subtracts one first. This calculation depends on message being an array here; it should not be copied unchanged into a function that receives only a pointer. The supplied message is longer than sixteen characters, so the subtraction is valid. Each due update advances one position and wraps after the final valid start. A late pass advances only once. Planning the final copied index is a direct way to prevent reading the terminator or memory beyond the array as visible text.

  1. Upload using the same full LCD wiring.
  2. Watch one full sweep, then inspect the first and final source slices.
Arduino sketch · guided example
#include <LiquidCrystal.h>
LiquidCrystal lcd(12, 11, 5, 4, 3, 2);
const char message[] = "Check the desk before you leave";
const byte lastStart = sizeof(message) - 1 - 16;
byte start = 0;
unsigned long movedAt = 0;
void showWindow() {
  lcd.setCursor(0, 1);
  for (byte i = 0; i < 16; ++i) lcd.write(message[start + i]);
}
void setup() {
  lcd.begin(16, 2);
  lcd.print("Desk reminder");
  showWindow();
  movedAt = millis();
}
void loop() {
  unsigned long now = millis();
  if (now - movedAt >= 1200UL) {
    movedAt = now;
    start = start == lastStart ? 0 : start + 1;
    showWindow();
  }
}

Observe and check

  • Row 0 stays fixed while row 1 displays complete sixteen-character windows.

Experiment

  • Choose a different message longer than sixteen characters and calculate its last valid start.

Visibility and Stored Characters

Task 8 · Guided build

Temporarily hide a desk sign

LiquidCrystal separates character storage from whether those characters are visible. noDisplay turns off the character display without erasing its stored text, and display makes it visible again. These commands do not disconnect the supply or control the separate backlight current path. The example alternates visibility every three seconds while preserving the exact two-line sign written during setup. It does not repeatedly send the strings. This distinction is useful when an interface should briefly hide information without rebuilding its layout. Do not confuse a hidden display with a blank row that has actually been overwritten by spaces: one is an output mode and the other changes stored content. Keep the timing state separate from the displayed characters, and schedule changes from actual loop timestamps. During the hidden interval, the Arduino still executes loop. A visible backlight with no characters is expected here, so use the known sketch behavior before diagnosing that observation as a wiring fault.

  1. Upload the standalone visibility example without changing wiring.
  2. Observe characters and backlight separately through two hide/show cycles.
Arduino sketch · guided example
#include <LiquidCrystal.h>
// Constructor order: RS, E, DB4, DB5, DB6, DB7 (Uno pin numbers).
LiquidCrystal lcd(12, 11, 5, 4, 3, 2);
bool visible = true;
unsigned long changedAt = 0;
void setup() {
  lcd.begin(16, 2); // Declare the visible column and row counts.
  lcd.setCursor(0, 0);
  lcd.print("DESK READY");
  lcd.setCursor(0, 1);
  lcd.print("Please take note");
  changedAt = millis();
}
void loop() {
  unsigned long now = millis();
  if (now - changedAt >= 3000UL) {
    changedAt = now;
    visible = !visible;
    if (visible) lcd.display();
    else lcd.noDisplay();
  }
}

Observe and check

  • Both original rows return without another print call.

Experiment

  • Explain why removing power would not be the same operation as noDisplay.
