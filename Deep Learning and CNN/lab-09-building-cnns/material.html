Python · shared setup
import tensorflow as tf
import keras
import numpy as np
import matplotlib.pyplot as plt
keras.utils.set_random_seed(109)
rng = np.random.default_rng(109)
# Locally drawn object icons, not photographs; colors vary independently of class.
class_names = np.array(['plate', 'cup', 'bottle'])
def draw_object(label, generator):
    yy, xx = np.mgrid[:24, :24]
    if label == 0:
        radius = np.sqrt((xx - 12) ** 2 + (yy - 12) ** 2)
        mask = (radius >= 5) & (radius <= 7)
    elif label == 1:
        mask = (yy >= 8) & (yy <= 17) & (xx >= 6) & (xx <= 15)
        mask &= ~((yy < 14) & (xx >= 8) & (xx <= 13))
        handle = (xx - 16) ** 2 + (yy - 11) ** 2
        mask |= (handle <= 9) & (handle >= 4) & (xx >= 15)
    else:
        mask = ((yy >= 8) & (yy <= 20) & (xx >= 9) & (xx <= 15))
        mask |= (yy >= 3) & (yy <= 8) & (xx >= 11) & (xx <= 13)
    mask = np.roll(mask, tuple(generator.integers(-2, 3, 2)), axis=(0, 1))
    color = generator.uniform(0.5, 0.95, 3)
    background = generator.uniform(0.02, 0.10)
    picture = background + mask[:, :, None] * color + generator.normal(0, 0.015, (24, 24, 3))
    return np.clip(picture, 0, 1).astype('float32')
labels = np.repeat(np.arange(3, dtype='int32'), 60)
images = np.stack([draw_object(int(label), rng) for label in labels])
train_ids, val_ids, test_ids = [], [], []
for label in range(3):
    ids = rng.permutation(np.flatnonzero(labels == label))
    train_ids.extend(ids[:40])
    val_ids.extend(ids[40:50])
    test_ids.extend(ids[50:])
train_ids = rng.permutation(np.array(train_ids))
val_ids = rng.permutation(np.array(val_ids))
test_ids = rng.permutation(np.array(test_ids))
x_train, y_train = images[train_ids], labels[train_ids]
x_val, y_val = images[val_ids], labels[val_ids]
x_test, y_test = images[test_ids], labels[test_ids]

def batches(x, y, batch_size=16, shuffle=False):
    ds = tf.data.Dataset.from_tensor_slices((x, y))
    if shuffle:
        ds = ds.shuffle(len(x), seed=123, reshuffle_each_iteration=True)
    options = tf.data.Options()
    options.threading.private_threadpool_size = 1
    options.threading.max_intra_op_parallelism = 1
    return ds.batch(batch_size).with_options(options)

Guided task 01

Dataset and label contracts

Before fitting, establish what one example and one target mean. Each input is a twenty-four-by-twenty-four RGB drawing, stored as float32 values in the interval zero to one. Each target is one integer: zero for plate, one for cup and two for bottle. The class-name order is part of the model contract, because the same output position must keep the same meaning during training and reporting.

The generator varies color, position and small pixel noise independently of the class. These changes make the fixture less trivial than three identical templates, but it remains a narrow procedural drawing distribution. A useful score here would not establish recognition of actual dishes or bottles in photographs. The setup splits IDs within each class before fitting, giving every role a known class coverage. Inspect several training examples and confirm that their displayed names match their shapes. A mislabeled image or reversed class-name list can undermine an otherwise valid training pipeline. Keep test images out of architecture decisions even though the arrays are available locally.

Try it

  1. Check input shape, value range and integer labels.
  2. Select three training examples of each class.
  3. Display a labelled grid and verify the class-name mapping.
Python · run in order
selected = np.concatenate([np.flatnonzero(y_train == label)[:3] for label in range(3)])
fig, axes = plt.subplots(3, 3, figsize=(6, 6))
for ax, index in zip(axes.flat, selected):
    ax.imshow(x_train[index])
    ax.set_title(class_names[y_train[index]])
    ax.axis('off')

Guided task 02

Trace shapes through a CNN

A CNN architecture is easier to understand when every layer’s output shape is written down. The first valid three-by-three convolution reduces height and width from twenty-four to twenty-two and produces four channels. A two-by-two max-pooling layer halves that grid to eleven by eleven. The second convolution keeps those dimensions with same padding and produces eight channels.

Global average pooling then averages each feature map over its spatial positions, leaving eight values per image. A final Dense layer turns those values into three class scores. Its output has no activation, so these are logits rather than probabilities. The bars below count activations for one example at each stage; they are not parameter counts. Parameters are shared across spatial locations in the convolutional layers, while activation counts grow with the number of evaluated positions. This task only checks an untrained architecture. Its intermediate numerical values carry no learned object-recognition interpretation yet. First make dimensions correct, then ask what training changes.

Try it

  1. Build the stated two-convolution architecture.
  2. Pass one drawing through each layer and record its shape.
  3. Plot activation counts for the successive outputs and print the total parameter count.
Python · run in order
cnn = keras.Sequential([
    keras.Input((24, 24, 3)),
    keras.layers.Conv2D(4, 3, activation='relu', padding='valid'),
    keras.layers.MaxPooling2D(2),
    keras.layers.Conv2D(8, 3, activation='relu', padding='same'),
    keras.layers.GlobalAveragePooling2D(),
    keras.layers.Dense(3)
])
current = tf.convert_to_tensor(x_train[:1])
shapes = []
for layer in cnn.layers:
    current = layer(current)
    shapes.append(tuple(current.shape))
activation_counts = [int(np.prod(shape[1:])) for shape in shapes]
print('Shapes:', shapes, 'Parameters:', cnn.count_params())
fig, ax = plt.subplots(figsize=(7, 4))
ax.bar(['conv 4', 'pool', 'conv 8', 'global mean', 'scores'], activation_counts)
ax.set(ylabel='Activations per example', title='Spatial size and channel count both matter')
fig.tight_layout()

Read the result

The activation bars describe intermediate tensors. The parameter count is much smaller than some activation counts because the same convolution weights are reused at many positions.

Change and compare

  • Calculate the first convolution’s parameter count including its biases.
  • Explain why global averaging leaves eight values rather than three.

Guided task 03

Train with a matching output and loss

The final three values are unrestricted logits. Sparse categorical cross-entropy with from_logits=True is appropriate because each target is a single integer class ID and the model does not apply softmax in its final layer. Adding a softmax while still describing the loss input as logits would break the stated numerical contract. The loss implementation handles the conversion needed for training internally.

This run builds a fresh model and trains it for six epochs on shuffled paired training batches. Validation loss is recorded after each epoch, but those records do not supply gradient updates. The dataset helper owns the ordering policy, so fit is not asked to shuffle a dataset a second time. Read the actual curves rather than expecting an arbitrary accuracy threshold. A small CPU-friendly network may learn slowly, and the global-mean representation may limit which spatial arrangements it can distinguish. Those are legitimate outcomes to inspect. The reserved test remains untouched while architecture and training choices are still being explored.

Try it

  1. Build a fresh copy of the architecture.
  2. Compile Adam at 0.005 with sparse cross-entropy from logits.
  3. Train six epochs and plot training and validation loss.
Python · run in order
keras.utils.set_random_seed(309)
cnn = keras.Sequential([
    keras.Input((24, 24, 3)),
    keras.layers.Conv2D(4, 3, activation='relu', padding='valid'),
    keras.layers.MaxPooling2D(2),
    keras.layers.Conv2D(8, 3, activation='relu', padding='same'),
    keras.layers.GlobalAveragePooling2D(),
    keras.layers.Dense(3)
])
cnn.compile(optimizer=keras.optimizers.Adam(0.005), loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True), metrics=[keras.metrics.SparseCategoricalAccuracy(name='accuracy')])
history = cnn.fit(batches(x_train, y_train, 16, shuffle=True), validation_data=batches(x_val, y_val), epochs=6, verbose=0, shuffle=False)
fig, ax = plt.subplots(figsize=(6, 4))
ax.plot(np.arange(1, 7), history.history['loss'], 'o-', label='training')
ax.plot(np.arange(1, 7), history.history['val_loss'], 'o-', label='validation')
ax.set(xlabel='Epoch', ylabel='Sparse cross-entropy', title='A small CNN on drawn objects')
ax.legend()
fig.tight_layout()

Read the result

The plotted values are measured during this fit. Report their trend and any gap without claiming that these drawn examples establish performance on real photographs.

Change and compare

  • Inspect whether both loss series improve over the allowed budget.
  • State why integer labels require no one-hot conversion for this selected loss.

Guided task 04

Convert logits for a readable prediction report

Softmax turns a row of class logits into nonnegative values that sum to one. The largest logit and the largest softmax value have the same class index, so argmax can produce the predicted ID from either representation. Keep the class axis explicit: for a batch-by-three array, each row belongs to one image and the last axis contains its three classes.

The report below displays probability vectors for four validation drawings, along with the true and predicted class names. A largest value is a model score, not a guarantee that the image belongs to that class. With a tiny procedural dataset and short training, mistakes or flat vectors are informative observations. Avoid silently changing the class-name ordering to make a prediction look plausible. Store the original integer IDs and convert them to names only through the fixed mapping. This task reads the trained model from the preceding task and uses training=False so inference behavior is explicit. It does not change weights or tune a threshold using the final test set.

Try it

  1. Run inference on four validation drawings using the trained cnn.
  2. Apply softmax along the final class axis and take one argmax per row.
  3. Plot each score vector with the fixed class-name order.
Python · run in order
logits = cnn(x_val[:4], training=False).numpy()
probabilities = tf.nn.softmax(logits, axis=-1).numpy()
predicted = probabilities.argmax(axis=1)
fig, axes = plt.subplots(2, 2, figsize=(8, 6))
for i, ax in enumerate(axes.flat):
    ax.bar(class_names, probabilities[i])
    ax.set_ylim(0, 1)
    ax.set_title(f'true: {class_names[y_val[i]]}; predicted: {class_names[predicted[i]]}')
    ax.set_ylabel('Softmax value')
fig.tight_layout()

Read the result

Read both the class ordering and the true/predicted labels. A confident-looking error remains an error; a probability vector is evidence about this model’s output, not proof of correctness.

Change and compare

  • Check that each row sums to one.
  • Explain why axis=0 would normalize a different quantity for this batch.

Guided task 05

Inspect learned intermediate maps

After training, the first convolution contains learned weights rather than the manually supplied filters from the previous lab. A small feature-extraction model can return that layer’s output while sharing the same trained parameters. This does not create a second training process or change the classifier. It exposes intermediate activations for inspection.

The four maps below correspond to the first layer’s four output channels for one validation image. They are post-ReLU values because that activation is configured inside the convolution layer. Use a common color scale across maps so differences in magnitude are visible rather than normalized away independently. A bright location means that this channel responds strongly there for this input. It does not establish that the model understands a cup handle or that this map caused the final prediction. Such interpretations need additional evidence. First learn to identify the layer, spatial grid and activation convention. A trained map is useful diagnostic information, but naming it after an object part too quickly can turn a numerical observation into an unsupported explanation.

Try it

  1. Create a model from cnn inputs to its first convolution output.
  2. Run one validation image through this feature extractor in inference mode.
  3. Display the original drawing and all four maps with a common scale.
Python · run in order
extractor = keras.Model(inputs=cnn.inputs, outputs=cnn.layers[0].output)
maps = extractor([x_val[:1]], training=False).numpy()
fig, axes = plt.subplots(1, 5, figsize=(12, 3))
axes[0].imshow(x_val[0])
axes[0].set_title(class_names[y_val[0]])
upper = max(float(maps.max()), 1e-6)
for channel in range(4):
    axes[channel + 1].imshow(maps[0, :, :, channel], cmap='magma', vmin=0, vmax=upper)
    axes[channel + 1].set_title(f'Channel {channel}')
for ax in axes:

fig.tight_layout()

Guided task 06

Flattening and global averaging change the head

The classifier head receives the final feature grid and turns it into class scores. Flattening an eleven-by-eleven-by-eight grid gives nine hundred sixty-eight values. A Dense layer can assign a different weight to each spatial position and channel. Global average pooling instead summarizes each of the eight maps with one mean, leaving only eight input values for the same three-class Dense output.

The parameter difference is large because each Dense input connects to every class output, with an added bias per class. This task builds only the two heads, so it compares their parameter counts without introducing another training experiment. Fewer parameters can reduce storage and limit the head’s flexibility, but global averaging also discards explicit within-map position information. It is not automatically the better choice for every problem. A task that depends on where a feature appears may need a different representation. Treat the head as a modeling decision with a concrete information tradeoff, and evaluate it under a controlled procedure rather than selecting it solely from a smaller bar.

Try it

  1. Build two heads for an input feature shape of (11, 11, 8).
  2. Use Flatten in one and GlobalAveragePooling2D in the other, each followed by Dense(3).
  3. Plot their parameter counts without training them.
Python · run in order
flat_head = keras.Sequential([keras.Input((11, 11, 8)), keras.layers.Flatten(), keras.layers.Dense(3)])
mean_head = keras.Sequential([keras.Input((11, 11, 8)), keras.layers.GlobalAveragePooling2D(), keras.layers.Dense(3)])
head_counts = [flat_head.count_params(), mean_head.count_params()]
fig, ax = plt.subplots(figsize=(6, 4))
ax.bar(['Flatten + Dense', 'Global mean + Dense'], head_counts)
ax.set(ylabel='Trainable head parameters', title='A spatial summary changes the head size')
fig.tight_layout()

Guided task 07

Verify that a training update changes weights

A successful forward pass proves that tensor shapes connect, but it does not prove that a training update reaches the intended weights. Copy a trained classifier into a separate probe, compile it with a fresh optimizer and apply one batch update. Store weight arrays before and after the update, then compare their numerical differences.

Cloning a model copies its architecture; set_weights is the explicit step that copies the trained values in this demonstration. The probe has its own optimizer state and does not continue the original optimizer’s history. That is appropriate because the goal is to inspect one fresh update, not reproduce an uninterrupted training run. Leave the original cnn untouched so later inference checks still refer to the same model. Small nonzero changes show that gradients and updates reached a tensor, but they do not guarantee an improvement in validation performance. Conversely, an unchanged tensor needs investigation of trainability, gradient paths and the chosen batch before concluding that the entire model failed to learn.

Try it

  1. Clone the trained architecture and explicitly copy its weights.
  2. Compile a fresh optimizer and save copies of all trainable arrays.
  3. Train on one sixteen-example batch and plot the change norm for each array.
Python · run in order
probe = keras.models.clone_model(cnn)
probe.set_weights(cnn.get_weights())
probe.compile(optimizer=keras.optimizers.SGD(0.01), loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True))
before = [w.numpy().copy() for w in probe.trainable_weights]
batch_loss = probe.train_on_batch(x_train[:16], y_train[:16])
changes = np.array([np.linalg.norm(w.numpy() - old) for w, old in zip(probe.trainable_weights, before)])
fig, ax = plt.subplots(figsize=(7, 4))
ax.bar(np.arange(len(changes)), changes)
ax.set(xlabel='Trainable array index', ylabel='L2 norm of change', title='One update on an independent probe')
fig.tight_layout()

Read the result

Look for finite update magnitudes and identify the kernel/bias order from the layer list. This numerical check confirms a change, not that the changed model is better.

Change and compare

  • Confirm that the original cnn predictions do not change when only probe is trained.
  • Explain why copying architecture is different from copying learned values.

Guided task 08

Inference batching preserves example meaning

An inference batch is a computational grouping, not a new class definition. This CNN has no batch-dependent inference operation, so evaluating twelve images together should agree numerically with evaluating them in four smaller groups and concatenating the outputs in the original order. Floating-point implementations can introduce tiny rounding differences, so compare with a tolerance rather than demanding identical bytes.

Keep preprocessing, weight values, training mode and ordering fixed during the check. Calling training=False is especially important in models that later include dropout or other mode-sensitive behavior. Concatenating along the wrong axis or reordering a subset can produce a plausible-shaped report whose rows no longer match the labels. The plot shows each image’s maximum absolute score difference between the two evaluation routes. This is a pipeline-consistency test, not a performance metric. Agreement says the batching route preserved predictions under these conditions; it says nothing by itself about whether the predicted classes are correct or whether the fixture resembles deployment images.

Try it

  1. Evaluate twelve validation images in one inference call.
  2. Evaluate the same ordered images in groups of three and concatenate along the batch axis.
  3. Plot the per-image maximum absolute logit difference.
Python · run in order
whole = cnn(x_val[:12], training=False).numpy()
pieces = [cnn(x_val[i:i+3], training=False).numpy() for i in range(0, 12, 3)]
joined = np.concatenate(pieces, axis=0)
differences = np.max(np.abs(whole - joined), axis=1)
fig, ax = plt.subplots(figsize=(6, 4))
ax.scatter(np.arange(12), differences, s=35, clip_on=False, label='Measured differences')
ax.axhline(1e-6, color='tab:orange', linestyle='--', label='Comparison tolerance')
ax.set_ylim(0, max(1.15e-6, float(differences.max())*1.15))
ax.ticklabel_format(axis='y', style='sci', scilimits=(-3,3), useOffset=False)
ax.text(0.02, 0.76, f'Maximum difference: {differences.max():.2g}', transform=ax.transAxes)
ax.legend(loc='center right', fontsize=8)
ax.set(xlabel='Validation example position', ylabel='Maximum absolute logit difference', title='Check inference batching consistency')
fig.tight_layout()

Read the result

Differences should be zero or small numerical rounding effects. Preserve the row order when relating this result to labels; score agreement is not an accuracy claim.

Change and compare

  • Repeat with groups of four.
  • Explain why sorting only the predictions before comparison would invalidate the check.
