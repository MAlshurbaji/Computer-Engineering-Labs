Python · shared setup
import numpy as np
import tensorflow as tf
import keras
import matplotlib.pyplot as plt
keras.utils.set_random_seed(111)
rng = np.random.default_rng(111)
class_names = ["cup", "bottle"]

def batches(x, y, batch_size=16, shuffle=False):
    ds = tf.data.Dataset.from_tensor_slices((x, y))
    if shuffle:
        ds = ds.shuffle(len(x), seed=123, reshuffle_each_iteration=True)
    options = tf.data.Options()
    options.threading.private_threadpool_size = 1
    options.threading.max_intra_op_parallelism = 1
    return ds.batch(batch_size).with_options(options)

# A group is one drawn object; its two noisy views must stay together.
def pictures(group_ids, tint=False):
    images, labels, groups = [], [], []
    for gid in group_ids:
        local = np.random.default_rng(int(gid) + 800)
        label = int(gid) % 2
        shift = int(local.integers(-1, 2))
        base = np.zeros((16, 16), dtype=np.float32)
        if label == 0:
            base[6:13, 4+shift:10+shift] = 0.85
            base[7:11, 10+shift:12+shift] = 0.85
            base[8:10, 10+shift:11+shift] = 0
        else:
            base[3:6, 7+shift:9+shift] = 0.85
            base[6:13, 5+shift:11+shift] = 0.85
        for view in range(2):
            image = np.repeat(base[..., None], 3, axis=-1)
            if tint:
                image = image * np.array([0.7, 0.9, 1.0], dtype=np.float32)
            image = np.clip(image + local.normal(0, 0.025, image.shape), 0, 1)
            images.append(image.astype("float32"))
            labels.append(label)
            groups.append(gid)
    return np.stack(images), np.array(labels, dtype="int32"), np.array(groups)

train_ids = np.arange(0, 32)
val_ids = np.arange(32, 40)
test_ids = np.arange(40, 48)
x_train, y_train, g_train = pictures(train_ids)
x_val, y_val, g_val = pictures(val_ids)
x_test, y_test, g_test = pictures(test_ids)

def classifier(augmentation=None):
    inputs = keras.Input((16, 16, 3))
    z = inputs if augmentation is None else augmentation(inputs)
    z = keras.layers.Conv2D(4, 3, padding="same", activation="relu", name="features")(z)
    z = keras.layers.MaxPooling2D()(z)
    z = keras.layers.Flatten()(z)
    outputs = keras.layers.Dense(2, name="scores")(z)
    model = keras.Model(inputs, outputs)
    model.compile(optimizer=keras.optimizers.Adam(0.005),
                  loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
                  metrics=["accuracy"])
    return model

def augment(seed=111):
    return keras.Sequential([
        keras.layers.RandomFlip("horizontal", seed=seed),
        keras.layers.RandomTranslation(0.10, 0.10, fill_mode="constant",
                                       fill_value=0.0, seed=seed+1)
    ])

Guided task 01

Group-aware Data Splits

Imagine a desk camera seeing the same cup twice. Putting its first picture in training and its second in validation gives a misleadingly familiar evaluation. A split should separate the underlying objects before creating or distributing related views. Here each group identifier describes one drawn object, and its two pictures share shape and position while their pixel noise differs. The fixtures use cups and bottles as visible learning examples, not photographs of real products.

The setup assigns complete groups to training, validation, and test. Both class labels occur in each partition; label zero means cup and one means bottle. Images have shape N×16×16×3, use float32, and already follow a fixed zero-to-one scale. No population statistics are estimated from the held-out partitions. Repeating a group identifier within training is expected, whereas finding that identifier in another partition is a leakage error.

Inspect the drawings before trusting any model score. A clean group split removes this particular leakage route, but the generator still produces a narrow family of shapes. New cups, backgrounds, cameras, or lighting could behave differently.

  1. Run setup once in a fresh notebook.
  2. Compare representative training and validation drawings.
  3. Check the printed group counts before proceeding.

fig, axes = plt.subplots(1, 4, figsize=(9, 3))
for ax, image, label in zip(axes, x_train[[0, 2, 4, 6]], y_train[[0, 2, 4, 6]]):
    ax.imshow(image)
    ax.set_title(class_names[label])
    ax.axis("off")
print("Groups:", len(train_ids), len(val_ids), len(test_ids))

Guided task 02

Label-preserving Transformations

Augmentation makes a training image vary while keeping its intended target unchanged. That condition depends on the meaning of the classes. A cup remains a cup when its handle appears on the other side, so horizontal reflection is acceptable for this drawing task. A left-arrow versus right-arrow classifier would need a different policy. Do not choose a transformation just because a library offers it.

The augmentation sequence combines a possible horizontal flip with small translations. A factor of 0.10 allows shifts up to ten percent of the image size along an axis. Constant zero filling matches the dark background. Interpolation can create intermediate intensities at edges, so transformed pictures need not contain exactly the original pixel values. The output remains the same tensor shape.

Calling the sequence with training=True requests new transformations. This inspection is intentionally performed on training data. Look for cropped handles, broken bottle necks, or shifts that remove the identity-defining region. Keeping the numeric label unchanged is only correct when the picture still supports that label. Small, inspectable transformations are a better starting point than a large unchecked menu.

Try it

  1. Build one seeded augmentation sequence.
  2. Apply it to four copies of a cup.
  3. Inspect identity and border fill in every view.
Python · run in order
augmentation = augment()
copies = np.repeat(x_train[0:1], 4, axis=0)
views = augmentation(copies, training=True).numpy()
fig, axes = plt.subplots(1, 4, figsize=(9, 3))
for i, ax in enumerate(axes):
    ax.imshow(views[i])
    ax.set_title("View " + str(i + 1))
    ax.axis("off")
fig.tight_layout()

Read the result

The four outputs show sampled transformations of the same drawn cup. Some views can look similar because randomness does not guarantee a visibly different result on every call. Inspect the entire transformed object rather than judging only the background.

Guided task 03

Training and Inference Modes

A preprocessing layer can behave differently while a model learns and while it is evaluated. These random image augmentation layers transform inputs during training and pass them through during ordinary inference. Setting training=False makes that mode explicit when inspecting or evaluating a model. A validation result should not silently vary because the evaluator keeps randomly moving each image.

A seed makes an experiment reproducible under a controlled software environment. It does not mean that one layer produces the same transformation forever: random state advances across calls. Two fresh layers initialized with the same seed and given the same input sequence provide a useful reproducibility check. In contrast, repeatedly calling a single layer samples successive views.

The display compares the original picture, a training-time result, and an inference-time result. The numerical maximum absolute difference verifies the identity behavior at inference more precisely than eyesight. This distinction also matters when the augmentation sequence becomes the first component of a classifier: model.fit invokes the training path, while the explicit inference calls used later do not.

Try it

  1. Create two fresh augmentation sequences with identical seeds.
  2. Compare their first transformed outputs.
  3. Verify that inference leaves the input unchanged.
Python · run in order
a1, a2 = augment(71), augment(71)
first = a1(x_train[:1], training=True).numpy()
repeat = a2(x_train[:1], training=True).numpy()
inference_view = a1(x_train[:1], training=False).numpy()
fig, axes = plt.subplots(1, 3, figsize=(8, 3))
for ax, image, title in zip(axes, [x_train[0], first[0], inference_view[0]], ["Original", "Training", "Inference"]):
    ax.imshow(image)
    ax.set_title(title)
    ax.axis("off")
print("Inference difference:", np.max(np.abs(inference_view-x_train[:1])))
fig.tight_layout()

Read the result

The inference image should match the original exactly. The two fresh seeded sequences are checked numerically, not selected for an attractive visual result. Subsequent samples from an already-used sequence need not match its first sample.

  • Call a1 a second time and compare the result.
  • Explain which mode belongs in a fixed validation evaluation.

Guided task 04

A Controlled Baseline

Before adding a technique, establish a reference run. The baseline uses a small convolution, pooling, flattening, and a two-score output. The output scores are logits, so the loss is sparse categorical cross-entropy with from_logits=True. The labels remain integer class indices. No softmax layer is needed when only the largest score determines the predicted class.

This model trains only on the training partition. The validation loss monitors a separate set of object groups after each epoch. A loss curve can reveal unstable optimization or a widening training-validation difference, but a few tiny-data epochs cannot prove deployment readiness. The selected architecture is intentionally small enough to run on a CPU.

Save the initialization of this baseline before fitting it. The augmented comparison will start from those same numeric weights, making the augmentation policy the main planned difference between the two runs. Random batch ordering and finite optimization still matter, so this is an instructive controlled comparison, not a claim that one short run establishes a universal winner. Keep the test set unused while deciding how to compare the models.

Try it

  1. Create the baseline and copy its initial weights.
  2. Fit six epochs using training and validation batches.
  3. Plot both loss histories against epoch number.
Python · run in order
baseline = classifier()
initial_weights = [w.copy() for w in baseline.get_weights()]
base_history = baseline.fit(batches(x_train,y_train,shuffle=True), validation_data=batches(x_val,y_val), epochs=6, shuffle=False, verbose=0)
fig, ax = plt.subplots(figsize=(6, 3))
ax.plot(np.arange(1,7), base_history.history["loss"], label="Train")
ax.plot(np.arange(1,7), base_history.history["val_loss"], label="Validation")
ax.set(xlabel="Epoch", ylabel="Cross-entropy", title="Baseline loss")
ax.legend()
fig.tight_layout()

Read the result

Read loss as an optimization measurement, not a percentage correct. Check that losses stay finite and that the curves are plausible. A lower validation loss is useful evidence within this fixture, but the drawings do not cover real desk scenes.

Change and compare

  • Repeat with three epochs and compare learning progress.
  • Explain why initial weights are copied before fitting.

Guided task 05

Learning with Augmented Inputs

An augmentation layer placed inside the model keeps the transformation policy alongside the learned classifier. The original training arrays are not overwritten. Each training batch passes through the policy, then through the same convolutional structure used by the baseline. Validation follows the inference path and therefore sees the unmodified validation pictures.

The new classifier receives the saved initial convolution and dense weights. Augmentation layers have random state but no learned convolution kernels to copy from the baseline. Matching the trainable weight shapes lets the experiment begin from the same learned-parameter initialization. The optimizer is fresh, and both fits use the same epoch budget.

Augmentation may make the training problem harder, so its training loss need not fall as quickly. The useful question is whether the changed learning process helps on a stated evaluation condition. It is possible for this small experiment to show little improvement or even worse performance. Report the measured result rather than writing an expectation into the conclusion. The test partition is still reserved.

Try it

  1. Build a classifier with augmentation at its input.
  2. Restore the saved baseline initialization.
  3. Fit six epochs and compare validation curves.
Python · run in order
augmented = classifier(augment(81))
augmented.set_weights(initial_weights)
aug_history = augmented.fit(batches(x_train,y_train,shuffle=True), validation_data=batches(x_val,y_val), epochs=6, shuffle=False, verbose=0)
fig, ax = plt.subplots(figsize=(6, 3))
ax.plot(np.arange(1,7), base_history.history["val_loss"], label="Baseline")
ax.plot(np.arange(1,7), aug_history.history["val_loss"], label="Augmented")
ax.set(xlabel="Epoch", ylabel="Validation cross-entropy")
ax.legend()
fig.tight_layout()

Read the result

The graph compares measured validation losses from the two completed fits. Similar curves are still informative. Avoid claiming that augmentation guarantees a gain; the policy, sample size, optimization, and chosen test conditions all affect the outcome.

  • Inspect whether the final validation losses differ.
  • Try only flipping in a separate exploratory run.

Guided task 06

Measured Corruption Sensitivity

A robustness question needs a concrete disturbance and a consistent evaluation rule. Here the disturbance is additive pixel noise with known standard deviation, followed by clipping to the allowed intensity range. The original labels remain fixed. The same corrupted validation arrays are shown to both trained classifiers, making their measurements comparable.

These disturbances are generated after the group split and are not added to training for this measurement. They represent an exploratory validation stress test, not independent new objects. Multiple noisy views of one object remain related. The graph uses accuracy, the fraction of correct argmax predictions, at three noise levels. A flat or irregular curve can occur with a small sample.

Noise robustness is only one property. It does not establish resistance to occlusion, poor framing, color shifts, or adversarial changes. Also, a noise scale of 0.16 is large relative to a zero-to-one pixel range. Inspect the perturbed pictures when choosing useful severity levels. Treat these measurements as validation evidence for a predeclared comparison rule, leaving the final test evaluation for the last task.

Try it

  1. Create one fixed noisy validation set per severity.
  2. Evaluate both models on the identical arrays.
  3. Plot measured accuracy against noise standard deviation.
Python · run in order
levels = np.array([0.0, 0.08, 0.16])
noise_rng = np.random.default_rng(501)
robust_scores = np.zeros((2, len(levels)))
for j, sigma in enumerate(levels):
    noisy = np.clip(x_val + noise_rng.normal(0,sigma,x_val.shape),0,1).astype("float32")
    for i, model in enumerate([baseline, augmented]):
        pred = np.argmax(model(noisy,training=False).numpy(),axis=1)
        robust_scores[i,j] = np.mean(pred == y_val)
fig, ax = plt.subplots(figsize=(6,3))
for name, scores in zip(["Baseline","Augmented"],robust_scores):
    ax.plot(levels,scores,"o-",label=name)
ax.set(xlabel="Noise standard deviation",ylabel="Validation accuracy",ylim=(0,1.05))
ax.legend()
fig.tight_layout()

Read the result

Every point is measured from a trained model on the specified validation fixture. The curve summarizes one corruption family and a small number of independent groups. Compare the actual values without treating the drawn objects as representative camera data.

  • Add a severity between the existing points.
  • Explain why both models receive the same noisy arrays.

Guided task 07

Occlusion and Policy Limits

Occlusion hides information instead of merely perturbing its intensity. A rectangular cover over a handle or bottle neck may remove exactly the evidence needed to distinguish the drawings. This is a useful way to investigate a limitation, but the occluded image is not automatically a valid training example with its original label. A human may also find the remaining picture ambiguous.

The task covers a fixed right-hand region of every validation image with the background value. It computes predicted-class agreement with the clean view for each trained classifier. Agreement asks whether a decision changed; it is different from accuracy. Two predictions can agree and both be wrong, or disagree because the corrupted prediction happens to become correct.

Show the location of the cover alongside a representative image so the numerical comparison has visible context. This validation-only probe does not claim that the cover simulates every real obstruction. Keep the policy small and named. If a transformation destroys the defining content, shrinking or rejecting that transformation may be more appropriate than forcing the model to memorize an inconsistent target.

Try it

  1. Create a copy with columns 9 through 12 covered.
  2. Compare clean and covered predictions without training.
  3. Display a paired image and the measured agreement values.
Python · run in order
covered = x_val.copy()
covered[:,4:13,9:13,:] = 0
agreement = []
for model in [baseline,augmented]:
    clean_pred = np.argmax(model(x_val,training=False).numpy(),axis=1)
    cover_pred = np.argmax(model(covered,training=False).numpy(),axis=1)
    agreement.append(np.mean(clean_pred == cover_pred))
fig, axes = plt.subplots(1,3,figsize=(9,3))
axes[0].imshow(x_val[0]); axes[0].set_title("Clean")
axes[1].imshow(covered[0]); axes[1].set_title("Covered")
axes[0].axis("off"); axes[1].axis("off")
axes[2].bar(["Base","Aug"],agreement)
axes[2].set(ylim=(0,1.05),ylabel="Prediction agreement")
fig.tight_layout()

Read the result

Use the image pair to judge what evidence the cover removed. The final panel reports decision consistency, not correctness or a causal explanation. A change is a prompt for investigation rather than proof that one isolated region alone determines the class.

  • Move the cover to background-only pixels.
  • Compare agreement with label-based accuracy.

Guided task 08

A Reserved Final Evaluation

Finish the comparison by stating a selection rule before looking at test predictions. This lesson chooses the model with the greater mean validation accuracy across the three noise conditions measured earlier; a tie chooses the baseline. That rule values the specific noise conditions equally. Another application might prioritize clean accuracy or a different disturbance, but the rule should not be revised after seeing the test answer.

Evaluate the selected model once on the untouched clean test partition. A confusion matrix records true classes by rows and predicted classes by columns. Its diagonal contains correct decisions; off-diagonal counts identify each direction of error. Row totals should match the number of test examples in each class. The test pictures still belong to the same narrow generator, so the result does not imply broad real-world robustness.

Keep the distinction between development and reporting visible. Validation shaped the selection, while test data produced the final reported measurement. Future experiments can propose new policies, but repeatedly selecting whichever policy scores best on this same test set would gradually turn it into another development set. Record the chosen policy and the evaluation condition alongside the number.

Try it

  1. Select using only the recorded validation robustness scores.
  2. Predict the clean test partition once.
  3. Plot a labelled confusion matrix and record the chosen model.
Python · run in order
chosen_index = int(np.argmax(robust_scores.mean(axis=1)))
chosen = [baseline,augmented][chosen_index]
test_pred = np.argmax(chosen(x_test,training=False).numpy(),axis=1)
confusion = np.zeros((2,2),dtype=int)
np.add.at(confusion,(y_test,test_pred),1)
fig, ax = plt.subplots(figsize=(4,3))
ax.imshow(confusion,cmap="Blues")
for r in range(2):
    for c in range(2):
        ax.text(c,r,str(confusion[r,c]),ha="center",va="center",color="white" if confusion[r,c]>confusion.max()/2 else "black")
ax.set(xticks=[0,1],yticks=[0,1],xticklabels=class_names,yticklabels=class_names,xlabel="Predicted",ylabel="True")
print("Chosen:",["baseline","augmented"][chosen_index],"test accuracy:",np.mean(test_pred==y_test))
fig.tight_layout()

Read the result

The matrix is the final clean-test measurement for the validation-selected model. Its total equals the number of held-out views. Report group counts and the drawn-data scope as part of the result rather than presenting accuracy alone.

  • Describe a fresh dataset needed for a real desk camera.
