Evaluating Image Classifiers

MaterialPracticeQuiz

Turn a classifier’s outputs into a report that explains what it gets right and where it struggles. Keep evaluation choices explicit so a single attractive score cannot hide the rest of the evidence.

What you will learn

  • Evaluate one fixed model using aligned held-out image IDs and predictions.
  • Read class-specific errors with confusion matrices and safe denominators.
  • Compare overall and class-balanced summaries.
  • Report confidence and a fixed review policy without treating scores as guarantees.

Before this lab: Complete Building CNNs; understand logits, softmax and the roles of training, validation and test data.

Python · shared setup
import tensorflow as tf
import keras
import numpy as np
import matplotlib.pyplot as plt
keras.utils.set_random_seed(110)
rng = np.random.default_rng(110)
# Locally drawn object icons, not photographs; colors vary independently of class.
class_names = np.array(['plate', 'cup', 'bottle'])
def draw_object(label, generator):
    yy, xx = np.mgrid[:24, :24]
    if label == 0:
        radius = np.sqrt((xx - 12) ** 2 + (yy - 12) ** 2)
        mask = (radius >= 5) & (radius <= 7)
    elif label == 1:
        mask = (yy >= 8) & (yy <= 17) & (xx >= 6) & (xx <= 15)
        mask &= ~((yy < 14) & (xx >= 8) & (xx <= 13))
        handle = (xx - 16) ** 2 + (yy - 11) ** 2
        mask |= (handle <= 9) & (handle >= 4) & (xx >= 15)
    else:
        mask = ((yy >= 8) & (yy <= 20) & (xx >= 9) & (xx <= 15))
        mask |= (yy >= 3) & (yy <= 8) & (xx >= 11) & (xx <= 13)
    mask = np.roll(mask, tuple(generator.integers(-2, 3, 2)), axis=(0, 1))
    color = generator.uniform(0.5, 0.95, 3)
    background = generator.uniform(0.02, 0.10)
    picture = background + mask[:, :, None] * color + generator.normal(0, 0.015, (24, 24, 3))
    return np.clip(picture, 0, 1).astype('float32')
labels = np.repeat(np.arange(3, dtype='int32'), 60)
images = np.stack([draw_object(int(label), rng) for label in labels])
train_ids, val_ids, test_ids = [], [], []
for label in range(3):
    ids = rng.permutation(np.flatnonzero(labels == label))
    train_ids.extend(ids[:40])
    val_ids.extend(ids[40:50])
    test_ids.extend(ids[50:])
train_ids = rng.permutation(np.array(train_ids))
val_ids = rng.permutation(np.array(val_ids))
test_ids = rng.permutation(np.array(test_ids))
x_train, y_train = images[train_ids], labels[train_ids]
x_val, y_val = images[val_ids], labels[val_ids]
x_test, y_test = images[test_ids], labels[test_ids]
# A review rule fixed before the final test evaluation.
review_threshold = 0.60
# Independent, supplied probability reports for practice and quiz calculations.
example_true = np.array([0, 0, 1, 1, 2, 2, 2, 0], dtype='int32')
example_probs = np.array([
    [0.80, 0.10, 0.10], [0.20, 0.60, 0.20],
    [0.10, 0.70, 0.20], [0.40, 0.35, 0.25],
    [0.10, 0.20, 0.70], [0.10, 0.60, 0.30],
    [0.20, 0.30, 0.50], [0.55, 0.25, 0.20]
], dtype='float32')

def batches(x, y, batch_size=16, shuffle=False):
    ds = tf.data.Dataset.from_tensor_slices((x, y))
    if shuffle:
        ds = ds.shuffle(len(x), seed=123, reshuffle_each_iteration=True)
    options = tf.data.Options()
    options.threading.private_threadpool_size = 1
    options.threading.max_intra_op_parallelism = 1
    return ds.batch(batch_size).with_options(options)

Guided task 01

Freeze the evaluation procedure

An evaluation is most informative when the procedure being evaluated is fixed first. This lab uses one specified compact CNN, one six-epoch training budget and a review threshold declared in setup. The architecture and training settings are carried in the code rather than selected by examining test scores. Validation is available for observing the training run, but this exercise does not use it to keep changing the procedure until a preferred result appears.

The input fixture consists of independent locally drawn icon samples with a stratified ID split. The final test set has not supplied gradient updates or architecture choices. Keep that separation visible even though all arrays exist in memory. Once the model is fitted, later tasks compute one table of test predictions and reuse it for several views of the same evidence. If you later decide to redesign the model after seeing test errors, that test has become development evidence for the redesign. A new independent evaluation would then be needed for a fresh final claim. This distinction concerns the decisions made with data, not simply the variable name test.

Try it

  1. Build the fixed compact architecture and compile its matching sparse-logit loss.
  2. Fit six epochs using training batches, with validation only for observation.
  3. Plot the loss history before computing any final-test predictions.
Python · run in order
keras.utils.set_random_seed(310)
cnn = keras.Sequential([
    keras.Input((24, 24, 3)),
    keras.layers.Conv2D(4, 3, activation='relu', padding='valid'),
    keras.layers.MaxPooling2D(2),
    keras.layers.Conv2D(8, 3, activation='relu', padding='same'),
    keras.layers.GlobalAveragePooling2D(),
    keras.layers.Dense(3)
])
cnn.compile(optimizer=keras.optimizers.Adam(0.005), loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True))
history = cnn.fit(batches(x_train, y_train, 16, shuffle=True), validation_data=batches(x_val, y_val), epochs=6, verbose=0, shuffle=False)
fig, ax = plt.subplots(figsize=(6, 4))
ax.plot(np.arange(1, 7), history.history['loss'], label='training')
ax.plot(np.arange(1, 7), history.history['val_loss'], label='validation')
ax.set(xlabel='Epoch', ylabel='Sparse cross-entropy', title='Fixed six-epoch procedure')
ax.legend()
fig.tight_layout()

Read the result

Read the actual development curves. The six-epoch procedure remains fixed for this evaluation, whether the curve is flattering or not.

Guided task 02

Confusion matrices retain error direction

A single accuracy number records how many predictions were correct but not which classes were confused. A confusion matrix keeps that direction. In this lab rows are true classes and columns are predicted classes, always ordered plate, cup, bottle. A cell in the cup row and bottle column counts actual cups reported as bottles. Reversing axes would change the meaning of row-based and column-based calculations later.

Compute test logits once in inference mode, convert them to probability vectors and take one predicted ID per row. Preserve test_ids beside these arrays so image review can return to the correct example. The matrix sum must equal the number of evaluated images, and its diagonal sum must equal the number of correct predictions. Those consistency checks catch omitted rows and alignment mistakes that can hide behind plausible percentages. The annotated chart uses count values, not normalized proportions. Text color changes with cell darkness to keep every count readable. An empty prediction column is meaningful evidence that this model did not choose that class on this test.

Try it

  1. Compute and cache the ordered final-test logits, probabilities and predicted IDs.
  2. Build a three-by-three confusion matrix with true labels as rows.
  3. Display counts with explicit class labels and verify its total.
Python · run in order
test_logits = cnn(x_test, training=False).numpy()
test_probs = tf.nn.softmax(test_logits, axis=-1).numpy()
test_pred = test_probs.argmax(axis=1)
cm = tf.math.confusion_matrix(y_test, test_pred, num_classes=3).numpy()
correct = test_pred == y_test
fig, ax = plt.subplots(figsize=(5, 4))
image_artist = ax.imshow(cm, cmap='Blues', vmin=0, vmax=max(int(cm.max()), 1))
for row in range(3):
    for col in range(3):
        ax.text(col, row, str(cm[row, col]), ha='center', va='center', color='white' if cm[row, col] > cm.max() / 2 else 'black')
ax.set(xticks=range(3), yticks=range(3), xticklabels=class_names, yticklabels=class_names, xlabel='Predicted class', ylabel='True class', title='Final-test confusion counts')
fig.colorbar(image_artist, ax=ax, label='Image count')
fig.tight_layout()

Read the result

Read an off-diagonal cell by naming its true row and predicted column. The chart is the actual outcome of this fixed small experiment, including any absent prediction class.

Change and compare

  • Check that the matrix sum equals the test sample count.
  • Name one possible error direction and locate its cell before reading the value.

Guided task 03

Per-class precision, recall and support

Per-class recall asks how many true examples of a class were recovered. Its denominator is the true-class row total. Precision asks how many predictions of a class were correct; its denominator is the predicted-class column total. Support is the number of true examples, which helps you judge how much evidence a class-specific rate has. These quantities answer different questions even when their values happen to match.

Some denominators can be zero. If a model never predicts bottle, bottle precision cannot be estimated from positive bottle predictions. This worksheet stores zero for such undefined rates to keep arrays finite, while retaining the denominator so the absence of evidence stays visible. That reporting convention is not a claim that zero predictions prove every possible future bottle prediction wrong. Likewise, a class with no true examples has no measured recall. Display support and predicted counts alongside rates when interpreting them. A macro summary over present classes can exclude unsupported classes explicitly, but should name that rule rather than silently changing which classes count.

Try it

  1. Use row totals, column totals and the diagonal of the cached confusion matrix.
  2. Compute rates with np.divide, writing zero wherever the relevant denominator is zero.
  3. Plot precision and recall per class and print their counts.
Python · run in order
support = cm.sum(axis=1)
predicted_count = cm.sum(axis=0)
true_positive = np.diag(cm)
precision = np.divide(true_positive, predicted_count, out=np.zeros(3, dtype=float), where=predicted_count > 0)
recall = np.divide(true_positive, support, out=np.zeros(3, dtype=float), where=support > 0)
print('True support:', support, 'Predicted count:', predicted_count)
fig, ax = plt.subplots(figsize=(7, 4))
positions = np.arange(3)
ax.bar(positions - 0.18, precision, width=0.36, label='precision')
ax.bar(positions + 0.18, recall, width=0.36, label='recall')
ax.set(xticks=positions, xticklabels=class_names, ylim=(0, 1), ylabel='Rate', title='Class-specific views of the same predictions')
ax.legend()
fig.tight_layout()

Read the result

Compare each rate with its denominator. A zero precision bar can reflect no predictions of that class, so use the printed predicted count before explaining the bar.

Change and compare

  • Identify whether a class is missed often, predicted too freely, or both.
  • Describe how you would label an absent-class recall rather than presenting it as strong evidence.

Guided task 04

Overall accuracy and class-balanced summaries

Overall accuracy weights each evaluated image equally. A macro-average of class recalls instead gives each included class equal weight. These can tell different stories when class frequencies are uneven. To make the distinction exact, this task uses a separate fictional report: ninety plate images, five cup images and five bottle images, all predicted as plate. It does not describe the trained CNN’s actual predictions.

The dominant class makes overall accuracy look high even though two classes are never recovered. Macro recall exposes that imbalance by giving those classes equal influence. Per-class F1 combines precision and recall through their harmonic mean, with a stated zero convention if their sum is zero. It is useful for comparing the two aspects, but does not replace reporting support or error directions. There is no single summary that answers every operational question. Choose metrics according to the task and present the definitions. If some classes have no true examples, report that absence and state whether a macro average includes all named classes or only present ones.

Try it

  1. Create the separate supplied imbalanced label report and its all-plate predictions.
  2. Compute overall accuracy, class recalls and macro recall.
  3. Plot the two summaries and keep their illustrative status explicit.
Python · run in order
demo_true = np.array([0] * 90 + [1] * 5 + [2] * 5)
demo_pred = np.zeros(100, dtype=int)
demo_cm = tf.math.confusion_matrix(demo_true, demo_pred, num_classes=3).numpy()
demo_recall = np.diag(demo_cm) / demo_cm.sum(axis=1)
overall = float((demo_true == demo_pred).mean())
macro = float(demo_recall.mean())
fig, ax = plt.subplots(figsize=(6, 4))
ax.bar(['Overall accuracy', 'Macro recall'], [overall, macro])
ax.set(ylim=(0, 1), ylabel='Rate', title='Illustrative imbalanced report, not CNN results')
fig.tight_layout()

Read the result

The two bars summarize the same fictional predictions with different weights. The difference comes from class frequency and missing recovery of minority classes, not from changing the model between metrics.

Guided task 05

Review difficult examples with their identities

Aggregate metrics should lead back to inspectable examples. Rank the cached test rows by negative log probability assigned to the true class, then display six with the largest values. This per-example cross-entropy can highlight both incorrect predictions and correct predictions made with weak support for the true class. It is not identical to sorting only by the maximum predicted probability.

Keep the original test ID, true name, predicted name and status on each displayed example. This prevents a visually plausible drawing from being separated from the numerical row that selected it. If the model makes no mistakes, the same ranking still identifies its least supported true labels; the display should say correct rather than inventing errors. The review is diagnostic evidence for this fixed report. If it inspires a later generator or architecture change, document that as a new development iteration. Do not quietly replace the evaluated model and reuse the same test as though it had never influenced the work.

Try it

  1. Compute a clipped negative log true-class probability for every cached test row.
  2. Select six largest-loss rows without changing their label alignment.
  3. Show the original drawing, record ID, true/predicted names and correctness.
Python · run in order
true_prob = test_probs[np.arange(len(y_test)), y_test]
per_example_loss = -np.log(np.clip(true_prob, 1e-7, 1.0))
review_rows = np.argsort(-per_example_loss, kind='stable')[:6]
fig, axes = plt.subplots(2, 3, figsize=(9, 6))
for ax, row in zip(axes.flat, review_rows):
    ax.imshow(x_test[row])

Guided task 06

Confidence needs an empirical check

The largest softmax value is often called confidence, but it does not automatically equal the probability that a prediction is correct. A reliability-style inspection groups examples by that value and compares their mean score with their observed fraction correct. If a group averages a score near eight tenths, an empirical correctness rate near eight tenths would be consistent with that score on these examples; a large difference deserves investigation.

This test set is very small, so bins can be empty or contain only a few examples. Skip empty bins in the plotted points and print every bin count rather than assigning invented accuracies to missing data. Do not claim reliable calibration from a handful of drawings, even if a point lies near the diagonal. The bin edges are fixed before this calculation and are not tuned to make the picture look favorable. The analysis reuses the same cached predictions. It diagnoses how scores relate to observed correctness within this narrow fixture, without changing the classifier or recalibrating scores on the final test.

Try it

  1. Take each cached probability vector’s maximum as its confidence score.
  2. Group scores using fixed edges 0, 0.4, 0.6, 0.8 and 1.
  3. Plot mean confidence against correctness only for nonempty bins, and print counts.
Python · run in order
confidence = test_probs.max(axis=1)
bin_ids = np.digitize(confidence, [0.4, 0.6, 0.8], right=False)
bin_counts = np.bincount(bin_ids, minlength=4)
mean_confidence, bin_accuracy = [], []
for bin_id in range(4):
    mask = bin_ids == bin_id
    if mask.any():
        mean_confidence.append(float(confidence[mask].mean()))
        bin_accuracy.append(float(correct[mask].mean()))
print('Bin counts:', bin_counts)
fig, ax = plt.subplots(figsize=(5, 4))
ax.plot([0, 1], [0, 1], '--', color='gray', label='agreement line')
ax.plot(mean_confidence, bin_accuracy, 'o-', label='nonempty test bins')
ax.set(xlim=(0, 1), ylim=(0, 1), xlabel='Mean maximum softmax value', ylabel='Observed fraction correct', title='Small-sample confidence inspection')
ax.legend()
fig.tight_layout()

Read the result

Interpret each point together with its printed count. An empty bin contributes no point, and a few points cannot establish dependable real-world score calibration.

Change and compare

  • Describe why confidence and correctness are different variables.
  • Explain why fitting a calibration correction on this final test would change its role.

Guided task 07

A fixed review policy changes coverage

A workflow can route low-score predictions for human review instead of automatically accepting every label. The threshold in this lab was fixed at setup, before final-test predictions were computed. A row is automatically accepted when its maximum softmax score is at least that threshold. Coverage is the fraction accepted; accepted accuracy is the fraction correct among only those accepted rows.

These two values must be reported together. A high accepted accuracy on a tiny accepted subset does not describe the unreviewed remainder, and a high threshold does not guarantee correctness. If no rows are accepted, accepted accuracy is undefined rather than zero or one. The code represents that case with None and still reports the coverage and review count. This is a reporting policy on one fixed model, not a retraining operation. Choosing the threshold after inspecting this test would use it for development. A real workflow would also need to study review effort, delayed decisions and the consequences of errors; the drawn fixture demonstrates only the numerical accounting.

Try it

  1. Apply the predeclared inclusive confidence threshold to cached test scores.
  2. Compute accepted and review counts, coverage and accepted accuracy when defined.
  3. Plot counts and label the conditional accuracy without filling an empty subset with an invented value.
Python · run in order
accepted = confidence >= review_threshold
accepted_count = int(accepted.sum())
review_count = len(accepted) - accepted_count
coverage = float(accepted.mean())
accepted_accuracy = float(correct[accepted].mean()) if accepted_count else None
label = 'undefined: no accepted rows' if accepted_accuracy is None else f'accepted accuracy: {accepted_accuracy:.3f}'
fig, ax = plt.subplots(figsize=(6, 4))
ax.bar(['Accepted', 'Review'], [accepted_count, review_count])
ax.set(ylabel='Image count', title=f'Fixed threshold {review_threshold:.2f}; {label}')
fig.tight_layout()
print('Coverage:', coverage, 'Accepted accuracy:', accepted_accuracy)

Read the result

The counts always cover the full test set. Conditional accuracy describes only accepted rows and remains undefined when there are none; it is not the overall test accuracy.

Guided task 08

A reproducible evaluation record

A final report should preserve enough context to reconstruct its numbers. Save class order, input shape and range, test IDs, confusion counts, support, overall accuracy, the declared review threshold and its resulting coverage. Also state what the data are: locally drawn icons from a small procedural generator. Without this context, a score can be separated from the conditions that gave it meaning.

The code writes a JSON record into a fresh temporary directory and reads it back to verify that basic information survives. It does not overwrite a user file or save a model in this task. Lists and ordinary Python numbers are used so the report is portable beyond NumPy. An undefined accepted accuracy is represented as null through Python None. The accompanying plot compares each true class’s support with its error count, making the amount of evidence visible. This report closes the fixed experiment. It can motivate future work, but later changes should receive their own declared development and evaluation procedure rather than silently inheriting the independence of this test.

Try it

  1. Assemble a report using the fixed model contract and cached evaluation quantities.
  2. Write and reread JSON only in a newly created temporary directory.
  3. Plot true support and error counts per class to accompany the summary.
