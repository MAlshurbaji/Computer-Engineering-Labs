Dense Regression

MaterialPracticeQuiz

Fit a small model to invented laundry-planning records and keep its limitations visible. You will connect the data split, normalization, training objective, prediction units, and saved model in one careful workflow.

Run setup once, then teaching tasks in order. The seeded records and fixed split are fixtures; only training rows may determine learned preprocessing. No appliance-control use is implied.

Python · shared setup
import tensorflow as tf
import keras
import numpy as np
import matplotlib.pyplot as plt
keras.utils.set_random_seed(104)
rng = np.random.default_rng(104)

import tempfile
from pathlib import Path
# Invented planning records; these are not appliance measurements.
n = 180
mass_kg = rng.uniform(1.0, 7.0, n)
item_count = rng.integers(4, 25, n)
features = np.column_stack([mass_kg, item_count]).astype(np.float32)
minutes = (8 + 2.5*mass_kg + 0.35*item_count + rng.normal(0, 0.8, n)).astype(np.float32)[:, None]
record_ids = rng.permutation(n)
train_ids, val_ids, test_ids = record_ids[:108], record_ids[108:144], record_ids[144:]
x_train, y_train = features[train_ids], minutes[train_ids]
x_val, y_val = features[val_ids], minutes[val_ids]
x_test, y_test = features[test_ids], minutes[test_ids]
feature_names = ["Mass (kg)", "Item count"]

def batches(x, y, batch_size=16, shuffle=False):
    ds = tf.data.Dataset.from_tensor_slices((x, y))
    if shuffle:
        ds = ds.shuffle(len(x), seed=123, reshuffle_each_iteration=True)
    options = tf.data.Options()
    options.threading.private_threadpool_size = 1
    options.threading.max_intra_op_parallelism = 1
    return ds.batch(batch_size).with_options(options)

Guided task 01

Regression targets and split isolation

Regression predicts a numeric quantity whose distances have meaning. Here the target is a planning duration in minutes, while the inputs are laundry mass in kilograms and an item count. The records are generated from a declared simple relation with small random variation, so they are useful for learning a workflow but provide no evidence about an actual washing machine or household routine.

The setup assigns record IDs to training, validation and test sets before any statistics are learned. Training rows supply parameter updates. Validation rows support development comparisons, while test targets stay untouched until the final chosen model is evaluated. A row must not appear in more than one set: repeated access under different names would undermine the separation. The plot shows only training and validation records, keeping the test targets out of exploratory comparisons. Because item count also affects the target, points at similar mass need not share the same duration. This is a reminder that a two-dimensional scatter plot can show only part of a multi-feature relationship. Inspect the split IDs and units before choosing a network architecture.

Try it

  1. Confirm that the three ID sets are disjoint and cover the records.
  2. Plot training and validation durations against mass.
  3. Use item count as the colour of the training points.
Python · run in order
assert set(train_ids).isdisjoint(val_ids)
assert set(train_ids).isdisjoint(test_ids)
assert set(val_ids).isdisjoint(test_ids)
fig, ax = plt.subplots(figsize=(7,3))
points = ax.scatter(x_train[:,0],y_train[:,0],c=x_train[:,1],cmap="viridis",label="Training",s=24)
ax.scatter(x_val[:,0],y_val[:,0],facecolors="none",edgecolors="black",label="Validation",s=35)
ax.set(xlabel="Mass (kg)",ylabel="Invented duration (minutes)",title="Development records")
ax.legend()
fig.colorbar(points,ax=ax,label="Training item count")
fig.tight_layout()
print("Split sizes:",len(train_ids),len(val_ids),len(test_ids))

Read the result

The two development sets sample the same invented feature ranges without sharing IDs. The point colours help explain variation that mass alone cannot describe, while the test set remains reserved.

  • Explain why splitting after making duplicate records would require grouping related copies.

Guided task 02

Train-only feature normalization

Feature columns can have different scales. A kilogram value and an item count are both numeric, but a one-unit change means something different for each. Standardization subtracts a training mean and divides by a training standard deviation for each feature. It gives the optimizer inputs on more comparable numerical scales while retaining a reversible description of the original units.

Estimate those statistics using training rows only, then apply the same values to validation rows. Recomputing a separate mean on validation would change the representation and use information from a set that did not belong to the fitting step. A standardized validation mean need not be exactly zero; zero training mean is a consequence of how the transformation was defined, not a rule that every future batch must satisfy. The histogram comparison shows both columns after training-derived scaling, but it does not guarantee identical distributions. Normalization cannot remove missing measurements, correct mislabeled units or create coverage outside the observed range. This task computes the statistics explicitly so that the later Normalization layer has a clear numerical contract rather than appearing as a black box.

Try it

  1. Calculate each training feature's mean and population standard deviation.
  2. Transform both development sets with those same statistics.
  3. Compare the standardized training feature distributions.
Python · run in order
train_mean = x_train.mean(axis=0)
train_std = x_train.std(axis=0)
z_train = (x_train-train_mean)/train_std
z_val = (x_val-train_mean)/train_std
fig, axes = plt.subplots(1,2,figsize=(9,3))
for i,ax in enumerate(axes):
    ax.hist(z_train[:,i],bins=12,alpha=.7,label="Training")
    ax.hist(z_val[:,i],bins=12,histtype="step",linewidth=2,label="Validation")
    ax.set(xlabel="Training-standardized value",ylabel="Records",title=feature_names[i])
    ax.legend()
fig.tight_layout()
print("Training means after scaling:",z_train.mean(axis=0))

Read the result

Both training columns have near-zero means and near-unit standard deviations. Validation values use the same coordinate system even when their observed mean or spread differs.

  • Compare with incorrectly re-estimating validation statistics, then explain why the two coordinate systems differ.

Guided task 03

A constant regression baseline

A baseline provides a simple reference before adding model complexity. For squared-error regression, a constant equal to the training target mean is a useful starting comparison. It uses no input features and makes the same minute prediction for every record. This is deliberately limited, but it tells us what can be achieved by learning only the overall target level.

The baseline value must come from training targets, not from the validation targets on which it is assessed. Calculate validation residuals and report MAE in minutes so the result remains interpretable. The scatter plot compares target values with constant predictions; a diagonal reference line represents exact agreement. A constant predictor appears as a horizontal band and cannot follow differences across records. The residual histogram exposes the errors that a single average leaves behind. Beating a baseline on these synthetic records would show that a model used feature information in this controlled setting, not that the model is suitable for real appliance planning. Keep the baseline calculation reproducible so later changes can be compared against the same straightforward reference.

Try it

  1. Estimate the constant from training target values only.
  2. Evaluate its MAE and MSE on validation rows.
  3. Plot target-versus-prediction and the validation residual distribution.
Python · run in order
baseline_value = float(y_train.mean())
baseline_pred = np.full_like(y_val,baseline_value)
baseline_mae = float(np.mean(np.abs(baseline_pred-y_val)))
baseline_mse = float(np.mean((baseline_pred-y_val)**2))
fig, axes = plt.subplots(1,2,figsize=(9,3))
axes[0].scatter(y_val[:,0],baseline_pred[:,0])
limits = [float(y_val.min()),float(y_val.max())]
axes[0].plot(limits,limits,"--",color="gray")
axes[0].set(xlabel="Target minutes",ylabel="Predicted minutes",title="Training-mean baseline")
axes[1].hist((baseline_pred-y_val).ravel(),bins=10)
axes[1].set(xlabel="Prediction - target (minutes)",ylabel="Validation records",title="Baseline residuals")
fig.tight_layout()
print("Validation MAE (minutes):",baseline_mae,"MSE:",baseline_mse)

Read the result

The constant line cannot track larger and smaller target durations. Reported errors describe this fixed validation split and baseline; their scale will give context to subsequent fitted-model errors.

Change and compare

  • Compare the mean baseline with a training-median constant using validation MAE.
  • Explain why replacing the constant with the validation mean would weaken the comparison.

Guided task 04

A fitted linear Dense regressor

A one-unit Dense layer with no activation predicts an unrestricted numeric output. Placing a Normalization layer before it keeps the training-derived feature transformation inside the model, so new raw inputs pass through the same processing. Adapt learns the normalization statistics; fit then learns the Dense kernel and bias from the regression objective.

The model is intentionally small because the fixture was generated from an approximately affine relation. Use MSE for optimization and MAE for a companion metric in the target's minute units. The batches helper bounds the input pipeline's thread pool and performs any requested training shuffle. Validation data are supplied without shuffling or parameter updates. The output bias starts at the training target mean, giving the fit a useful target-level starting point. Ten epochs here mean ten passes over the training dataset, not ten individual gradient steps. The learning curves show recorded objectives, which must be inspected rather than assumed to improve smoothly at every epoch. This linear architecture is the predeclared final model for the lesson; a later hidden-layer example is a development comparison. The final test evaluation will not decide which architecture to keep.

Try it

  1. Adapt a Normalization layer using x_train only.
  2. Fit the Normalization-plus-Dense model for ten epochs.
  3. Inspect training and validation MSE and retain the fitted linear_model.
Python · run in order
normalizer = keras.layers.Normalization(axis=-1)
normalizer.adapt(x_train)
linear_model = keras.Sequential([keras.Input(shape=(2,)),normalizer,keras.layers.Dense(1, bias_initializer=keras.initializers.Constant(float(y_train.mean())))])
linear_model.compile(optimizer=keras.optimizers.Adam(0.1),loss="mse",metrics=["mae"])
linear_history = linear_model.fit(batches(x_train,y_train,shuffle=True),validation_data=batches(x_val,y_val),epochs=10,verbose=0,shuffle=False)
linear_val = linear_model(x_val,training=False).numpy()
linear_mae = float(np.mean(np.abs(linear_val-y_val)))
fig, ax = plt.subplots(figsize=(6,3))
ax.plot(linear_history.history["loss"],label="Training")
ax.plot(linear_history.history["val_loss"],label="Validation")
ax.set(xlabel="Epoch index",ylabel="MSE (minutes squared)",title="Small linear Dense model")
ax.legend()
fig.tight_layout()
print("Validation MAE (minutes):",linear_mae)

Read the result

Inspect the recorded losses and recomputed validation MAE without expecting a particular accuracy claim. The model accepts raw kilogram/count inputs because its normalization layer is included in the graph.

Change and compare

  • Inspect the Dense parameter count separately from the normalizer's stored statistics.
  • Repeat a controlled run with fewer epochs while keeping the split and preprocessing unchanged.

Guided task 05

Residual diagnostics in target units

An aggregate loss cannot show which examples a model systematically misses. A residual plot compares prediction minus target with an input or a target value. A pattern can suggest that the model is missing part of a relationship, while isolated large residuals identify records worth inspecting. A random-looking plot alone does not prove that all important structure has been captured.

Use validation predictions from the fitted linear model and keep the sign convention consistent with the earlier loss lab. Plot residuals separately against mass and item count because each feature can reveal a different pattern. The horizontal zero line identifies exact agreement, and the same vertical limits make the two panels comparable. Compute MAE and the largest absolute residual in minutes, but do not treat the largest observed error as a guaranteed bound for future examples. The synthetic noise, limited sample size and narrow feature range all restrict what this check establishes. In a real project, investigating a suspicious point includes checking its units and data provenance rather than automatically removing it to improve a score. Here every point is an intentionally generated fixture.

Try it

  1. Recompute validation predictions in inference mode.
  2. Plot signed residuals against both raw input features.
  3. Report validation MAE and the largest observed absolute residual.
Python · run in order
val_prediction = linear_model(x_val,training=False).numpy()
residuals = (val_prediction-y_val).ravel()
val_mae = float(np.mean(np.abs(residuals)))
largest_error = float(np.max(np.abs(residuals)))
fig, axes = plt.subplots(1,2,figsize=(9,3),sharey=True)
for i,ax in enumerate(axes):
    ax.scatter(x_val[:,i],residuals,s=25)
    ax.axhline(0,color="gray",linestyle="--")
    ax.set(xlabel=feature_names[i],ylabel="Prediction - target (minutes)")
axes[0].set_title("Residuals by mass")
axes[1].set_title("Residuals by item count")
fig.tight_layout()
print("MAE:",val_mae,"largest observed absolute error:",largest_error)

Read the result

Look for systematic trends or a few dominating errors rather than a single desirable-looking score. The shared vertical scale makes the two feature views comparable and preserves the meaning of a minute of error.

Change and compare

  • List the three validation rows with the largest absolute residuals.
  • Reverse the residual sign and explain what changes in the graph and what stays unchanged in MAE.

Guided task 06

A small nonlinear alternative

A hidden Dense layer with ReLU can represent a more flexible input-to-output relationship than one linear Dense layer. That flexibility is useful only if the data and evaluation justify it. The fixture in this lesson is already close to affine, so a larger model is not automatically the better choice. We keep the linear model as the predeclared final model and use the hidden model as a development comparison.

Adapt a new normalizer on the same training inputs, then fit an eight-unit hidden layer and a one-unit linear output. The output remains unrestricted because this is numeric regression, not a class probability. Initialize the output bias at the training target mean to keep the initial scale sensible. Evaluate both models on exactly the same validation rows and report MAE using the same units and reduction. The chart is created from actual execution, so it may show either model with a smaller development error. A single comparison on a small validation set does not prove a universally superior architecture. Additional flexibility also brings more parameters and another way to fit incidental variation. Preserve the test set rather than using it to settle this exploratory comparison.

Try it

  1. Create a separate normalized model with an eight-unit ReLU hidden layer.
  2. Fit it for twelve epochs using the existing training and validation split.
  3. Compare validation MAE and fitted parameter counts with the linear model.
Python · run in order
hidden_norm = keras.layers.Normalization(axis=-1)
hidden_norm.adapt(x_train)
hidden_model = keras.Sequential([keras.Input(shape=(2,)),hidden_norm,keras.layers.Dense(8,activation="relu"),keras.layers.Dense(1,bias_initializer=keras.initializers.Constant(float(y_train.mean())))])
hidden_model.compile(optimizer=keras.optimizers.Adam(0.03),loss="mse")
hidden_history = hidden_model.fit(batches(x_train,y_train,shuffle=True),validation_data=batches(x_val,y_val),epochs=12,verbose=0,shuffle=False)
hidden_val = hidden_model(x_val,training=False).numpy()
comparison_mae = [float(np.mean(np.abs(linear_model(x_val,training=False).numpy()-y_val))),float(np.mean(np.abs(hidden_val-y_val)))]
fig, axes = plt.subplots(1,2,figsize=(9,3))
axes[0].bar(["Linear","Hidden 8"],comparison_mae)
axes[0].set(ylabel="Validation MAE (minutes)",title="Observed development errors")
axes[1].plot(hidden_history.history["loss"],label="Training")
axes[1].plot(hidden_history.history["val_loss"],label="Validation")
axes[1].set(xlabel="Epoch index",ylabel="MSE",title="Hidden-model learning curves")
axes[1].legend()
fig.tight_layout()
print("MAEs:",comparison_mae,"Dense parameters:",linear_model.layers[-1].count_params(),sum(layer.count_params() for layer in hidden_model.layers if isinstance(layer,keras.layers.Dense)))

Read the result

Compare measured development errors without assuming that more units help. The hidden model has more trainable Dense parameters, but the model selected for final evaluation remains the linear architecture declared earlier.

Change and compare

  • Count the hidden model's kernel and bias entries by hand.
  • Change only the hidden width in a separate development run while preserving the split.

Guided task 07

New records and extrapolation

A deployed regressor receives inputs rather than target values. It can produce a number for a record outside the range represented in training, but successful computation does not establish a useful prediction. Extrapolation asks the learned relation to continue beyond the examples that constrained it. A linear model extends its plane mechanically, even if the real relationship would bend or stop making sense.

Create a mass sweep at a fixed item count and mark the observed training mass interval. Pass the raw sweep through the complete model, including its already adapted normalizer. Do not adapt again on the sweep: doing so would change the input coordinates and invalidate the learned Dense weights. The model's output is a minute estimate under the synthetic relation it learned. The shaded region identifies where mass lies within the training range, while the outer points are explicitly extrapolations. Matching the mass range alone is not a full support check because feature combinations matter too. An unusual count paired with an ordinary mass may also be poorly represented. Report assumptions alongside predictions instead of presenting every finite output as equally supported.

Try it

  1. Create a mass sweep from zero to ten kilograms with item count fixed at twelve.
  2. Predict using the complete fitted linear model without adapting it.
  3. Shade the training mass range and label extrapolated portions.
Python · run in order
sweep_mass = np.linspace(0,10,101,dtype=np.float32)
new_records = np.column_stack([sweep_mass,np.full(101,12,dtype=np.float32)])
sweep_prediction = linear_model(new_records,training=False).numpy().ravel()
fig, ax = plt.subplots(figsize=(7,3))
ax.plot(sweep_mass,sweep_prediction,label="Model command: 12 items")
ax.axvspan(float(x_train[:,0].min()),float(x_train[:,0].max()),alpha=.15,color="green",label="Observed training mass range")
ax.set(xlabel="Mass (kg)",ylabel="Predicted minutes",title="A computed output is not an extrapolation guarantee")
ax.legend(fontsize=8)
fig.tight_layout()
print("Example predictions:",sweep_prediction[[0,50,100]])

Read the result

The model continues its learned response beyond the shaded interval. Those outer values are computed extrapolations with no new measured targets in this activity; their smoothness is a property of the model, not evidence of physical validity.

Change and compare

  • Hold mass fixed and sweep item count instead.
  • Identify which new feature combinations are absent from the original fixture even when each separate value is in range.

Guided task 08

Final evaluation and model persistence

A final test evaluation measures the predeclared model on records withheld from development. It should not become another search loop for choosing settings. Here the linear model was selected before the hidden-layer comparison, and the test result is reported once as a property of this synthetic split. A small test set still has sampling uncertainty and cannot establish real-world appliance performance.

Saving the entire Keras model preserves the normalization layer with the Dense weights. This is safer than saving only a kernel and later guessing the preprocessing values or feature order. Use a temporary directory so the exercise never overwrites an existing project file. Reload the model and compare predictions on the same raw inputs within a floating-point tolerance. Equality checks operational persistence, not predictive quality: a consistently wrong model can also be saved and restored perfectly. The scatter plot and MAE describe prediction error, while the reload difference checks a separate software requirement. Keep those claims distinct. Feature names, units and dataset provenance still belong in accompanying project metadata when building a reusable application.

Try it

  1. Evaluate the predeclared linear model on the untouched test set.
  2. Save it in a newly created temporary directory and reload it.
  3. Compare predictions before and after loading, then plot the test result.
Python · run in order
test_prediction = linear_model(x_test,training=False).numpy()
test_mae = float(np.mean(np.abs(test_prediction-y_test)))
saved_dir = Path(tempfile.mkdtemp(prefix="dense-regression-"))
model_path = saved_dir/"model.keras"
linear_model.save(model_path)
loaded = keras.models.load_model(model_path)
reloaded_prediction = loaded(x_test,training=False).numpy()
reload_difference = float(np.max(np.abs(test_prediction-reloaded_prediction)))
fig, ax = plt.subplots(figsize=(6,3))
ax.scatter(y_test[:,0],test_prediction[:,0])
limits = [float(min(y_test.min(),test_prediction.min())),float(max(y_test.max(),test_prediction.max()))]
ax.plot(limits,limits,"--",color="gray")
ax.set(xlabel="Test target (minutes)",ylabel="Predicted minutes",title=f"Final synthetic test MAE: {test_mae:.2f} min")
fig.tight_layout()
print("Reload maximum difference:",reload_difference)

Read the result

Inspect the test scatter for the selected model and report the MAE in minutes. A negligible reload difference confirms consistent saved behavior, while the error chart addresses the separate question of agreement with the held-out synthetic targets.
