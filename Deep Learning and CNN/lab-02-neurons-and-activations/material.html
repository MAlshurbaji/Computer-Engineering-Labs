Python · shared setup
import tensorflow as tf

import numpy as np
import matplotlib.pyplot as plt
keras.utils.set_random_seed(102)

# Drawn-up parcel descriptors: mass fraction and occupied-box fraction.
# Values describe four invented examples, not a measured delivery dataset.
parcel_x = tf.constant([[0.2, 0.1], [0.4, 0.7], [0.8, 0.3], [1.0, 0.9]], tf.float32)
parcel_names = ["Small", "Bulky", "Dense", "Large"]

Guided task 01

Weighted sums

A neuron begins by combining input features with weights. Each feature is multiplied by its corresponding weight, and the contributions are added. For two inputs this is x1 times w1 plus x2 times w2. A positive weight makes larger values increase the result; a negative weight makes them decrease it. The feature order is part of the calculation. Swapping two feature columns without swapping their matching weights changes the meaning.

We use invented parcel descriptors expressed as fractions so their numeric ranges are easy to compare. A mass fraction and a box-space fraction are still different quantities even when both lie between zero and one. The selected weights are an inspection exercise, not an established parcel-handling score. By plotting individual contributions before the total, you can see how a negative contribution can partly offset a positive one. A matrix-vector multiplication applies exactly the same weights to every row in the batch. That shared rule distinguishes a model from a separate hand-written answer for each example, and the output vector retains the order of the original parcel rows.

Try it

  1. Multiply each parcel feature by weights [1.5, -0.5].
  2. Sum the two contributions for each parcel.
  3. Compare contributions with the resulting batch of weighted sums.
Python · run in order
weights = tf.constant([1.5, -0.5], tf.float32)
contributions = parcel_x * weights
scores = tf.linalg.matvec(parcel_x, weights)
fig, axes = plt.subplots(1, 2, figsize=(9, 3))
locations = np.arange(4)
axes[0].bar(locations-0.15, contributions[:,0], width=0.3, label="Mass contribution")
axes[0].bar(locations+0.15, contributions[:,1], width=0.3, label="Space contribution")
axes[0].set_xticks(locations, parcel_names)
axes[0].set(ylabel="Weighted contribution", title="Before summing")
axes[0].legend(fontsize=8)
axes[1].bar(parcel_names, scores.numpy())
axes[1].set(ylabel="Weighted sum", title="One shared rule")
fig.tight_layout()
print(scores.numpy())

Read the result

Follow one parcel across both panels and add its two signed contributions. A negative weight does not require a negative input; it specifies how a positive change in that feature affects the sum.

Change and compare

  • Set the space weight to zero and identify which feature stops influencing the result.
  • Swap only the feature columns, then explain why the original weights no longer match their meanings.

Guided task 02

Bias and response shifts

A bias is an added constant after the weighted sum. It lets a neuron change its output even when every input feature is zero. With one input, the weight controls the slope of the affine response and the bias shifts the entire line vertically. It is useful to examine these roles separately before combining them with an activation function.

Here the input represents a normalized fill setting for a desk container. Three selected biases share the same weight, so their lines have equal slopes. Moving the bias changes which input produces a particular output level without changing the amount that output changes for a small input increment. A negative bias is allowed, and an affine output need not lie between zero and one just because its input does. This is one reason output activation depends on the intended task. None of these lines has been fitted to measurements. They are controlled numerical examples that expose the role of one parameter. When later training adjusts both weight and bias, this interpretation helps you connect parameter changes with visible movement of a prediction curve.

Try it

  1. Evaluate a one-input response with weight 1.2 over settings from zero to one.
  2. Repeat for biases -0.6, 0 and 0.6.
  3. Mark the zero-output reference to compare intercepts.
Python · run in order
settings = tf.linspace(0.0, 1.0, 101)
biases = [-0.6, 0.0, 0.6]
responses = tf.stack([1.2 * settings + bias for bias in biases])
fig, ax = plt.subplots(figsize=(6, 3))
for response, bias in zip(responses, biases):
    ax.plot(settings, response, label=f"bias = {bias}")
ax.axhline(0, color="gray", linewidth=1)
ax.set(xlabel="Normalized fill setting", ylabel="Affine output", title="Same weight, different biases")
ax.legend()
fig.tight_layout()
print("Outputs at zero input:", responses[:,0].numpy())

Read the result

Parallel lines reveal the unchanged weight. Read the intercepts at zero input and notice that a normalized input does not impose an output range on this unrestricted affine calculation.

Change and compare

  • Keep the bias fixed and change the weight to compare slopes.
  • Solve which setting gives zero output for the negative-bias line, then locate it on the plot.

Guided task 03

ReLU and inactive regions

The rectified linear unit, or ReLU, returns zero for a negative input and returns the input itself when it is positive. Its output is therefore piecewise linear. Apply it after the affine calculation: the bias can determine where the response enters its active region, while the weight affects how the active branch changes.

A flat output region does not mean that the underlying input stopped changing. Several different negative pre-activation values all become zero after ReLU, so the operation loses the distinctions between those values. This is useful for building conditional responses inside a network, but it also affects how changes can propagate through a neuron during training. This lesson focuses on the forward calculation; the next lesson examines gradients. A ReLU output has a lower bound of zero but no built-in upper bound of one. Treating it as a probability would therefore be unjustified. Plot the affine and activated responses together to locate exactly which part was changed and which part was preserved, rather than memorizing the function name without its behavior.

Try it

  1. Use pre-activation z = 2x - 0.8 on settings from zero to one.
  2. Apply keras.activations.relu to z.
  3. Compare the two responses and locate the active-region boundary.
Python · run in order
settings = tf.linspace(0.0, 1.0, 101)
z = 2.0 * settings - 0.8
activated = keras.activations.relu(z)
fig, ax = plt.subplots(figsize=(6, 3))
ax.plot(settings, z, label="Pre-activation")
ax.plot(settings, activated, linewidth=2, label="ReLU output")
ax.axvline(0.4, color="gray", linestyle=":")
ax.set(xlabel="Normalized setting", ylabel="Output", title="ReLU after an affine response")
ax.legend()
fig.tight_layout()
print("Selected ReLU values:", keras.activations.relu(tf.constant([-0.8,0.0,1.2])).numpy())

Read the result

Below the boundary the affine line continues changing while ReLU stays at zero. Above it the two curves agree, including values greater than one near the upper end of the displayed settings.

Change and compare

  • Change only the bias to move the boundary.
  • Choose a setting where the output exceeds one and explain why it is still a valid ReLU value.

Guided task 04

Sigmoid and saturation

Sigmoid transforms a real-valued score into a number between zero and one. Zero maps to one-half, positive scores map above one-half, and negative scores map below it. The mapping is smooth, but equal score changes do not create equal output changes everywhere. Near the center the curve responds more strongly; at the extremes it approaches its limits gradually.

The range makes sigmoid suitable for a binary model's positive-class output when paired with an appropriate training objective and label convention. It does not by itself make a chosen score into a trustworthy real-world probability. These examples are deliberately untrained, and we use them to inspect the transformation rather than to make a decision about actual parcels. The second panel shows how much the output changes when the score increases by one. A smaller change at an extreme is an example of saturation. Keep the pre-activation score available when debugging a model, because very different large scores can produce nearly identical displayed outputs after rounding. Printing several decimal places can reveal numeric differences, but it does not establish calibration or practical certainty.

Try it

  1. Evaluate sigmoid over scores from -8 to 8.
  2. Measure the output change caused by adding one to selected scores.
  3. Plot the curve and the size of that finite change.
Python · run in order
z = tf.linspace(-8.0, 8.0, 201)
probability = keras.activations.sigmoid(z)
probes = tf.constant([-6.0, -0.5, 5.0], tf.float32)
changes = keras.activations.sigmoid(probes+1) - keras.activations.sigmoid(probes)
fig, axes = plt.subplots(1, 2, figsize=(9, 3))
axes[0].plot(z, probability)
axes[0].set(xlabel="Untrained score z", ylabel="Sigmoid(z)", ylim=(0,1), title="Bounded response")
axes[1].bar(["-6 to -5", "-0.5 to 0.5", "5 to 6"], changes)
axes[1].set(ylabel="Change in output", title="Equal score increment")
fig.tight_layout()
print("Sigmoid at zero:", float(keras.activations.sigmoid(tf.constant(0.0))))

Read the result

The center interval produces a larger change than the two extreme intervals. This describes the selected activation function, not the accuracy or confidence quality of a trained classifier.

Change and compare

  • Compare sigmoid(z) with 1 - sigmoid(-z).
  • Change the finite increment from one to one-tenth and examine how the scale changes.

Guided task 05

Keras Dense parameter layout

A Dense layer applies one affine rule per output unit. With two input features and three output units, its kernel contains two rows and three columns. Each kernel column supplies the two feature weights for one unit, and the bias vector supplies three separate offsets. The batch dimension is not part of the kernel: the same parameters are reused for every example.

Calling an unbuilt layer once establishes its input width and creates its parameters. This activity then replaces those parameters with explicit values, making the manual and layer calculations directly comparable. The operation is input matrix times kernel plus bias. Check the full result rather than only its shape, because a wrong feature order can still produce a valid matrix multiplication. There is no training step here, and the selected numbers should not be interpreted as learned parcel expertise. Seeing the parameter layout makes later model summaries more meaningful: parameter count depends on input width and output width, while batch size controls how many rows are processed at once. A linear Dense layer leaves the calculated scores unrestricted until another activation is applied.

Try it

  1. Create a three-unit Dense layer and build it with the two-feature fixture.
  2. Set the supplied kernel and bias, then compute the same rule manually.
  3. Plot both sets of outputs for the first parcel.
Python · run in order
layer = keras.layers.Dense(3, activation=None)
_ = layer(parcel_x)
kernel = np.array([[1.0, -1.0, 0.5], [0.5, 1.0, 2.0]], dtype=np.float32)
bias = np.array([0.1, 0.0, -0.2], dtype=np.float32)
layer.set_weights([kernel, bias])
dense_output = layer(parcel_x)
manual_output = tf.matmul(parcel_x, kernel) + bias
fig, ax = plt.subplots(figsize=(6, 3))
positions = np.arange(3)
ax.bar(positions-0.15, dense_output[0], width=0.3, label="Dense")
ax.bar(positions+0.15, manual_output[0], width=0.3, label="Manual")
ax.set_xticks(positions, ["Unit 1", "Unit 2", "Unit 3"])
ax.set(ylabel="Linear output", title="First parcel: two equivalent calculations")
ax.legend()
fig.tight_layout()
print("Parameter count:", layer.count_params())

Read the result

The paired bars should coincide. The layer contains six kernel entries and three biases, independently of the four-row batch used for this call.

Change and compare

  • Process only one fixture row and confirm the parameter count is unchanged.
  • Change one kernel column and identify which output unit changes.

Guided task 06

Hidden units as reusable features

A hidden layer produces intermediate values that another layer can combine. Those values need not correspond to the original input units. In a one-dimensional example, two ReLU units can detect different regions of an input setting. Subtracting one activated response from another can create a rise that later levels off, even though each individual active branch is linear.

The example uses one hinge at 0.25 and another at 0.75. The first responds once the input passes the earlier boundary; the second begins later and cancels further growth when it is subtracted. This is an exact demonstration with chosen parameters, not a learned behavior or a recommendation about a physical control. The intermediate plot is important because a final curve can hide how its pieces were assembled. Naming the hidden columns helps you track which unit contributes at each input. A network with more units can combine more such pieces, but adding units alone does not establish that the resulting model will generalize. First establish how a small representation works, then use data and evaluation to decide whether more flexibility is useful.

Try it

  1. Compute the two shifted ReLU features over settings from zero to one.
  2. Subtract the later feature from the earlier feature.
  3. Plot the hidden features and their combined response.
Python · run in order
settings = tf.linspace(0.0,1.0,201)
hidden = tf.stack([tf.nn.relu(settings-0.25), tf.nn.relu(settings-0.75)], axis=1)
combined = hidden[:,0] - hidden[:,1]
fig, axes = plt.subplots(1,2,figsize=(9,3))
axes[0].plot(settings,hidden[:,0],label="Hinge at 0.25")
axes[0].plot(settings,hidden[:,1],label="Hinge at 0.75")
axes[0].set(xlabel="Normalized setting",ylabel="Hidden activation",title="Two reusable features")
axes[0].legend()
axes[1].plot(settings,combined)
axes[1].set(xlabel="Normalized setting",ylabel="Combined output",title="Rise then plateau")
fig.tight_layout()
print("Output at setting 1:",float(combined[-1]))

Read the result

Only the first hidden unit contributes between the hinges. Once both are active, their equal slopes cancel in the difference, leaving a plateau rather than an indefinitely rising output.

Change and compare

  • Move the later hinge and predict the new plateau height.
  • Add the two hidden outputs instead of subtracting them and compare the slopes.

Guided task 07

Softmax and relative scores

Softmax turns a vector of scores into nonnegative values that sum to one along a chosen class axis. Increasing one score relative to the others increases its share. Adding the same constant to every score does not change the result, because only their relative differences matter. This makes a useful contrast with applying independent sigmoids, whose outputs need not sum to one.

Imagine three possible labels for a drawn desk object: cup, book and bottle. The score order must stay attached to that class order before or after the transformation. We use one fixed score vector and a shifted copy to inspect the operation. These values are not the predictions of a trained recognizer, so the largest share merely identifies the largest supplied score. Even in a trained system, a large softmax value is not a guarantee that a new image belongs to a familiar class. This task concerns the arithmetic and representation contract. Plotting both vectors together exposes the common-shift invariance, while printing the sum checks that the intended class axis was used.

Try it

  1. Transform fixed class scores [1, 2, -1] with softmax.
  2. Repeat after adding five to every score.
  3. Compare both results using the same class order.
Python · run in order
logits = tf.constant([1.0,2.0,-1.0],tf.float32)
shares = tf.nn.softmax(logits)
shifted_shares = tf.nn.softmax(logits+5.0)
fig, ax = plt.subplots(figsize=(6,3))
positions = np.arange(3)
ax.bar(positions-.15,shares,width=.3,label="Original scores")
ax.bar(positions+.15,shifted_shares,width=.3,label="All scores +5")
ax.set_xticks(positions,["Cup","Book","Bottle"])
ax.set(ylabel="Softmax share",ylim=(0,1),title="Relative scores determine the result")
ax.legend()
fig.tight_layout()
print("Sum:",float(tf.reduce_sum(shares)))

Read the result

The paired bars should agree, and book has the largest share because its supplied score is largest. The fixed class order explains the bars; a softmax vector does not contain class names by itself.

Change and compare

  • Increase only the cup score and track how all three shares change.
  • Compare the sum of three independent sigmoid values with the softmax sum.

Guided task 08

Why nonlinear composition matters

Stacking affine operations without a nonlinear activation still produces an affine operation. If the first layer computes 2x - 0.5 and the next computes three times that result plus 0.2, substitution gives 6x - 1.3. Two calculation stages do not automatically create a more flexible family of curves. This observation is about the function being represented, not about whether a program uses one or two layer objects.

Insert ReLU between those same stages and the result changes: below the first layer's boundary, the second layer receives zero; above it, the second layer receives the positive affine value. The final response is now piecewise rather than one straight line. Plot both versions and the collapsed expression together to make this distinction explicit. A nonlinear network can still learn an unhelpful rule, so expressive capacity is only one part of building a useful model. Data quality, an appropriate objective and held-out evaluation will matter in subsequent labs. For now, checking the algebra gives you a clear reason for including hidden activations instead of treating them as unexplained configuration choices.

Try it

  1. Evaluate two stacked affine rules and their collapsed expression.
  2. Insert ReLU between the same two rules.
  3. Compare all responses over an input interval that crosses the hinge.
Python · run in order
x = tf.linspace(-0.5,1.0,151)
first = 2*x-0.5
linear_stack = 3*first+0.2
collapsed = 6*x-1.3
nonlinear_stack = 3*tf.nn.relu(first)+0.2
fig, ax = plt.subplots(figsize=(7,3))
ax.plot(x,linear_stack,label="Two affine stages")
ax.plot(x,collapsed,"--",label="Collapsed affine expression")
ax.plot(x,nonlinear_stack,label="ReLU between stages")
ax.set(xlabel="Input setting",ylabel="Final output",title="Composition changes with activation")
ax.legend()
fig.tight_layout()
print("Maximum affine difference:",float(tf.reduce_max(tf.abs(linear_stack-collapsed))))

Read the result

The two affine curves overlap within floating-point precision. The nonlinear version has a flat region before its hinge, so one straight-line expression cannot reproduce it over the entire displayed interval.

Change and compare

  • Change the second bias and identify which parts of the nonlinear curve move.
  • Remove ReLU from a two-layer Keras model and derive its equivalent kernel and bias for one input.
