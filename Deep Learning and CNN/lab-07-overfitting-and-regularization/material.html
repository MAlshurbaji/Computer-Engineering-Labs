Overfitting and Regularization

MaterialPracticeQuiz

Learn to ask whether a model is learning a useful pattern or merely fitting the available examples. Small invented cooling-time records make the experiments quick enough to inspect carefully.

What you will learn

  • Compare model capacity under stated training conditions.
  • Separate prediction error from an L2 penalty.
  • Distinguish dropout training behavior from inference.
  • Use validation for stopping and selection while preserving a final test set.

Before this lab: Complete batching and optimization; understand training and validation losses.

Python · shared setup
import tensorflow as tf
import keras
import numpy as np
import matplotlib.pyplot as plt
keras.utils.set_random_seed(107)
rng = np.random.default_rng(107)
# Invented cooling times for different tray widths, not food-safety guidance.
width = rng.uniform(15, 35, 80).astype('float32')
cooling = (12 + 0.025 * (width - 15) ** 2 + rng.normal(0, 1.5, 80)).astype('float32')
ids = rng.permutation(80)
train_ids, val_ids, test_ids = ids[:32], ids[32:56], ids[56:]
x_train = ((width[train_ids, None] - 15) / 20).astype('float32')
y_train = (cooling[train_ids, None] / 30).astype('float32')
x_val = ((width[val_ids, None] - 15) / 20).astype('float32')
y_val = (cooling[val_ids, None] / 30).astype('float32')
grid = np.linspace(0, 1, 80, dtype='float32')[:, None]

def batches(x, y, batch_size=16, shuffle=False):
    ds = tf.data.Dataset.from_tensor_slices((x, y))
    if shuffle:
        ds = ds.shuffle(len(x), seed=123, reshuffle_each_iteration=True)
    options = tf.data.Options()
    options.threading.private_threadpool_size = 1
    options.threading.max_intra_op_parallelism = 1
    return ds.batch(batch_size).with_options(options)

Guided task 01

Split roles and noisy observations

Generalization concerns new examples, so the records used to update weights cannot also be the only evidence for usefulness. This setup assigns eighty independent invented tray records to training, validation and test roles. The split happens before any fitting. Fixed unit conversions make the numbers convenient without estimating a transformation from the held-out data.

The relation includes noise, so two similar widths need not have identical cooling times. A model that bends to every training point may be following noise rather than a repeatable relation. On the other hand, an inflexible model can miss a real nonlinear pattern. Neither conclusion follows merely from seeing a scattered dataset. Begin by inspecting coverage and the size of each set. The final test records are deliberately absent from this development plot. Looking at validation repeatedly is permitted for the stated development tasks, but eventually makes it part of the selection process. Reserve the final test for a fixed procedure rather than using it to choose the most flattering model.

Try it

  1. Verify that the three ID sets are disjoint.
  2. Inspect training and validation coverage in original units.
  3. Keep the test records out of model-development comparisons.
Python · run in order
split_sizes = [len(train_ids), len(val_ids), len(test_ids)]
fig, ax = plt.subplots(figsize=(6, 4))
ax.scatter(x_train[:, 0] * 20 + 15, y_train[:, 0] * 30, label='training')
ax.scatter(x_val[:, 0] * 20 + 15, y_val[:, 0] * 30, marker='x', label='validation')
ax.set(xlabel='Tray width (cm)', ylabel='Invented cooling time (min)', title='Development records only')
ax.legend()
fig.tight_layout()

Read the result

Compare the width ranges represented by both development sets. The plotted variation is supplied synthetic noise, not evidence about actual safe cooling procedures.

  • Explain why a fixed unit conversion differs from fitting a scaler on all records.

Guided task 02

Capacity and the family of possible curves

Architecture limits the patterns a model can express. A single linear output produces a straight line in this one-input problem. Adding a hidden nonlinear layer allows bends, but does not guarantee that the learned bends are useful. Count parameters to make the capacity change concrete, and inspect predictions across the input range rather than treating a parameter count as a quality score.

Both models below receive eight epochs and the same training records. Their architectures differ, so identical random weights are not meaningful, but fresh initialization and a fixed seed make the comparison easier to repeat. The short budget is intentional: this task illustrates the families of curves and the experimental controls, not a contest to find the lowest possible error. Optimization and capacity interact. A flexible model trained briefly may still fit poorly, while a simple model may already capture most of the pattern. Use the observed curve together with losses and training conditions before deciding that complexity is the missing ingredient.

Try it

  1. Build a linear model and a model with sixteen ReLU hidden units.
  2. Fit each for eight epochs using fresh Adam optimizers.
  3. Plot both predictions over the same grid and print their parameter counts.
Python · run in order
capacity_models = {}
for name, hidden in [('linear', False), ('hidden 16', True)]:
    keras.utils.set_random_seed(207)
    layers = [keras.Input((1,))]
    if hidden:
        layers.append(keras.layers.Dense(16, activation='relu'))
    layers.append(keras.layers.Dense(1))
    model = keras.Sequential(layers)
    model.compile(optimizer=keras.optimizers.Adam(0.02), loss='mse')
    model.fit(batches(x_train, y_train), epochs=8, verbose=0, shuffle=False)
    capacity_models[name] = model
    print(name, model.count_params())
fig, ax = plt.subplots(figsize=(6, 4))
ax.scatter(x_train[:, 0], y_train[:, 0], color='gray', alpha=0.5, label='training')
for name, model in capacity_models.items():
    ax.plot(grid[:, 0], model(grid, training=False).numpy()[:, 0], label=name)
ax.set(xlabel='Scaled tray width', ylabel='Scaled time', title='Different function families')
ax.legend()
fig.tight_layout()

Read the result

Inspect whether each fitted curve is straight or can bend. Do not assume that the more flexible model must have the best validation result after this small training budget.

Change and compare

  • Change hidden width while keeping the fitting budget fixed.
  • Identify why a parameter count alone cannot establish generalization.

Guided task 03

Learning curves as evidence over time

A final loss hides the path used to reach it. Learning curves show whether training and validation are still improving, flattening or moving in different directions. A sustained decline in training loss while validation deteriorates is a reason to investigate overfitting, but one noisy validation point is not a reliable diagnosis. The validation set is small, and each epoch changes the model.

This run uses a compact two-hidden-layer network and records both losses for twelve epochs. Its curve is generated by execution; the exercise does not force an overfitting shape. A small experiment may show improvement in both series throughout the budget. In that case, report what happened rather than relabeling it to fit a story. Also check that both losses use comparable definitions. Later tasks add penalties to the optimized objective, which can make a loss value different from prediction error alone. Annotating the loss definition, epoch budget and validation role makes a learning curve useful evidence rather than an unlabeled performance decoration.

Try it

  1. Fit a fresh two-hidden-layer model for twelve epochs.
  2. Retain both loss series from the History object.
  3. Locate the minimum observed validation loss without evaluating the test set.
Python · run in order
keras.utils.set_random_seed(307)
curve_model = keras.Sequential([keras.Input((1,)), keras.layers.Dense(16, activation='relu'), keras.layers.Dense(16, activation='relu'), keras.layers.Dense(1)])
curve_model.compile(optimizer=keras.optimizers.Adam(0.02), loss='mse')
curve_history = curve_model.fit(batches(x_train, y_train), validation_data=batches(x_val, y_val), epochs=12, verbose=0, shuffle=False).history
best_epoch = int(np.argmin(curve_history['val_loss'])) + 1
fig, ax = plt.subplots(figsize=(6, 4))
ax.plot(np.arange(1, 13), curve_history['loss'], label='training')
ax.plot(np.arange(1, 13), curve_history['val_loss'], label='validation')
ax.axvline(best_epoch, color='gray', linestyle='--', label='minimum observed validation')
ax.set(xlabel='Epoch', ylabel='MSE in scaled units', title='Record the actual learning curves')
ax.legend()
fig.tight_layout()

Read the result

Describe the actual direction of both curves and the chosen minimum. No particular widening gap is required, and the observed minimum may occur at the last epoch.

Change and compare

  • Distinguish a single upward fluctuation from a sustained trend.
  • State what extra evidence would help if both losses stayed high.

Guided task 04

L2 separates data fit from a parameter penalty

L2 regularization adds a cost proportional to the sum of squared selected weights. This encourages the optimizer to trade some data fit against large parameter values. It does not clip a weight to a fixed limit or remove a neuron. The coefficient controls the strength of that extra term, so the loss being optimized can differ from the mean squared prediction error.

Use a known tiny layer to see the two quantities separately. Its weights are supplied rather than learned, allowing the penalty to be checked exactly. Calling the layer creates its output, and layer.losses contains the configured regularization contribution. In this example only the kernel is penalized and no bias exists. The plot displays prediction error, penalty and their sum as different quantities. When comparing regularized and unregularized experiments, use a common data metric for prediction quality; otherwise a larger total objective may simply reflect an added penalty. That bookkeeping is especially important when regularization strengths differ.

Try it

  1. Create a bias-free layer with supplied weights two and minus one.
  2. Evaluate the supplied single example and retrieve the L2 penalty.
  3. Plot data MSE, penalty and their combined objective separately.
Python · run in order
layer = keras.layers.Dense(1, use_bias=False, kernel_regularizer=keras.regularizers.L2(0.01))
layer.build((None, 2))
layer.set_weights([np.array([[2.0], [-1.0]], dtype='float32')])
prediction = layer(tf.constant([[1.0, 1.0]]))
data_mse = float(tf.reduce_mean(tf.square(prediction - 0.5)))
penalty = float(tf.add_n(layer.losses))
total = data_mse + penalty
fig, ax = plt.subplots(figsize=(6, 4))
ax.bar(['data MSE', 'L2 penalty', 'total objective'], [data_mse, penalty, total])
ax.set(ylabel='Objective contribution', title='Keep penalty and prediction error distinct')
fig.tight_layout()

Read the result

The total is the sum of two terms with different meanings. The known weights make this a calculation check, not a measured regularization benefit.

Change and compare

  • Double the L2 coefficient without changing the weights.
  • Predict what happens to the penalty if both supplied weights are doubled.

Guided task 05

A controlled L2 comparison

An L2 experiment should change the penalty while keeping the starting point and fitting procedure comparable. Both models below receive identical initial arrays, the same architecture, the same data order and the same optimizer settings. One adds a kernel penalty and the other does not. Copying initial weights is more explicit than merely hoping repeated construction used the same random state.

The plotted quantity is validation mean squared prediction error calculated directly from inference outputs. It excludes the regularization penalty, so both models are measured on the same prediction task. Kernel norms are printed as a separate observation. A stronger penalty can reduce weight magnitude without improving validation error, especially if the coefficient is poorly chosen or the budget is short. Do not require a particular winner. This exercise demonstrates how to make the comparison interpretable. Selecting a coefficient is a development decision based on limited evidence, and trying many coefficients against the same validation records can itself adapt the process to those records.

Try it

  1. Create two sixteen-unit models and copy one common initialization into both.
  2. Train with L2 coefficients zero and 0.02 for eight epochs.
  3. Compute validation data MSE directly, excluding penalties.
Python · run in order
keras.utils.set_random_seed(407)
template = keras.Sequential([keras.Input((1,)), keras.layers.Dense(16, activation='relu'), keras.layers.Dense(1)])
initial = template.get_weights()
validation_mse = []
kernel_norms = []
for coefficient in [0.0, 0.02]:
    model = keras.Sequential([keras.Input((1,)), keras.layers.Dense(16, activation='relu', kernel_regularizer=keras.regularizers.L2(coefficient)), keras.layers.Dense(1)])
    model.set_weights(initial)
    model.compile(optimizer=keras.optimizers.Adam(0.02), loss='mse')
    model.fit(batches(x_train, y_train), epochs=8, verbose=0, shuffle=False)
    validation_mse.append(float(tf.reduce_mean(tf.square(model(x_val, training=False) - y_val))))
    kernel_norms.append(float(np.linalg.norm(model.layers[0].kernel.numpy())))
print('Kernel norms:', kernel_norms)
fig, ax = plt.subplots(figsize=(6, 4))
ax.bar(['L2 = 0', 'L2 = 0.02'], validation_mse)
ax.set(ylabel='Validation data MSE', title='Compare a shared prediction metric')
fig.tight_layout()

Read the result

Read the measured validation errors without assuming regularization must improve this short run. The printed norms describe weights, while the bars describe held-out predictions.

Change and compare

  • Try a smaller positive coefficient with the same controls.
  • Explain why comparing total objectives alone would mix two different questions.

Guided task 06

Dropout has training and inference modes

Dropout randomly removes some activations during training and scales the retained ones. The fraction specifies a stochastic rule, not an exact number that must disappear from every small input. At inference, ordinary Dropout leaves its input unchanged. This difference lets training discourage reliance on a particular activation pattern while predictions use the full available representation.

The demonstration uses a matrix of ones rather than a trained network, so the effect is directly visible. With rate one half, surviving training values are doubled. The mask changes between training calls, but an inference call returns the original ones. Setting trainable=False is not the switch for this behavior: dropout has no trainable weights, and the training argument controls whether the random masking is used. In a fitted model, Keras passes the appropriate mode through the usual training and inference paths. Keep this distinction in mind when comparing training and validation losses, since one may include stochastic dropout while the other does not.

Try it

  1. Apply one Dropout layer to a four-by-twelve matrix of ones in training mode.
  2. Apply the same layer in inference mode.
  3. Display both outputs with the same color limits.
Python · run in order
dropout = keras.layers.Dropout(0.5, seed=507)
ones = tf.ones((4, 12))
training_values = dropout(ones, training=True).numpy()
inference_values = dropout(ones, training=False).numpy()
fig, axes = plt.subplots(1, 2, figsize=(8, 3))
for ax, values, title in zip(axes, [training_values, inference_values], ['training=True', 'training=False']):
    ax.imshow(values, vmin=0, vmax=2, cmap='viridis')
    ax.set(title=title, xlabel='Activation index', ylabel='Example')
fig.tight_layout()

Read the result

The inference panel remains all ones. The training panel can contain zeros and twos; the exact mask and number of zeros are not requirements of a single small sample.

  • Change the rate to 0.25 and predict the nonzero scale before running.

Guided task 07

Early stopping and restored weights

Early stopping uses a monitored quantity to decide when more training is no longer justified under a chosen rule. Here the monitor is validation loss, patience is two epochs, and lower is better. Patience tolerates a specified run of non-improving epochs; it does not mean training must stop after two epochs total. The maximum epoch count remains a separate upper bound.

Restoring the best weights matters because the last executed epoch may be worse than an earlier one. The callback stores a snapshot associated with its best monitored value and restores that snapshot at the end when requested. The final inference error should therefore be checked against the best observed validation loss, not automatically the last history entry. This small run may use every allowed epoch if validation keeps improving. That is valid behavior, not a failed callback. Early stopping is a validation-based selection decision, so the validation score used to pick the epoch is not an untouched final evaluation. Preserve the separate test role throughout this process.

Try it

  1. Fit a fresh model with validation-loss early stopping, patience two and restored best weights.
  2. Allow up to twelve epochs and record how many actually execute.
  3. Recompute validation MSE from the restored model.
Python · run in order
keras.utils.set_random_seed(607)
stopped_model = keras.Sequential([keras.Input((1,)), keras.layers.Dense(16, activation='relu'), keras.layers.Dense(1)])
stopped_model.compile(optimizer=keras.optimizers.Adam(0.03), loss='mse')
stop = keras.callbacks.EarlyStopping(monitor='val_loss', patience=2, mode='min', restore_best_weights=True)
stopped_history = stopped_model.fit(batches(x_train, y_train), validation_data=batches(x_val, y_val), epochs=12, callbacks=[stop], verbose=0, shuffle=False).history
restored_mse = float(tf.reduce_mean(tf.square(stopped_model(x_val, training=False) - y_val)))
fig, ax = plt.subplots(figsize=(6, 4))
ax.plot(np.arange(1, len(stopped_history['val_loss']) + 1), stopped_history['val_loss'], 'o-', label='observed validation')
ax.axhline(restored_mse, linestyle='--', label='restored model MSE')
ax.set(xlabel='Executed epoch', ylabel='Validation MSE', title='Stopping and restoration are separate choices')
ax.legend()
fig.tight_layout()

Read the result

Compare the restored-model line with the minimum observed validation value. The number of executed epochs depends on the actual curve; do not expect a predetermined stopping epoch.

Change and compare

  • Describe what restore_best_weights=False would change.
  • Explain why increasing patience changes a training rule rather than adding test evidence.

Guided task 08

Selection rules and honest development records

A model-selection rule should be stated before looking for a convenient winner. Consider three fictional development reports with parameter counts and validation MSE. The rule below requires at most one hundred parameters, then chooses the smallest validation error among eligible candidates. A lower error from a model outside that budget is not eligible under the stated request.

The records are illustrative decision inputs, not results of the models trained earlier. Their purpose is to make the selection mechanism transparent. Store the chosen name together with the budget, metric and dataset role so someone can reconstruct the decision. A different budget could legitimately produce a different selection, but repeatedly changing the rule to favor a preferred result is not the same experiment. After selecting a procedure, freeze its architecture, preprocessing and stopping choices before a final test. The development score has already influenced the choice. It should be reported as development evidence, alongside limitations of the small invented fixture, rather than presented as an independent estimate of real-world performance.

Try it

  1. Read the three supplied fictional candidate reports.
  2. Apply the parameter budget before minimizing validation MSE.
  3. Plot the supplied errors and mark the selected eligible candidate.
Python · run in order
names = np.array(['compact', 'medium', 'large'])
parameters = np.array([17, 65, 161])
reported_mse = np.array([0.030, 0.025, 0.020])
eligible = np.flatnonzero(parameters <= 100)
chosen_index = eligible[np.argmin(reported_mse[eligible])]
chosen = str(names[chosen_index])
fig, ax = plt.subplots(figsize=(6, 4))
ax.bar(names, reported_mse, color=['tab:green' if i == chosen_index else 'gray' for i in range(3)])
ax.set(ylabel='Supplied validation MSE', title='Illustrative selection under a parameter budget')
fig.tight_layout()

Read the result

The selected bar follows both the budget and the metric rule. These supplied values are not measured training results and must not be attributed to the earlier models.

  • Write the information needed to reproduce a selection without showing final-test results.
