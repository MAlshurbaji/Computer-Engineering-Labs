Python · shared setup
import numpy as np
import tensorflow as tf
import keras
import matplotlib.pyplot as plt
keras.utils.set_random_seed(115)
rng = np.random.default_rng(115)
class_names = ["cup", "bottle"]

def batches(x, y, batch_size=16, shuffle=False):
    ds = tf.data.Dataset.from_tensor_slices((x, y))
    if shuffle:
        ds = ds.shuffle(len(x), seed=123, reshuffle_each_iteration=True)
    options = tf.data.Options()
    options.threading.private_threadpool_size = 1
    options.threading.max_intra_op_parallelism = 1
    return ds.batch(batch_size).with_options(options)

# A group is one drawn object; its two noisy views must stay together.
def pictures(group_ids, tint=False):
    images, labels, groups = [], [], []
    for gid in group_ids:
        local = np.random.default_rng(int(gid) + 800)
        label = int(gid) % 2
        shift = int(local.integers(-1, 2))
        base = np.zeros((16, 16), dtype=np.float32)
        if label == 0:
            base[6:13, 4+shift:10+shift] = 0.85
            base[7:11, 10+shift:12+shift] = 0.85
            base[8:10, 10+shift:11+shift] = 0
        else:
            base[3:6, 7+shift:9+shift] = 0.85
            base[6:13, 5+shift:11+shift] = 0.85
        for view in range(2):
            image = np.repeat(base[..., None], 3, axis=-1)
            if tint:
                image = image * np.array([0.7, 0.9, 1.0], dtype=np.float32)
            image = np.clip(image + local.normal(0, 0.025, image.shape), 0, 1)
            images.append(image.astype("float32"))
            labels.append(label)
            groups.append(gid)
    return np.stack(images), np.array(labels, dtype="int32"), np.array(groups)

train_ids = np.arange(0, 32)
val_ids = np.arange(32, 40)
test_ids = np.arange(40, 48)
x_train, y_train, g_train = pictures(train_ids)
x_val, y_val, g_val = pictures(val_ids)
x_test, y_test, g_test = pictures(test_ids)

def classifier(augmentation=None):
    inputs = keras.Input((16, 16, 3))
    z = inputs if augmentation is None else augmentation(inputs)
    z = keras.layers.Conv2D(4, 3, padding="same", activation="relu", name="features")(z)
    z = keras.layers.MaxPooling2D()(z)
    z = keras.layers.Flatten()(z)
    outputs = keras.layers.Dense(2, name="scores")(z)
    model = keras.Model(inputs, outputs)
    model.compile(optimizer=keras.optimizers.Adam(0.005),
                  loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
                  metrics=["accuracy"])
    return model

import json
import tempfile
from pathlib import Path

def project_model(width, mean, variance):
    inputs = keras.Input((16,16,3), dtype="float32")
    normalized = keras.layers.Normalization(axis=-1, mean=mean, variance=variance)(inputs)
    features = keras.layers.Conv2D(width,3,padding="same",activation="relu")(normalized)
    pooled = keras.layers.MaxPooling2D()(features)
    outputs = keras.layers.Dense(2)(keras.layers.Flatten()(pooled))
    model = keras.Model(inputs,outputs)
    model.compile(optimizer=keras.optimizers.Adam(0.003),
        loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
        metrics=["accuracy"])
    return model

def validate_batch(images):
    images = np.asarray(images)
    if images.dtype != np.float32 or images.ndim != 4 or images.shape[1:] != (16,16,3):
        raise ValueError("Expected float32 NHWC images with shape (N,16,16,3).")
    if len(images) == 0 or not np.isfinite(images).all() or images.min()<0 or images.max()>1:
        raise ValueError("Expected a nonempty finite batch in the zero-to-one range.")
    return images

Guided task 01

Project Scope and Data Contract

The project is a small desk-item sorter that distinguishes a drawn cup from a drawn bottle. Define the output contract before training: index zero means cup, index one means bottle, and each input is a 16×16 RGB float32 image in the zero-to-one range. The system does not recognize every object that might appear on a desk; a forced two-class prediction is not an out-of-distribution detector.

The setup creates two related views per object group and assigns whole groups to training, validation, and test. Training supports parameter learning, validation chooses between two planned model sizes, and test remains untouched until the final reporting task. This role assignment is part of the project specification, not something to revise when a score is disappointing.

Write down what the experiment can establish: repeatable classification measurements on the supplied drawing generator, with a saved model and preprocessing metadata. Real camera use would require representative photographs, uncertain or unknown-object handling, and a new evaluation plan. Keeping the claim narrow makes the project more useful because another student can reproduce exactly what was built and measured.

Guided task 02

Training-only Preprocessing Statistics

Fixed pixel scaling and learned normalization are different operations. The drawing generator already returns values between zero and one. We now estimate one mean and variance for each RGB channel using only training pixels. These statistics become part of the model's preprocessing, while validation and test retain their role as unseen evaluation inputs.

The reduction axes are batch, height, and width, leaving a three-element channel vector. Variance is the mean squared deviation under NumPy's default population convention. A Normalization layer can store these supplied statistics and apply the same transformation during training and inference. The model file will therefore contain the learned preprocessing values rather than relying on a user to remember a separate normalization step.

Check that the variances are finite and nonzero. A nearly constant channel can make scaling sensitive to tiny differences; the library uses a numerical safeguard, but the data should still be inspected. The plotted channel means describe this training fixture, not a general property of cups or bottles. Never recompute the statistics on an incoming test batch, which would change the model's input interpretation between evaluations.

Try it

  1. Compute per-channel mean and variance from x_train only.
  2. Check the three-element results.
  3. Plot the stored training means with clear channel labels.
Python · run in order
channel_mean = x_train.mean(axis=(0,1,2))
channel_variance = x_train.var(axis=(0,1,2))
fig, ax = plt.subplots(figsize=(5,3))
ax.bar(["Red","Green","Blue"],channel_mean)
ax.set(ylabel="Training mean intensity",ylim=(0,1))
print("Variance:",channel_variance)
fig.tight_layout()

Read the result

The three means are measured from training data before any model choice. Later saved models embed exactly these statistics. A validation or test batch should be passed through that fixed transform without adapting it again.

Guided task 03

A Simple Baseline and Success Criterion

A baseline gives model performance a meaningful point of comparison. The simplest classifier here always predicts the most frequent training class. Count training labels, choose the first maximum to resolve a tie, then evaluate that fixed prediction on validation labels. The baseline has no access to validation labels while deciding which class to predict.

A balanced drawing fixture makes this baseline deliberately weak but transparent. On a different dataset, a high majority-class accuracy might reveal severe imbalance rather than a useful solution. Record the class support and baseline accuracy before training candidate CNNs. This helps prevent celebrating a number that a trivial rule already achieves.

The project will select between two small CNN widths using final validation cross-entropy after an equal four-epoch budget. That criterion is stated now, before candidate results. Accuracy remains a reporting measurement, while cross-entropy guides the planned choice. This distinction avoids switching metrics after seeing which one favors a preferred model. The test set stays reserved for the final chosen artifact.

Try it

  1. Build the majority rule from training labels.
  2. Compute its validation accuracy.
  3. Record the planned loss-based candidate-selection rule.
Python · run in order
training_counts = np.bincount(y_train,minlength=2)
majority_class = int(np.argmax(training_counts))
baseline_predictions = np.full(len(y_val),majority_class)
baseline_accuracy = float(np.mean(baseline_predictions==y_val))
fig, ax = plt.subplots(figsize=(5,3))
ax.bar(class_names,training_counts)
ax.set(ylabel="Training views",title="Majority baseline: "+class_names[majority_class])
print("Validation baseline accuracy:",baseline_accuracy)
fig.tight_layout()

Read the result

The chart documents the label distribution from which the baseline was constructed. Baseline evaluation uses validation labels only after the rule is fixed. A CNN must be interpreted relative to this simple comparison and the fixture's limits.

Guided task 04

Controlled Candidate Training

A useful project comparison changes one planned design choice at a time. The two candidates have four or eight convolution filters, while input preprocessing, pooling, output classes, optimizer rate, batch size, and epoch budget stay the same. Each candidate receives the same training-only channel statistics.

Set a recorded random seed before constructing each candidate. Different widths still require different parameter arrays, so matching a seed does not give identical initial weights or equal model capacity. It does make the procedure reproducible within the stated environment. The dataset helper shuffles training examples while validation batches remain fixed.

Train both candidates for four epochs and retain their histories and complete models. Plot training and validation loss for each in separate panels within one figure. A larger model is not guaranteed to perform better; it may learn faster, overfit, or behave similarly on a tiny dataset. Do not add more candidates because one particular test score looks attractive. The next task applies the already stated validation rule to these two finished runs.

Try it

  1. Build widths four and eight with recorded seeds.
  2. Train each for four epochs using the same statistics.
  3. Retain models and histories for the planned comparison.
Python · run in order
widths = [4,8]
candidates, histories = [], []
for width in widths:
    keras.utils.set_random_seed(115+width)
    candidate = project_model(width,channel_mean,channel_variance)
    run = candidate.fit(batches(x_train,y_train,shuffle=True),validation_data=batches(x_val,y_val),epochs=4,shuffle=False,verbose=0)
    candidates.append(candidate)
    histories.append(run.history)
fig, axes = plt.subplots(1,2,figsize=(9,3))
for ax,width,run in zip(axes,widths,histories):
    ax.plot(run["loss"],label="Train")
    ax.plot(run["val_loss"],label="Validation")
    ax.set(title=str(width)+" filters",xlabel="Epoch index",ylabel="Cross-entropy")
    ax.legend()
fig.tight_layout()

Read the result

These are actual candidate learning curves. Compare training behavior and validation behavior separately, keeping the equal target budget visible. A single short run does not establish that one architecture is universally preferable.

Change and compare

  • Compare the candidates' parameter counts.
  • Explain which factors are controlled and which necessarily differ.

Guided task 05

Selection and Validation Error Review

Apply the stated selection rule to the final validation loss of each candidate. The smaller value wins; an exact tie selects the four-filter model because it appears first. Save the selected index, width, and model reference. No test prediction is needed to make this choice.

An aggregate loss does not show individual cases. Inspect a few validation images with the smallest absolute difference between the two output logits. These are low-margin decisions, which can be correct or incorrect. A small margin is not a calibrated probability of error, but it identifies examples where the two scores are close for this model.

The review is descriptive at this stage. It helps characterize the selected model and catch obvious data or labeling mistakes without silently expanding the experiment into unlimited tuning. If the inspection motivates a new research question, plan a separate development cycle and protect a fresh final evaluation set. Record the current selected artifact rather than overwriting the conclusion whenever another model happens to look better on one displayed image.

Try it

  1. Select the minimum final validation loss.
  2. Find four validation pictures with the smallest logit margins.
  3. Display true and predicted labels for those pictures.
Python · run in order
selection_losses = np.array([h["val_loss"][-1] for h in histories])
selected_index = int(np.argmin(selection_losses))
selected_width = widths[selected_index]
selected_model = candidates[selected_index]
validation_logits = selected_model(x_val,training=False).numpy()
validation_predictions = np.argmax(validation_logits,axis=1)
margins = np.abs(validation_logits[:,0]-validation_logits[:,1])
review_indices = np.argsort(margins,kind="stable")[:4]
fig, axes = plt.subplots(1,4,figsize=(10,3))
for ax,index in zip(axes,review_indices):
    ax.imshow(x_val[index])
    ax.set_title("True "+class_names[y_val[index]]+"\nPred "+class_names[validation_predictions[index]])
    ax.axis("off")
print("Selected width:",selected_width,"validation losses:",selection_losses)
fig.tight_layout()

Read the result

The gallery is chosen by score margin, not by whether an image makes the model look good. Read correct and incorrect low-margin cases together. The selection remains the predefined validation-loss rule.

Guided task 06

Saving the Model and Its Meaning

A reusable artifact needs both numerical computation and an interpretation contract. Save the complete selected Keras model, including its Normalization layer, in a newly created temporary directory. The .keras file stores the architecture and weights. A separate JSON metadata file records how callers should supply inputs and interpret output indices.

The metadata includes class order, input dimensions, dtype, pixel range, training channel statistics, selected filter width, seed convention, group-split description, and the selection criterion. These fields prevent a common deployment error: applying an already embedded normalization twice or decoding class index one with the wrong label list. The statistics are recorded for audit; inference sends raw zero-to-one pixels into the saved model.

A fresh temporary directory avoids overwriting an earlier experiment. Print its path so the learner can inspect the two files. The parameter-count plot describes the actual candidate architectures, not their quality. Saving a model does not freeze every detail of a computing environment, so retain package versions and numerical tolerances when comparing reload behavior. The next task evaluates the saved artifact rather than relying only on the still-live Python variable.

Try it

  1. Create a fresh temporary artifact directory.
  2. Save the selected model and explicit metadata JSON.
  3. Record package versions and inspect parameter counts.
Python · run in order
artifact_dir = Path(tempfile.mkdtemp(prefix="desk-project-"))
model_path = artifact_dir / "desk_sorter.keras"
metadata_path = artifact_dir / "metadata.json"
selected_model.save(model_path)
metadata = {"class_names":class_names,"input_shape":[16,16,3],"dtype":"float32","pixel_range":[0,1],"normalization_embedded":True,"channel_mean":channel_mean.tolist(),"channel_variance":channel_variance.tolist(),"selected_width":selected_width,"candidate_seeds":[119,123],"selection":"minimum final validation cross-entropy; four-filter tie break","split":"disjoint object groups before fitting","data":"drawn cups and bottles","keras_version":keras.__version__,"tensorflow_version":tf.__version__}
metadata_path.write_text(json.dumps(metadata,indent=2),encoding="utf-8")
fig, ax = plt.subplots(figsize=(5,3))
ax.bar(["4 filters","8 filters"],[m.count_params() for m in candidates])
ax.set(ylabel="Model parameters")
print("Artifacts:",artifact_dir)
fig.tight_layout()

The saved model contains preprocessing, while the metadata explains its expected raw input and output order. The artifact directory is unique to this run. Parameter count measures size and cannot be substituted for validation quality.

Guided task 07

One Reserved Test Report

Reload the saved model and metadata, then perform the final reserved-test evaluation. The input validator enforces the recorded dtype, shape, finite values, and zero-to-one range. Because normalization is embedded in the model, the validated raw test arrays are passed directly to inference.

Compare reloaded logits with the selected in-memory model on those same inputs. Numerical equality within a small tolerance verifies persistence of the computation in this environment. Then decode predictions using the saved class order, not an unrelated hard-coded label list. Build a confusion matrix with true classes as rows and predicted classes as columns.

This is the project's final test report. The model and selection criterion were fixed before this task. Do not use its errors to choose the other candidate while still presenting the result as an untouched final evaluation. Report accuracy together with class support, group counts, and the drawn-data limitation. The confusion plot uses contrast-aware text so high-count cells remain readable. Its purpose is to make the actual measurement inspectable rather than to decorate the project with a single impressive number.

Try it

  1. Load the model and metadata from the saved directory.
  2. Validate and predict the reserved test batch once for reporting.
  3. Check reload equality and plot the confusion matrix.
Python · run in order
loaded_model = keras.models.load_model(model_path)
loaded_metadata = json.loads(metadata_path.read_text(encoding="utf-8"))
test_batch = validate_batch(x_test)
test_logits = loaded_model(test_batch,training=False).numpy()
memory_logits = selected_model(test_batch,training=False).numpy()
test_predictions = np.argmax(test_logits,axis=1)
test_accuracy = float(np.mean(test_predictions==y_test))
confusion = np.zeros((2,2),dtype=int)
np.add.at(confusion,(y_test,test_predictions),1)
fig, ax = plt.subplots(figsize=(4,3))
ax.imshow(confusion,cmap="Blues")
for r in range(2):
    for c in range(2):
        ax.text(c,r,str(confusion[r,c]),ha="center",va="center",color="white" if confusion[r,c]>confusion.max()/2 else "black")
ax.set(xticks=[0,1],yticks=[0,1],xticklabels=loaded_metadata["class_names"],yticklabels=loaded_metadata["class_names"],xlabel="Predicted",ylabel="True")
print("Final test accuracy:",test_accuracy,"views:",len(y_test),"groups:",len(np.unique(g_test)))
fig.tight_layout()

Read the result

The matrix is a measurement from the saved selected artifact on reserved groups. Reload equality checks preservation, while the confusion matrix checks classification outcomes. Neither establishes reliability beyond the supplied drawn-data domain.

Guided task 08

A Reproducible Inference Handoff

A final handoff should make ordinary inference predictable and reject malformed input clearly. The saved model expects a nonempty batch of zero-to-one float32 RGB drawings with the specified spatial dimensions. A uint8 array, a missing channel axis, a NaN, or an out-of-range intensity is an input-contract error, not a new model performance result.

Run one independent new group through the loaded artifact, then decode its output with the saved class order. This group is an illustrative inference demonstration after final reporting, not a new tuning set and not a replacement test score. Also exercise the validator with deliberately malformed copies to confirm that errors are raised before the model is called.

The handoff should distinguish deterministic procedure from universal bit-for-bit reproducibility. Recorded seeds, data generation, class order, model file, preprocessing metadata, and library versions make the experiment repeatable, while floating-point results can still depend on runtime details. Keep a tolerance for numerical comparisons. Finish by naming the model's scope and an appropriate next dataset rather than claiming that a tiny drawing classifier is ready for arbitrary real-world sorting.

Try it

  1. Generate one new drawn object group for an inference example.
  2. Decode outputs using saved metadata.
  3. Confirm that wrong dtype and nonfinite input are rejected.
Python · run in order
new_images, new_labels, new_groups = pictures(np.array([300]))
new_logits = loaded_model(validate_batch(new_images),training=False).numpy()
new_predictions = np.argmax(new_logits,axis=1)
rejected = 0
bad_nan = new_images.copy()
bad_nan[0,0,0,0] = np.nan
for malformed in [new_images.astype("uint8"),bad_nan]:
    try:
        validate_batch(malformed)
    except ValueError:
        rejected += 1
fig, axes = plt.subplots(1,2,figsize=(6,3))
for i,ax in enumerate(axes):
    ax.imshow(new_images[i])
    ax.set_title(loaded_metadata["class_names"][new_predictions[i]])
    ax.axis("off")
print("Malformed batches rejected:",rejected)
fig.tight_layout()

Read the result

The displayed labels are actual inferences from the saved artifact on a new drawn group. The rejection count checks input handling, not classification accuracy. Preserve the artifact and experiment description together for another student to reproduce the workflow.
