Run setup once and teaching tasks in order. Images are float32 RGB in [0, 1], with class order Cup=0, Book=1, Bottle=2. The stratified split is fixed before model fitting.

Python · shared setup
import tensorflow as tf
import keras
import numpy as np
import matplotlib.pyplot as plt
keras.utils.set_random_seed(105)
rng = np.random.default_rng(105)

# Independent procedural drawings, not photographs or real recognition evidence.
class_names = ["Cup", "Book", "Bottle"]
def draw_item(label, row_shift, col_shift, tint):
    image = np.full((16, 16, 3), 0.94, dtype=np.float32)
    if label == 0:
        image[5:13, 3:10] = [0.15, 0.4, tint]
        image[6:11, 10:14] = [0.15, 0.4, tint]
        image[7:10, 10:12] = 0.94
    elif label == 1:
        image[3:14, 3:13] = [tint, 0.22, 0.2]
        image[4:13, 5:12] = [0.88, 0.82, 0.62]
    else:
        image[2:5, 7:10] = [0.25, 0.35, 0.25]
        image[5:14, 5:12] = [0.2, tint, 0.32]
    return np.roll(image, (row_shift, col_shift), axis=(0, 1))
pictures, targets = [], []
for label in range(3):
    for sample in range(60):
        image = draw_item(label, int(rng.integers(-1,2)), int(rng.integers(-1,2)), float(rng.uniform(.55,.85)))
        image = np.clip(image + rng.normal(0, .015, image.shape), 0, 1).astype(np.float32)
        pictures.append(image)
        targets.append(label)
images = np.stack(pictures)
labels = np.array(targets, dtype=np.int32)
train_ids, val_ids, test_ids = [], [], []
for label in range(3):
    ids = rng.permutation(np.flatnonzero(labels == label))
    train_ids.extend(ids[:36])
    val_ids.extend(ids[36:48])
    test_ids.extend(ids[48:])
train_ids, val_ids, test_ids = [rng.permutation(ids) for ids in (train_ids,val_ids,test_ids)]
x_train, y_train = images[train_ids], labels[train_ids]
x_val, y_val = images[val_ids], labels[val_ids]
x_test, y_test = images[test_ids], labels[test_ids]

def batches(x, y, batch_size=16, shuffle=False):
    ds = tf.data.Dataset.from_tensor_slices((x, y))
    if shuffle:
        ds = ds.shuffle(len(x), seed=123, reshuffle_each_iteration=True)
    options = tf.data.Options()
    options.threading.private_threadpool_size = 1
    options.threading.max_intra_op_parallelism = 1
    return ds.batch(batch_size).with_options(options)

Guided task 01

Class labels and dataset meaning

A classification target names a category rather than a numeric amount. Cup, book and bottle are encoded as integers zero, one and two, but those integers do not represent ordered measurements. Predicting two is not twice as much object as predicting one. The class-name list supplies the meaning of each integer and later fixes the order of the model's output columns.

The fixture generator creates small drawings with limited shifts, colour variation and pixel noise. These are independent examples of three designed patterns, not photographs collected from real desks. Each split contains examples from every class, with IDs assigned before fitting. The pictures make the task easy to inspect, but a successful model could rely on colour or background regularities that would fail outside this generator. Display examples and count labels before training so that the problem you intend matches the data you actually created. A balanced fixture simplifies this lesson's comparisons; real datasets may have very different class frequencies. Keep the representation assumptions visible alongside the model, including RGB order, floating-point scale and the final-axis channel convention established in Lab 01.

Guided task 02

Logits, softmax and class order

A multiclass model can output unrestricted scores called logits. A larger logit indicates a stronger relative preference within that model's class ordering, but the raw values do not sum to one and are not probabilities. Softmax converts each score row into nonnegative shares that sum to one across the class axis. Argmax chooses the position of the largest entry; it returns an index, so a separate class-name mapping is still needed.

Use three deliberately supplied score rows before examining any fitted model. One row clearly favors a class, another is less separated, and one contains a tie. Equal top values require an explicit tie convention; TensorFlow's argmax chooses the smallest index among equal maxima. This deterministic behavior is a software rule, not additional evidence about the drawing. For untied scores, softmax preserves the winning class because it is monotonic within the shared normalization. Plotting both raw scores and transformed outputs helps separate score magnitude from a decision. Even a sharply peaked output does not certify that an input resembles the training population or that its probability estimates are calibrated.

Try it

  1. Create the three supplied score rows in Cup, Book, Bottle order.
  2. Compute row-wise softmax and argmax predictions.
  3. Plot raw logits and transformed shares for the same rows.
Python · run in order
example_logits = tf.constant([[2.0,0.2,-1.0],[0.4,0.5,0.3],[1.0,1.0,-0.5]],tf.float32)
example_probabilities = tf.nn.softmax(example_logits,axis=-1)
winners = tf.argmax(example_logits,axis=-1).numpy()
fig, axes = plt.subplots(1,2,figsize=(9,3))
for i,ax in enumerate(axes):
    values = example_logits.numpy() if i==0 else example_probabilities.numpy()
    im = ax.imshow(values,cmap="viridis")
    ax.set_xticks(range(3),class_names)
    ax.set_yticks(range(3),["Clear row","Close row","Tied row"])
    ax.set_title("Logits" if i==0 else "Softmax shares")
    fig.colorbar(im,ax=ax)
fig.tight_layout()
print("Chosen names:",[class_names[i] for i in winners])

Read the result

Both transformations preserve the ordering of untied classes. The tied row selects Cup because its tied maximum has the smaller index, which is a declared computational convention rather than stronger visual support.

Guided task 03

Sparse categorical cross-entropy

Sparse categorical cross-entropy compares one integer class label per example with a vector of class outputs. Sparse refers to the label representation: a single integer identifies the correct column, rather than a one-hot target vector. When the model produces raw logits, set from_logits=True so the loss interprets those values correctly and handles the normalization internally.

The penalty depends on the probability assigned to the true class. A wrong prediction made with strong preference for another class can receive a much larger loss than an uncertain prediction, even if both have the same argmax error count. Conversely, two correct predictions can have different losses because their true-class probabilities differ. In this task, fixed logits make the comparison inspectable without training. Calculate the loss without reduction to retain one contribution per row, and compare it with negative log of the corresponding softmax probability. This direct formula is an explanatory check; the built-in logits-aware loss is the appropriate training interface because it avoids an unnecessary manual probability calculation in the objective path. Always keep the integer label range consistent with the number and order of output units.

Try it

  1. Create three fixed logit rows and their integer labels.
  2. Compute unreduced sparse cross-entropy with from_logits=True.
  3. Compare each loss with the true-class probability.
Python · run in order
logits = tf.constant([[2.0,0.0,-1.0],[0.0,2.0,-1.0],[0.0,2.0,-1.0]],tf.float32)
true_labels = tf.constant([0,0,1],tf.int32)
loss_function = keras.losses.SparseCategoricalCrossentropy(from_logits=True,reduction="none")
row_losses = loss_function(true_labels,logits)
probabilities = tf.nn.softmax(logits,axis=-1)
true_probability = tf.gather(probabilities,true_labels,axis=1,batch_dims=1)
fig, axes = plt.subplots(1,2,figsize=(9,3))
axes[0].bar(["Row 1","Row 2","Row 3"],true_probability)
axes[0].set(ylabel="Probability assigned to true class",ylim=(0,1))
axes[1].bar(["Row 1","Row 2","Row 3"],row_losses)
axes[1].set(ylabel="Cross-entropy contribution",title="True-class support drives the penalty")
fig.tight_layout()
print("Labels:",true_labels.numpy(),"losses:",row_losses.numpy())

Read the result

Rows two and three have identical model scores but different true labels, so their losses differ. The labels are part of the objective; interpreting scores alone cannot determine whether a prediction is correct.

Change and compare

  • Keep a row's label fixed and increase only its true-class logit.
  • Compare the loss ordering with a simple correct/incorrect flag and identify information the flag discards.

Guided task 04

A tiny Dense image classifier

A Dense classifier can consume an image by flattening its pixels into one feature vector. Flatten preserves the value order but removes an explicit spatial grid from the next layer's input. The hidden Dense layer can combine all pixel features, while the final three-unit linear layer produces one logit for each class. Later convolutional labs introduce a different way to use spatial structure.

The fixture already supplies float32 RGB values in zero through one, so dividing by 255 again would be a representation error. Build a twelve-unit ReLU hidden layer and train with sparse categorical cross-entropy from logits. Sparse categorical accuracy reports how often the largest logit matches the integer target. Loss and accuracy measure different aspects: accuracy depends only on the chosen class, while loss also responds to relative score support. Use the validation set to observe this declared eight-epoch run, keeping test labels reserved. The training helper shuffles only training examples and uses a bounded data pipeline. Any strong result on these simple repeated drawing styles remains a result about the generator, not evidence of recognition across arbitrary household photographs.

Try it

  1. Build Flatten → Dense(12, ReLU) → Dense(3, linear).
  2. Train eight epochs with the logits-aware sparse loss and accuracy metric.
  3. Plot recorded loss and accuracy for training and validation.
Python · run in order
classifier = keras.Sequential([keras.Input(shape=(16,16,3)),keras.layers.Flatten(),keras.layers.Dense(12,activation="relu"),keras.layers.Dense(3)])
classifier.compile(optimizer=keras.optimizers.Adam(0.01),loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),metrics=[keras.metrics.SparseCategoricalAccuracy(name="accuracy")])
history = classifier.fit(batches(x_train,y_train,shuffle=True),validation_data=batches(x_val,y_val),epochs=8,verbose=0,shuffle=False)
validation_logits = classifier(x_val,training=False).numpy()
fig, axes = plt.subplots(1,2,figsize=(9,3))
for key,label in [("loss","Cross-entropy"),("accuracy","Classification accuracy")]:
    ax = axes[0] if key=="loss" else axes[1]
    ax.plot(history.history[key],label="Training")
    ax.plot(history.history["val_"+key],label="Validation")
    ax.set(xlabel="Epoch index",ylabel=label)
    ax.legend()
fig.tight_layout()
print("Validation logits shape:",validation_logits.shape)

Read the result

Compare the two metrics rather than treating them as interchangeable. A correct class choice can stay unchanged while its logits and cross-entropy continue moving. The output shape must retain one row per image and three class columns.

Guided task 05

Binary labels, sigmoid and BCE

A binary formulation asks one yes-or-no question rather than choosing among three separate names. Here the positive class is Bottle, encoded as one, and the negative class is any other supplied drawing, encoded as zero. This merges Cup and Book for the binary task without changing the underlying pictures. The target definition must be explicit because reversing the positive class reverses how the output should be interpreted.

Use one final sigmoid unit with binary cross-entropy configured for probability outputs. This is a different output-loss pairing from the three linear logits and sparse loss used earlier. The negative class does not need a second independent sigmoid unit: for this mutually exclusive binary task its probability is one minus the positive-class output. The validation histogram groups model outputs by true binary label, allowing overlap or separation to be inspected without imposing a decision threshold yet. These are estimated positive-class outputs from a small synthetic training problem. Their numerical range does not establish probability calibration, and a confident output on an unfamiliar picture still requires cautious interpretation. Keep the multi-class classifier unchanged so the two problem formulations remain separate experiments.

Try it

  2. Train a separate eight-unit Dense binary model for six epochs.
  3. Plot validation outputs separately for true bottles and other drawings.

ax.set(xlabel="Model output for positive class Bottle",ylabel="Validation drawings",title="Binary formulation of the same fixtures")
ax.legend()
fig.tight_layout()

Guided task 06

Thresholds are decision rules

A binary probability-like output and a class decision are different objects. A threshold converts the numeric output into a positive or negative decision. We declare that an output equal to the threshold counts as positive. Raising this threshold can only remove positive decisions for a fixed set of scores; it cannot create additional positives. The model weights stay unchanged during this comparison.

Evaluate thresholds 0.3, 0.5 and 0.7 on the same binary validation outputs. Count false positives, where a non-bottle is selected, and false negatives, where a bottle is missed. A threshold change trades decisions rather than retraining the representation. The observed counts may remain unchanged if no output lies between two thresholds, so do not expect a visible tradeoff in every small fixture. Deciding an operational threshold requires a stated application objective and appropriate validation evidence; this lesson only inspects the mechanics. The two bar charts show both the number of selected examples and the corresponding error types. Keeping the exact equality rule in the specification prevents ambiguous behavior at a boundary when a later program implements the same decision.

Try it

  1. Keep the fitted binary model and its validation outputs fixed.
  2. Apply inclusive thresholds 0.3, 0.5 and 0.7.
  3. Count selected examples, false positives and false negatives for each.
Python · run in order
thresholds = [0.3,0.5,0.7]
truth = binary_val.ravel().astype(bool)
selected_counts, false_positives, false_negatives = [], [], []
for threshold in thresholds:
    chosen = bottle_probability>=threshold
    selected_counts.append(int(chosen.sum()))
    false_positives.append(int(np.sum(chosen & ~truth)))
    false_negatives.append(int(np.sum(~chosen & truth)))
fig, axes = plt.subplots(1,2,figsize=(9,3))
axes[0].bar([str(t) for t in thresholds],selected_counts)
axes[0].set(xlabel="Inclusive threshold",ylabel="Positive decisions")
positions = np.arange(3)
axes[1].bar(positions-.15,false_positives,width=.3,label="False positives")
axes[1].bar(positions+.15,false_negatives,width=.3,label="False negatives")
axes[1].set_xticks(positions,[str(t) for t in thresholds])
axes[1].set(xlabel="Inclusive threshold",ylabel="Validation errors")
axes[1].legend()
fig.tight_layout()
print("Selected:",selected_counts,"FP:",false_positives,"FN:",false_negatives)

Read the result

Compare counts for the same fixed predictions. Positive decisions cannot increase as the threshold rises, although counts can tie when the fixture contains no scores in an affected interval.

Guided task 07

Confusion counts and axis conventions

A confusion matrix organizes class decisions by true and predicted labels. In this lesson rows are true classes and columns are predicted classes. A diagonal entry counts correct decisions for one class; an off-diagonal entry shows a particular kind of substitution. The matrix is a table of counts, so row totals must equal the number of examples with each true class.

Apply argmax to the unchanged multiclass model's validation logits and use the declared class order for both axes. Overall accuracy is the diagonal sum divided by the number of evaluated examples. It compresses the table to one proportion, so it can hide which class pairs are confused. A row-normalized table can answer another question about per-class fractions, but here we retain raw counts to make conservation of examples easy to inspect. The synthetic validation set has equal class counts, which limits what this example demonstrates about imbalance. Do not transpose axes silently when comparing with another tool: the same numbers in the opposite orientation would reverse the meaning of each error. A labelled plot and row-total check make the convention explicit.

Try it

  1. Select multiclass labels from validation logits without changing the model.
  2. Build a three-by-three table with true classes on rows.
  3. Display counts and compute overall accuracy from its diagonal.
Python · run in order
predicted_labels = np.argmax(validation_logits,axis=1)
confusion = tf.math.confusion_matrix(y_val,predicted_labels,num_classes=3).numpy()

Guided task 08

Held-out predictions and model scope

Use the reserved test split only after the multiclass architecture and eight-epoch training procedure have been fixed. Compute predictions once, compare them with test labels, and describe the result as performance on the held-out generated drawings. The separate binary experiment and threshold illustrations do not change this predeclared final multiclass model.

A class prediction does not explain why the network selected it. For inspection, rank the test outputs by entropy and display a few of the less concentrated score distributions. Entropy is calculated from the softmax shares and is larger when support is spread among classes. It is a description of model output, not a proof that a prediction is wrong or that a low-entropy prediction is safe. The selected panels retain both the true and predicted names, so a reader can see what the output did on these examples. Even perfect test decisions would leave the limited rendering style, small shifts and familiar colours as major scope restrictions. Testing new environments or unseen object styles requires new evidence rather than a stronger claim about this fixture.

Try it

  1. Evaluate the fixed multiclass model on the held-out test images.
  2. Calculate accuracy and output entropy without retraining.
  3. Show four test drawings with the highest output entropy.
Python · run in order
test_logits = classifier(x_test,training=False)
test_probabilities = tf.nn.softmax(test_logits,axis=-1).numpy()
test_labels = np.argmax(test_probabilities,axis=1)
test_accuracy = float(np.mean(test_labels==y_test))
entropy = -np.sum(test_probabilities*np.log(np.clip(test_probabilities,1e-7,1.0)),axis=1)
inspect_ids = np.argsort(entropy)[-4:][::-1]
fig, axes = plt.subplots(1,4,figsize=(11,3))
for ax,index in zip(axes,inspect_ids):
    ax.imshow(x_test[index])
    ax.set_title(f"True: {class_names[y_test[index]]}\nPred: {class_names[test_labels[index]]}\nEntropy: {entropy[index]:.3f}",fontsize=10)
    ax.set_axis_off()
fig.tight_layout()
print("Held-out generated-image accuracy:",test_accuracy)
