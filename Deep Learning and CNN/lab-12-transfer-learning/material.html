Python · shared setup
import numpy as np
import tensorflow as tf
import keras
import matplotlib.pyplot as plt
keras.utils.set_random_seed(112)
rng = np.random.default_rng(112)
class_names = ["cup", "bottle"]

def batches(x, y, batch_size=16, shuffle=False):
    ds = tf.data.Dataset.from_tensor_slices((x, y))
    if shuffle:
        ds = ds.shuffle(len(x), seed=123, reshuffle_each_iteration=True)
    options = tf.data.Options()
    options.threading.private_threadpool_size = 1
    options.threading.max_intra_op_parallelism = 1
    return ds.batch(batch_size).with_options(options)

# A group is one drawn object; its two noisy views must stay together.
def pictures(group_ids, tint=False):
    images, labels, groups = [], [], []
    for gid in group_ids:
        local = np.random.default_rng(int(gid) + 800)
        label = int(gid) % 2
        shift = int(local.integers(-1, 2))
        base = np.zeros((16, 16), dtype=np.float32)
        if label == 0:
            base[6:13, 4+shift:10+shift] = 0.85
            base[7:11, 10+shift:12+shift] = 0.85
            base[8:10, 10+shift:11+shift] = 0
        else:
            base[3:6, 7+shift:9+shift] = 0.85
            base[6:13, 5+shift:11+shift] = 0.85
        for view in range(2):
            image = np.repeat(base[..., None], 3, axis=-1)
            if tint:
                image = image * np.array([0.7, 0.9, 1.0], dtype=np.float32)
            image = np.clip(image + local.normal(0, 0.025, image.shape), 0, 1)
            images.append(image.astype("float32"))
            labels.append(label)
            groups.append(gid)
    return np.stack(images), np.array(labels, dtype="int32"), np.array(groups)

train_ids = np.arange(0, 32)
val_ids = np.arange(32, 40)
test_ids = np.arange(40, 48)
x_train, y_train, g_train = pictures(train_ids)
x_val, y_val, g_val = pictures(val_ids)
x_test, y_test, g_test = pictures(test_ids)

def classifier(augmentation=None):
    inputs = keras.Input((16, 16, 3))
    z = inputs if augmentation is None else augmentation(inputs)
    z = keras.layers.Conv2D(4, 3, padding="same", activation="relu", name="features")(z)
    z = keras.layers.MaxPooling2D()(z)
    z = keras.layers.Flatten()(z)
    outputs = keras.layers.Dense(2, name="scores")(z)
    model = keras.Model(inputs, outputs)
    model.compile(optimizer=keras.optimizers.Adam(0.005),
                  loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
                  metrics=["accuracy"])
    return model

# Target groups are new objects with a blue-tinted rendering.
tx_train, ty_train, tg_train = pictures(np.arange(200,224), tint=True)
tx_val, ty_val, tg_val = pictures(np.arange(224,232), tint=True)
tx_test, ty_test, tg_test = pictures(np.arange(232,240), tint=True)

def source_models():
    base = keras.Sequential([
        keras.Input((16,16,3)),
        keras.layers.Conv2D(4,3,padding="same",activation="relu"),
        keras.layers.MaxPooling2D(),
        keras.layers.Flatten()
    ], name="learned_features")
    inputs = keras.Input((16,16,3))
    outputs = keras.layers.Dense(2)(base(inputs))
    source = keras.Model(inputs,outputs)
    source.compile(optimizer=keras.optimizers.Adam(0.005),
        loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
        metrics=["accuracy"])
    return base, source

def target_model(base, rate=0.003):
    inputs = keras.Input((16,16,3))
    outputs = keras.layers.Dense(2)(base(inputs))
    model = keras.Model(inputs,outputs)
    model.compile(optimizer=keras.optimizers.Adam(rate),
        loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
        metrics=["accuracy"])
    return model

Guided task 01

Source and Target Domains

Transfer learning reuses a representation learned from one task when starting a related task. Our source data contain drawn cups and bottles on dark backgrounds. The target data use new group IDs and a blue-tinted rendering of the same broad object categories. This simple shift lets us inspect the complete learning process without downloading a large model or dataset.

The source and target partitions are separated by object identity. Target training groups provide the new supervised examples; target validation groups guide the comparison; target test groups remain reserved. The class order stays cup then bottle in both domains, but the target classifier still receives a newly initialized output head. Reusing an old class head would be a separate design decision requiring compatible label meaning and ordering.

A small locally trained source network is genuinely pretrained once its weights have been updated from source examples. It is not an ImageNet model and has not seen diverse natural photographs. The experiment demonstrates the transfer procedure rather than promising the broad visual features of a large pretrained system. Inspect the two domains before deciding whether reuse is plausible.

Try it

  1. Run setup and inspect both domains.
  2. Check source and target group separation.
  3. Keep target test arrays unused during development.
Python · run in order
fig, axes = plt.subplots(2,2,figsize=(5,5))
for row, (images,labels,name) in enumerate([(x_train,y_train,"Source"),(tx_train,ty_train,"Target")]):
    for col,index in enumerate([0,2]):
        axes[row,col].imshow(images[index])
        axes[row,col].set_title(name+" "+class_names[labels[index]])
        axes[row,col].axis("off")
fig.tight_layout()

Read the result

The class geometry is related while the color distribution differs. This is a deliberately limited domain shift; successful transfer here would not establish performance on photographs or new object categories.

Guided task 02

Learning the Source Representation

Pretraining is a learning stage, not a special model constructor. The source classifier starts with random parameters, then updates its convolution and output weights to reduce the source classification loss. We copy the feature extractor's initial weights so that a later check can establish whether learning actually changed them.

The feature extractor contains a four-filter convolution, max pooling, and flattening. It maps an RGB image into a 256-element representation. A dense source head converts that representation into two logits. The extractor and source model share the same layer objects, so fitting the source model updates the extractor that will be reused. Creating another random extractor with the same architecture would not preserve this learned information.

Six short epochs keep the demonstration inexpensive. Plot training and source-validation losses to inspect the run. Finite losses and changed weights establish that optimization ran, but neither alone proves that the features are useful. Target validation will provide evidence about reuse. Keep the source validation and target validation roles distinct: one monitors pretraining, while the other measures the new domain.

Try it

  1. Create a source model and save its initial extractor weights.
  2. Train on source data for six epochs.
  3. Verify a nonzero extractor weight change.
Python · run in order
base, source = source_models()
source_before = [w.copy() for w in base.get_weights()]
source_history = source.fit(batches(x_train,y_train,shuffle=True),validation_data=batches(x_val,y_val),epochs=6,shuffle=False,verbose=0)
source_delta = max(float(np.max(np.abs(a-b))) for a,b in zip(source_before,base.get_weights()))
fig, ax = plt.subplots(figsize=(6,3))
ax.plot(source_history.history["loss"],label="Source train")
ax.plot(source_history.history["val_loss"],label="Source validation")
ax.set(xlabel="Epoch index",ylabel="Cross-entropy")
ax.legend()
print("Extractor change:",source_delta)
fig.tight_layout()

Read the result

The plotted losses are measured during source training. The weight-change check distinguishes learned reuse from merely recreating the architecture. Do not describe randomly initialized or unchanged features as pretrained.

Guided task 03

Inspecting Learned Features

The feature extractor can process target pictures before a target head is trained. Its output is a vector of learned activations rather than a class label. Different coordinates describe responses at different pooled locations and channels. Because the extractor ends with flattening, spatial position remains part of the representation.

We compute features for target training images in inference mode, then show the first sixteen coordinates for several examples. This small slice is an inspection tool, not a complete explanation of the network. A dark coordinate may mean the corresponding ReLU response is zero; it does not imply the entire image contains no information. The full representation still has 256 values.

Feature caching can avoid repeating an unchanged extractor when training a new head. However, cached features become stale if extractor weights later change. They also represent the exact preprocessing used when computed. During fine-tuning, run images through the current extractor so gradients can reach its weights; training only on a detached NumPy cache cannot update the image-processing layers. This distinction connects computational efficiency to the chosen training stage.

Try it

  1. Compute target-training feature vectors.
  2. Check their batch and feature dimensions.
  3. Display a small coordinate slice for inspection.
Python · run in order
target_features = base(tx_train,training=False).numpy()
fig, ax = plt.subplots(figsize=(7,3))
image = ax.imshow(target_features[:6,:16],aspect="auto",cmap="viridis")
ax.set(xlabel="Feature coordinate",ylabel="Target example",title="Learned feature slice")
fig.colorbar(image,ax=ax,label="Activation")
fig.tight_layout()

Read the result

The heatmap contains actual activations from the trained source extractor on target images. It does not show class probabilities. Similar rows may reflect related drawings; inspection alone cannot establish whether the representation separates all target cases.

  • Explain when a cached feature array must be recomputed.

Guided task 04

Frozen Feature Transfer

A new output head initially has no knowledge of the target labels. Freezing the pretrained extractor lets that head adapt without simultaneously disturbing the representation it receives. Setting base.trainable=False excludes the extractor variables from gradient updates when the target model is compiled for this stage.

The order matters: change trainability before compiling the model used for training. Compilation establishes the training configuration. We also take a copy of every extractor weight immediately before fitting. After four epochs, an exact array comparison checks that those weights stayed unchanged. The head may change even though the extractor does not.

This model contains no batch-normalization layers, avoiding the additional question of moving statistics in a frozen or inference-mode backbone. Larger pretrained networks may require more careful treatment of stateful layers. The present example focuses on the central distinction between trainable parameters and a fixed feature computation. Monitor target validation loss while the head learns, and keep the target test set out of this stage.

Try it

  1. Freeze the learned extractor before building the target model.
  2. Copy extractor weights and fit the new head.
  3. Compare all extractor arrays after training.
Python · run in order
base.trainable = False
frozen_before = [w.copy() for w in base.get_weights()]
transfer = target_model(base)
head_history = transfer.fit(batches(tx_train,ty_train,shuffle=True),validation_data=batches(tx_val,ty_val),epochs=4,shuffle=False,verbose=0)
frozen_unchanged = all(np.array_equal(a,b) for a,b in zip(frozen_before,base.get_weights()))
frozen_val_logits = transfer(tx_val,training=False).numpy()
fig, ax = plt.subplots(figsize=(6,3))
ax.plot(head_history.history["loss"],label="Target train")
ax.plot(head_history.history["val_loss"],label="Target validation")
ax.set(xlabel="Epoch index",ylabel="Cross-entropy",title="Frozen extractor")
ax.legend()
fig.tight_layout()

Read the result

The target curves measure the new head's learning. The exact frozen-weight check is stronger evidence of freezing than a small visual change in the loss curve. A low loss does not by itself reveal which parameters were updated.

  • Explain why copying weights requires independent arrays.

Guided task 05

Low-rate Fine-tuning

After the target head has adapted, fine-tuning allows the extractor to move slightly toward the target domain. The existing target model already contains the learned source extractor and the trained head. We unfreeze that extractor, then recompile with a new optimizer using a much smaller learning rate.

Recompilation is not optional bookkeeping. The training configuration must reflect the changed trainable variables. A fresh optimizer also avoids carrying incompatible variable tracking from the earlier frozen stage. Here the fine-tuning rate is 0.0001 compared with 0.003 for head training, and the run lasts two epochs. These choices reduce the size of updates; they do not guarantee that validation performance improves.

Copy the extractor weights again immediately before fine-tuning. The largest absolute difference after fitting should now be nonzero, in contrast with the frozen stage. Plot the target validation losses from both stages with the boundary identified. The final point belongs to a different optimizer configuration, so interpret the combined curve as a staged procedure rather than one uninterrupted identical training regime.

Try it

  1. Unfreeze the extractor and copy its current weights.
  2. Recompile transfer with Adam at 0.0001.
  3. Fit two epochs and verify extractor weights update.
Python · run in order
base.trainable = True
fine_before = [w.copy() for w in base.get_weights()]
transfer.compile(optimizer=keras.optimizers.Adam(0.0001),loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),metrics=["accuracy"])
fine_history = transfer.fit(batches(tx_train,ty_train,shuffle=True),validation_data=batches(tx_val,ty_val),epochs=2,shuffle=False,verbose=0)
fine_delta = max(float(np.max(np.abs(a-b))) for a,b in zip(fine_before,base.get_weights()))
fig, ax = plt.subplots(figsize=(6,3))
ax.plot(np.arange(1,5),head_history.history["val_loss"],"o-",label="Frozen")
ax.plot(np.arange(5,7),fine_history.history["val_loss"],"o-",label="Fine-tuned")
ax.set(xlabel="Stage epoch",ylabel="Target validation loss")
ax.legend()
print("Fine-tuning extractor change:",fine_delta)
fig.tight_layout()

Read the result

The extractor-change value should be positive, confirming that fine-tuning reached the reused layers. Compare validation losses without assuming improvement. A smaller learning rate controls update scale but does not make every update useful.

  • Explain why cached NumPy features would prevent this extractor update.

Guided task 06

A Target-only Comparison

Transfer is a hypothesis about useful starting knowledge. A target-only model provides a practical comparison: it learns the same target labels without source pretraining. We use the same small convolutional structure and six target epochs, matching the four head-training plus two fine-tuning epochs used by transfer.

This comparison does not equalize total computational cost. Transfer also spent six source epochs learning its representation. If source weights already existed before a new project, that cost might be shared across tasks; in this local demonstration it is visible and should be acknowledged. Neither counting target epochs nor counting every source epoch alone answers every fairness question.

The bar chart includes the frozen-stage validation prediction snapshot, the fine-tuned model, and the target-only model. All three scores use the same target validation labels. The snapshot is important because fine-tuning modified the shared transfer model; it no longer represents the earlier frozen state. This is a useful reminder that naming a variable twice does not create independent model weights. Preserve predictions or a saved model when comparing a historical stage.

Try it

  1. Train a fresh target-only classifier for six epochs.
  2. Compute all three validation accuracies.
  3. Use the saved frozen-stage logits for its historical score.
Python · run in order
scratch = classifier()
scratch_history = scratch.fit(batches(tx_train,ty_train,shuffle=True),epochs=6,shuffle=False,verbose=0)
fine_val_logits = transfer(tx_val,training=False).numpy()
scratch_val_logits = scratch(tx_val,training=False).numpy()
val_accuracies = np.array([np.mean(np.argmax(v,axis=1)==ty_val) for v in [frozen_val_logits,fine_val_logits,scratch_val_logits]])
fig, ax = plt.subplots(figsize=(6,3))
ax.bar(["Frozen","Fine-tuned","Target-only"],val_accuracies)
ax.set(ylabel="Target validation accuracy",ylim=(0,1.05))
fig.tight_layout()

Read the result

The bars report the measured result of this run. Transfer may help, tie, or lose on these small fixtures. Distinguish the fair use of identical evaluation inputs from the separate question of matching training cost.

Guided task 07

Validation-based Selection

Selection should use a stated development criterion rather than an attractive test score. Compare the final fine-tuned and target-only models by target validation cross-entropy. This criterion considers the scores assigned to correct classes, not only whether the largest score won. A tie chooses transfer because it is listed first.

The historical frozen-stage prediction array remains useful for reporting, but it is not a deployable model snapshot in this lesson. Therefore the selection is explicitly limited to the two currently available models. Choosing a stage that was not saved and then evaluating the latest weights under that stage's name would produce a misleading report.

Inspect the chosen model's validation confusion matrix to see which error directions contribute to the summary. Do not tune architecture or thresholds repeatedly from this tiny matrix while still calling the final validation comparison independent. The purpose here is to complete a small planned workflow: train candidate models, choose using validation, then report on reserved target test groups. Record the selected model name and criterion so the last step can be reproduced.

Try it

  1. Compute validation cross-entropy for the two current models.
  2. Select the smaller loss with transfer winning ties.
  3. Inspect a validation confusion matrix for that choice.
Python · run in order
criterion = keras.losses.SparseCategoricalCrossentropy(from_logits=True)
selection_losses = np.array([float(criterion(ty_val,v)) for v in [fine_val_logits,scratch_val_logits]])
selected_index = int(np.argmin(selection_losses))
selected_model = [transfer,scratch][selected_index]
selected_name = ["fine-tuned transfer","target-only"][selected_index]
val_pred = np.argmax(selected_model(tx_val,training=False).numpy(),axis=1)
val_confusion = np.zeros((2,2),dtype=int)
np.add.at(val_confusion,(ty_val,val_pred),1)
fig, ax = plt.subplots(figsize=(4,3))
ax.imshow(val_confusion,cmap="Blues")
for r in range(2):
    for c in range(2):
        ax.text(c,r,str(val_confusion[r,c]),ha="center",va="center",color="white" if val_confusion[r,c]>val_confusion.max()/2 else "black")
ax.set(xlabel="Predicted class",ylabel="True class",xticks=[0,1],yticks=[0,1])
print(selected_name,selection_losses)
fig.tight_layout()

Read the result

The matrix is still a development measurement. Its total should equal the target validation size. Selection loss and accuracy can rank models differently because cross-entropy also responds to confidence in the correct class.

Guided task 08

Final Transfer Report

The reserved target test set provides the final measurement after selection has finished. Run the selected model in inference mode and compute accuracy without changing the model or the selection rule. A prediction count by true class helps confirm that both target categories are represented in the report.

Save the selected complete model to a new temporary directory. The .keras format stores the model configuration and weights so that a later load can reconstruct the computation. Compare logits before and after loading on the same test inputs. Small floating-point tolerances are appropriate; class labels alone would miss numerical changes that happen not to cross a decision boundary.

A model file does not explain the whole experiment. Record the class order, zero-to-one RGB preprocessing, drawn-data source, and the fact that the feature extractor was learned locally. Also note whether validation selected transfer or target-only. This avoids presenting a target-only winner as evidence of transfer success, or presenting a small procedural source as a large pretrained vision model. The lesson's strongest result is a reproducible process with explicit evidence at each stage.

Try it

  1. Evaluate the validation-selected model once on target test.
  2. Save it to a fresh temporary folder and reload.
  3. Compare pre-save and reloaded logits numerically.
Python · run in order
import tempfile
from pathlib import Path
test_logits = selected_model(tx_test,training=False).numpy()
test_accuracy = np.mean(np.argmax(test_logits,axis=1)==ty_test)
folder = Path(tempfile.mkdtemp(prefix="transfer-lesson-"))
model_path = folder / "selected.keras"
selected_model.save(model_path)
restored = keras.models.load_model(model_path)
restored_logits = restored(tx_test,training=False).numpy()
fig, ax = plt.subplots(figsize=(5,3))
ax.bar(class_names,np.bincount(ty_test,minlength=2))
ax.set(ylabel="Reserved test views",title=selected_name)
print("Test accuracy:",test_accuracy,"saved:",model_path)
fig.tight_layout()

Read the result

The plot documents test class support rather than hiding it behind one accuracy value. The numerical reload check verifies model persistence in this runtime. It does not validate unseen real-world object types or camera conditions.
