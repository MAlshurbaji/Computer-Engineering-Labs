Tensors and Image Arrays

import matplotlib.pyplot as plt
keras.utils.set_random_seed(101)
rng = np.random.default_rng(101)

# These original 24-pixel drawings are teaching fixtures, not photographs.
cup = np.full((24, 24, 3), 245, dtype=np.uint8)
cup[8:20, 5:15] = [40, 110, 190]
cup[9:17, 15:20] = [40, 110, 190]
cup[11:15, 15:18] = [245, 245, 245]

book[4:21, 5:20] = [180, 60, 70]
book[5:20, 8:19] = [235, 220, 180]
book[7:8, 10:17] = [80, 80, 80]

bottle[3:7, 10:14] = [65, 90, 80]

Guided task 01

Rank, shape and named axes

A tensor is a collection of values with a consistent numeric type and a stated arrangement of axes. A single shelf count has no axis, three counts form a vector, and rows of daily counts form a matrix. Rank counts axes; shape gives the length of each axis. Neither word tells you what the numbers mean, so keep units and axis labels beside the data. A shape of three by two could describe three objects over two days or three days for two objects. The program cannot choose that meaning for you.

Here each row represents one day and each column represents one kind of desk object. Reducing the day axis answers a question about objects across days. Reducing the object axis instead answers a question about the total on each day. Before using an axis number, say which labels will disappear and which will remain. The chart deliberately retains object names, connecting a tensor calculation with an understandable result. These counts are invented examples, and no learning occurs yet. The purpose is to establish a reliable description that later model code can use.

Try it

  1. Create the two-day count matrix and inspect its shape and rank.
  2. Add across days while retaining one value per object.
  3. Compare the labelled chart with the original rows.
Python · run in order
counts = tf.constant([[2, 4, 1], [3, 2, 2]], dtype=tf.float32)
totals = tf.reduce_sum(counts, axis=0)
print("shape:", counts.shape, "rank:", tf.rank(counts).numpy())
fig, ax = plt.subplots(figsize=(6, 3))
ax.bar(icon_names, totals.numpy())
ax.set(ylabel="Objects across two days", title="Invented desk inventory")
fig.tight_layout()

Read the result

Read each bar as a column total, not as a daily total. The printed rank is two even though the matrix contains six numbers; rank describes the arrangement rather than the amount of data.

Change and compare

  • Reduce axis 1 and relabel the chart with the two days.
  • Add a third day and predict which dimension changes before running it.

Guided task 02

Image dtype and numeric range

An image array stores numbers; the display interprets those numbers according to its format. The supplied drawings use unsigned bytes, so each red, green or blue channel is an integer between zero and 255. Most of this course uses float32 RGB values between zero and one. Casting changes the numeric type, while dividing by 255 changes the scale. These are separate operations. A cast alone would leave a channel value of 245 as 245.0, which is outside the intended floating-point display range.

Convert once at the boundary between the original data and your calculation. Repeating the division would make an already normalized drawing almost black, while forgetting it can cause display clipping. Keep the raw array available so that you can compare representations without trying to reconstruct discarded information. The picture should look the same after a correct conversion even though the dtype and numeric range differ. A visually plausible picture alone is insufficient: inspecting the minimum, maximum and a known pixel can catch mistakes that a display automatically hides. This small check becomes especially useful when different image loaders follow different conventions.

Try it

  1. Convert the cup drawing to float32 and divide by 255 once.
  2. Print the dtype and observed range.
  3. Display the byte and floating-point versions side by side.
Python · run in order
raw = icons_u8[0]
image = tf.cast(raw, tf.float32) / 255.0
print(image.dtype, float(tf.reduce_min(image)), float(tf.reduce_max(image)))
fig, axes = plt.subplots(1, 2, figsize=(7, 3))
axes[0].imshow(raw)
axes[0].set_title("uint8: 0 to 255")
axes[1].imshow(image.numpy())
axes[1].set_title("float32: 0 to 1")
for ax in axes:
    ax.set_axis_off()
fig.tight_layout()

Read the result

The two panels should represent the same drawing. Inspect the printed range as well: this fixture does not need to contain a pure-black or pure-white pixel to follow the declared [0, 1] convention.

Change and compare

  • Inspect the RGB values at row 8, column 5 in both representations.
  • Try division twice in a separate variable and explain the darker result.

Guided task 03

RGB channel selection

A colour pixel contains three channel values in the declared order red, green, blue. The final axis holds those values; it is not another spatial direction. Selecting one channel produces a two-dimensional array of intensities. Showing that array with a grey colour map answers how strong that channel is at each location, rather than reconstructing the original colour picture. A blue object can therefore appear brighter in the blue-channel panel than in the red-channel panel.

Use the same display limits for every channel panel. Otherwise each panel may be stretched independently, making a weak channel look as strong as a large one. The comparison is about numeric intensity, so zero and one need the same visual meaning everywhere. Row and column positions still identify the same locations after channel selection. This gives you a simple debugging tool: a misplaced axis selection changes the panel shape or extracts a strip instead of a channel. Channel views are not learned features; they are direct pieces of the input representation. Later filters will combine or transform these inputs, but this first inspection requires no model.

Try it

  1. Normalize the bottle drawing and select each final-axis channel.
  2. Plot the three channels with shared zero-to-one limits.
  3. Compare a bottle-body pixel across the three channel arrays.
Python · run in order
image = tf.cast(icons_u8[2], tf.float32) / 255.0
channels = [image[:, :, i] for i in range(3)]
fig, axes = plt.subplots(1, 3, figsize=(9, 3))
for ax, channel, name in zip(axes, channels, ["Red", "Green", "Blue"]):
    ax.imshow(channel.numpy(), cmap="gray", vmin=0, vmax=1)
    ax.set_title(name + " intensity")
    ax.set_axis_off()
fig.tight_layout()
print("Body RGB:", image[10, 10].numpy())

Read the result

Compare corresponding pixels, not just the overall brightness of each panel. The bottle body has a larger green value than red or blue, while the pale background has equal values in all three channels.

Change and compare

  • Display the cup's channels using the same fixed limits.
  • Select image[10, :, :] and explain why it is a row of RGB pixels rather than a channel image.

Guided task 04

NHWC batches

A model normally receives a collection of examples rather than one unlabelled image array. In this course an image batch follows NHWC: number of examples, height, width and channels. Stacking three equally shaped RGB drawings adds an example axis in front, producing three by twenty-four by twenty-four by three. Stacking differs from joining drawings along their width: the latter would make a wider single image rather than more examples.

The batch axis preserves the order of the examples. Names or labels must follow that same order, even when the displayed pictures look easy to recognize. A selection that reorders images without reordering associated labels silently changes the training problem. For a single new image, adding a length-one example axis preserves the four-axis convention; it does not create a second copy of the content. Checking the batch shape before a model call makes errors easier to locate than waiting for a later layer failure. This task displays all three batch members and prints the single-image batch shape, making the numerical arrangement visible without assuming that an extra axis changes the drawing itself.

Try it

  1. Create the normalized three-example tensor from the stored drawings.
  2. Add a batch axis to one selected image using tf.newaxis.
  3. Display batch members in their existing order.
Python · run in order
batch = tf.cast(icons_u8, tf.float32) / 255.0
one_example = batch[1][tf.newaxis, ...]
print("Batch:", batch.shape, "single-image batch:", one_example.shape)
fig, axes = plt.subplots(1, 3, figsize=(8, 3))
for i, ax in enumerate(axes):
    ax.imshow(batch[i].numpy())
    ax.set_title(f"{i}: {icon_names[i]}")
    ax.set_axis_off()
fig.tight_layout()

Read the result

The example axis has length three in the full batch and length one in the single-image batch. The height, width and RGB channel dimensions remain unchanged, and the name above each panel follows its batch position.

Change and compare

  • Select batch indices [2, 0] and keep the corresponding names in the same order.
  • Compare adding an axis with duplicating an image using tf.stack.

Guided task 05

Spatial slicing and crops

Cropping selects a rectangular part of a drawing without inventing new pixels. A Python slice includes its start and excludes its stop, so rows four through nineteen require the slice 4:20. Apply the row and column selections to the spatial axes, then retain the channel axis. The crop has its own coordinate origin: its top-left pixel corresponds to the chosen starting location in the full image.

An image can remain a valid RGB array while losing the part you wanted to examine. Shape checks establish the crop size, but a visual comparison establishes whether the coordinates match the intended object. A reversed assumption about row and column order is especially easy to miss in a square image. Use a non-square crop here so that its sixteen-row, seventeen-column shape provides another clue. Cropping is different from resizing: it removes content outside a region instead of changing the sampling grid of the whole picture. Keeping the original drawing alongside the crop helps you explain which information was retained. When later choosing crops for learning, the same crop rule must have a clear purpose rather than accidentally removing the relevant object.

Try it

  1. Select cup rows 4:20 and columns 3:20, keeping all channels.
  2. Inspect the crop's shape and its first pixel.
  3. Display the source and crop without stretching their numeric ranges.
Python · run in order
image = tf.cast(icons_u8[0], tf.float32) / 255.0
crop = image[4:20, 3:20, :]
fig, axes = plt.subplots(1, 2, figsize=(7, 3))
axes[0].imshow(image.numpy())
axes[0].set_title("Full drawing")
axes[1].imshow(crop.numpy())
axes[1].set_title("Rows 4:20, columns 3:20")
for ax in axes:
    ax.set_xlabel("Column")
    ax.set_ylabel("Row")
fig.tight_layout()
print("Crop shape:", crop.shape)

Read the result

The crop contains sixteen rows and seventeen columns. Its coordinates begin at zero in the new display; crop[0, 0] refers to image[4, 3], so a crop changes the coordinate reference as well as the visible region.

Change and compare

  • Move only the starting column and keep the crop width fixed.
  • Make a crop that excludes the cup handle and describe the information lost.

Guided task 06

Broadcasting per-channel adjustments

Broadcasting applies a smaller compatible array across repeated positions of a larger one. A three-element vector can describe one multiplier for each RGB channel. When multiplied by an HWC image, that vector aligns with the final axis and repeats across rows and columns. This gives a consistent colour adjustment without writing a separate loop for every pixel.

The alignment is a shape rule, not an understanding of colour. A vector with the wrong length or an incorrectly placed axis may fail or act along a different dimension. Write the intended axis meaning before choosing the shape. Multiplication may also create values outside the declared image range, so this example clips adjusted results to zero through one. Clipping protects the display convention but discards any excess above one; it is not a reversible edit. Keep the source unchanged and inspect both the gains and output range. We use this operation to understand array arithmetic, not to claim a realistic camera correction. The same broadcast pattern later appears when preprocessing a whole batch or subtracting one learned value per feature.

Try it

  1. Apply gains [1.2, 0.7, 0.9] to the RGB channels.
  2. Clip the result to [0, 1] while preserving the source.
  3. Compare the two images and inspect one adjusted pixel.
Python · run in order
image = tf.cast(icons_u8[1], tf.float32) / 255.0
gains = tf.constant([1.2, 0.7, 0.9], dtype=tf.float32)
adjusted = tf.clip_by_value(image * gains, 0.0, 1.0)
fig, axes = plt.subplots(1, 2, figsize=(7, 3))
for ax, picture, title in zip(axes, [image, adjusted], ["Original", "Per-channel gains"]):
    ax.imshow(picture.numpy())
    ax.set_title(title)
    ax.set_axis_off()
fig.tight_layout()
print("Adjusted range:", float(tf.reduce_min(adjusted)), float(tf.reduce_max(adjusted)))

Read the result

The gains change every pixel using the same channel rule, including the background. A red value that exceeds one after multiplication is clipped, so dividing the adjusted picture by the gains would not perfectly recover the original.

Change and compare

  • Use equal gains for all channels and compare brightness with colour balance.
  • Count how many values would exceed one before clipping.

Guided task 07

Reduction axes and image summaries

A reduction turns many values into a smaller summary. Averaging the height and width axes of an NHWC batch produces one RGB mean per example. The example axis and channel axis remain, giving a three-by-three table for these drawings. Averaging all axes instead would return only one scalar, losing both object identity and colour differences.

A mean is a compact description, not a complete image. Rearranging the same pixels can preserve every channel mean while changing the shape of the object. Background size also influences the summary: these pale backgrounds occupy many pixels and can dominate the average. The bar chart therefore describes these exact drawings, not an intrinsic colour of every cup, book or bottle. Use such summaries to inspect data and detect obvious differences, while remembering what spatial information has been discarded. The explicit axis tuple (1, 2) documents the intended calculation. Checking the output shape tells you whether the example and channel identities survived, and comparing a known mean with a direct NumPy calculation offers an independent arithmetic check.

Try it

  1. Average only the two spatial axes of the normalized batch.
  2. Print the resulting per-example RGB table.
  3. Plot one grouped bar for each object-channel combination.
Python · run in order
batch = tf.cast(icons_u8, tf.float32) / 255.0
means = tf.reduce_mean(batch, axis=(1, 2))
fig, ax = plt.subplots(figsize=(7, 3))
locations = np.arange(3)
for channel, name in enumerate(["Red", "Green", "Blue"]):
    ax.bar(locations + (channel-1)*0.24, means[:, channel].numpy(), width=0.24, label=name)
ax.set_xticks(locations, icon_names)
ax.set(ylabel="Mean channel value", ylim=(0, 1), title="Spatial means of drawn examples")
ax.legend()
fig.tight_layout()
print(means.numpy())

Read the result

Each group keeps the identity of one drawing, while each bar keeps one channel identity. Compare the pale background with the object area when explaining why a visually colourful object can still have three relatively large means.

Change and compare

  • Average only the channel axis and inspect the resulting shape.
  • Reorder image rows and confirm that the spatial channel means remain unchanged.

Guided task 08

Reshape versus transpose

Reshape changes how an ordered sequence of values is grouped into dimensions. It does not exchange the meanings of the row and column axes. Transpose explicitly reorders axes, so a pixel at row r, column c moves to row c, column r when height and width are exchanged. Both operations can produce the same target shape while placing individual pixels differently.

This example uses a sixteen-by-twenty-four region so the new shape is visibly different. We compare a true spatial transpose with a reshape to twenty-four by sixteen. The reshape preserves the flattened sequence but cuts it into rows of a different length, disrupting the drawing. By contrast, flattening and then restoring the original shape can recover the exact array because both operations agree about the value order. That round trip is useful when checking a representation change, but it does not prove that arbitrary reshaping preserves image geometry. Later dense layers often consume flattened features, whereas convolutional layers need meaningful spatial axes. Choose the transformation according to the next computation's contract and verify a pixel relationship, rather than accepting a matching shape as sufficient evidence.

Try it

  1. Take the first sixteen rows of the book drawing.
  2. Compare transpose with reshape to the same target dimensions.
  3. Flatten and restore the original region, then check exact equality.
Python · run in order
region = tf.cast(icons_u8[1, :16], tf.float32) / 255.0
transposed = tf.transpose(region, perm=(1, 0, 2))
regrouped = tf.reshape(region, (24, 16, 3))
flat = tf.reshape(region, (-1,))
restored = tf.reshape(flat, region.shape)
fig, axes = plt.subplots(1, 3, figsize=(9, 3))
for ax, picture, title in zip(axes, [region, transposed, regrouped], ["Original region", "Transpose spatial axes", "Reshape same values"]):
    ax.imshow(picture.numpy())
    ax.set_title(title)
    ax.set_axis_off()
fig.tight_layout()
print("Round trip equal:", bool(tf.reduce_all(restored == region)))

Read the result

The middle and right panels have the same shape but generally different pixel layouts. The flatten-and-restore check concerns a separate round trip back to the original shape; it does not make the spatial reshape equivalent to transpose.

Change and compare

  • Check that transposed[5, 7] equals region[7, 5].
  • Choose another non-square region and predict its transposed shape.
