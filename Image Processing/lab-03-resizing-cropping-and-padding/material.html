Resizing, Cropping and Padding

MaterialPracticeQuiz

Make images fit a destination without losing track of what changed. Use the book, mug and fine ruler marks to compare sampling choices and coordinate rules.

Guided task 01

Size ordering and aspect ratio

An RGB array stores height, width and channels in that order. OpenCV's resize destination instead takes width followed by height. Naming both quantities makes the boundary visible and prevents a transposed destination from slipping through a shape check that only counts elements. The original desk is wider than it is tall, with a width-to-height ratio of 1.5.

Compare a proportional reduction to 144 by 96 with a direct resize to a 128 by 128 square. Both are valid arrays, but the square changes horizontal and vertical scales differently. The mug's shape and the notebook label provide recognizable reference objects for judging the distortion. Resizing preserves the whole field of view while changing sampling and, when scales differ, shape. It does not select a region as cropping does. A square destination requirement alone does not establish that stretching is appropriate; later activities compare alternatives. Record the resize policy alongside dimensions so another person can reproduce the same representation instead of guessing how a square was obtained.

Try it

  1. Resize to width 144 and height 96 using area interpolation.
  2. Resize the original directly to a 128-pixel square.
  3. Compare object proportions and verify output shapes.
Python · run in order
proportional = cv2.resize(rgb,(144,96),interpolation=cv2.INTER_AREA)
stretched = cv2.resize(rgb,(128,128),interpolation=cv2.INTER_AREA)
fig, axes = plt.subplots(1,3,figsize=(11,3.4))
for ax,image,title in zip(axes,[rgb,proportional,stretched],["192 wide x 128 high","144 wide x 96 high","128 square: stretched"]):
    ax.imshow(image)
    ax.set_title(title)
    ax.axis("off")
fig.tight_layout()

Read the result

The proportional result retains the original shape ratio. The square retains every region but compresses horizontal distances relative to vertical distances.

Guided task 02

Enlargement interpolation

An enlarged image needs values at more sample locations than its source contains. Nearest-neighbor interpolation selects existing samples, producing blocks when the source is small. Bilinear interpolation combines nearby samples and can make transitions smoother. Neither method has access to text strokes or fine detail that disappeared during an earlier reduction.

First reduce the desk to 96 by 64 with area interpolation. Then enlarge that same small image back to the original dimensions with nearest and linear interpolation. Compare both with the original, especially the reading label and ruler marks. The restored dimensions should not be mistaken for restored information. We use identical small input for both enlargements so the observed difference belongs to the enlargement policy. Matplotlib's display interpolation is explicitly nearest in these panels; this avoids adding another smooth display layer that could hide the stored pixel blocks. Choose an interpolation policy based on the kind of data and the intended use, then inspect the result at a scale where the changes are visible. Smoother appearance alone is not proof that the original scene has been recovered.

Try it

  1. Create one shared half-size source.
  2. Enlarge it with nearest and linear interpolation.
  3. Compare original and reconstructed detail without extra display smoothing.
Python · run in order
small = cv2.resize(rgb,(96,64),interpolation=cv2.INTER_AREA)
nearest_large = cv2.resize(small,(w,h),interpolation=cv2.INTER_NEAREST)
linear_large = cv2.resize(small,(w,h),interpolation=cv2.INTER_LINEAR)
fig, axes = plt.subplots(1,3,figsize=(11,3.4))
for ax,image,title in zip(axes,[rgb,nearest_large,linear_large],["Original detail","Nearest enlargement","Linear enlargement"]):
    ax.imshow(image,interpolation="nearest")
    ax.set_title(title)
    ax.axis("off")
fig.tight_layout()

Read the result

The two enlarged images have the original shape but were both reconstructed from fewer samples. Inspect text and thin marks rather than assuming that a smoother panel contains more recovered detail.

Guided task 03

Shrinking and aliasing

Fine repeated patterns can be misrepresented when too few samples remain. Selecting every fourth column of alternating black and white stripes can repeatedly choose the same colour, even though the original stripe band contains both equally. This is a simple aliasing example: the reduced samples suggest a pattern that does not describe the source's local mixture.

Add a narrow striped band to the desk drawing and shrink the image to 48 by 32. Compare nearest-neighbor sampling with area interpolation. In this exact four-to-one reduction, the area route combines a block containing both stripe colours, while nearest chooses a single source sample. Real scenes can have less regular textures, so this controlled example explains a mechanism rather than guaranteeing that one method always looks best. Downsampling can remove details that are genuinely important, including narrow lettering. Prefer a deliberate filtering and sampling policy for image reduction, and inspect representative fine structures. The source stays available so that a destination too small for the task can be reconsidered rather than treated as an unavoidable preprocessing requirement.

Try it

  1. Add a 24-row alternating one-pixel stripe band.
  2. Shrink by four on both axes with nearest and area interpolation.
  3. Inspect the band and its actual output values.
Python · run in order
striped = rgb.copy()
stripe_row = ((np.arange(w)%2)*255).astype(np.uint8)
striped[88:112] = stripe_row[None,:,None]
nearest_small = cv2.resize(striped,(48,32),interpolation=cv2.INTER_NEAREST)
area_small = cv2.resize(striped,(48,32),interpolation=cv2.INTER_AREA)
fig, axes = plt.subplots(1,3,figsize=(11,3.4))
for ax,image,title in zip(axes,[striped,nearest_small,area_small],["One-pixel stripe band","Nearest reduction","Area reduction"]):
    ax.imshow(image,interpolation="nearest")
    ax.set_title(title)
    ax.axis("off")
fig.tight_layout()
print("Nearest band codes:",np.unique(nearest_small[22:28]))
print("Area band codes:",np.unique(area_small[22:28]))

Read the result

The controlled stripe band can collapse to one selected colour under nearest sampling. Area interpolation summarizes the mixture, but the original individual stripes are no longer resolvable.

  • Choose a larger destination and compare the smallest text that remains readable.

Guided task 04

Categorical masks and nearest sampling

A category mask is an image-shaped array whose values name classes rather than brightness. In our illustrative annotation, zero means desk, one means book and seven means mug. The gap between the numbers has no visual or numerical meaning. Averaging one and seven does not describe a partly valid new category four.

Create a simple mask over the known drawn shapes and resize it to 151 by 101 with nearest interpolation. Also show a deliberately incorrect linear resize to expose invented codes near boundaries. Use a fixed colour scale for both masks and print the sets of stored values. The mask geometry is deliberately approximate; it demonstrates representation and alignment rather than a finished segmentation dataset. Continuous RGB images can use interpolation that blends colours, while their categorical masks need a label-preserving policy using the same destination geometry. Preserving the set of allowed labels is necessary but not sufficient for perfect alignment: coordinate conventions and sampled geometry must also agree. Later labs examine those annotation details more fully. Never repair invented category numbers merely by calling them new legitimate classes.

Try it

  1. Construct an illustrative desk/book/mug mask.
  2. Resize the mask with nearest and, as a failure example, linear interpolation.
  3. Compare the unique stored codes and boundary appearance.
Python · run in order
labels = np.zeros((h,w),dtype=np.uint8)
labels[20:109,12:81] = 1
labels[((xx-143)/32)**2+((yy-82)/33)**2<=1] = 7
nearest_labels = cv2.resize(labels,(151,101),interpolation=cv2.INTER_NEAREST)
linear_labels = cv2.resize(labels,(151,101),interpolation=cv2.INTER_LINEAR)

for ax in axes:
    ax.axis("off")

Guided task 05

Crop selection and reproducibility

Cropping selects a smaller field of view without resampling the retained pixels. A center crop follows a fixed geometric rule, while a sampled crop chooses its origin from a defined set of allowed positions. Neither promises that every important object remains present. A mug near the right edge can be partly removed even when the output dimensions are exactly correct.

Use a 128-wide by 96-high crop. Compute the center origin by integer division, with any odd extra source pixel left on the right or bottom. Then sample one valid origin using a local generator with a fixed seed. NumPy's upper integer bound is exclusive, so add one when the last valid origin should be eligible. Record the sampled origin, because replaying the geometry is more explicit than relying on whatever random calls happened earlier in a notebook. Display crop rectangles on the full scene and both extracted arrays. A reproducible crop is useful for debugging; a deterministic evaluation policy should be specified separately from any later training augmentation policy. Do not infer suitability from randomness alone.

Try it

  1. Calculate the center crop origin.
  2. Sample one valid origin with local seed 203 and retain its coordinates.
  3. Draw both windows and inspect which objects each crop retains.
Python · run in order
crop_w, crop_h = 128,96
center_x, center_y = (w-crop_w)//2,(h-crop_h)//2
crop_rng = np.random.default_rng(203)
sample_x = int(crop_rng.integers(0,w-crop_w+1))
sample_y = int(crop_rng.integers(0,h-crop_h+1))
center_crop = rgb[center_y:center_y+crop_h,center_x:center_x+crop_w].copy()
sample_crop = rgb[sample_y:sample_y+crop_h,sample_x:sample_x+crop_w].copy()
fig, axes = plt.subplots(1,3,figsize=(11,3.4))
axes[0].imshow(rgb)
axes[0].add_patch(plt.Rectangle((center_x-0.5,center_y-0.5),crop_w,crop_h,fill=False,edgecolor="cyan",linewidth=2))
axes[0].add_patch(plt.Rectangle((sample_x-0.5,sample_y-0.5),crop_w,crop_h,fill=False,edgecolor="yellow",linewidth=2))
axes[0].set_title("Cyan center; yellow sampled")
axes[1].imshow(center_crop)
axes[1].set_title("Center crop")
axes[2].imshow(sample_crop)
axes[2].set_title(f"Sampled origin ({sample_x},{sample_y})")
for ax in axes:
    ax.axis("off")
fig.tight_layout()

Read the result

Both crops have equal dimensions but may retain different evidence. The recorded origin describes the actual sampled window, including which objects were cut at its boundary.

Guided task 06

Letterboxing and rounded dimensions

Letterboxing fits the whole image inside a destination and fills the remaining canvas with a declared padding colour. It avoids the large shape distortion of a direct square stretch and the content removal of a crop. The padding is newly introduced data, so its colour and location belong in the processing record.

For a 160-pixel square, choose the smaller destination-to-source ratio and round the resulting width and height. The desk becomes 160 by 107, leaving 53 padding rows. Put 26 above and 27 below by assigning the integer half to the top. The nominal ratio is useful for selecting dimensions, but the actual horizontal and vertical scales are 160/192 and 107/128. They differ slightly because a discrete grid needs integer sizes. Use those actual ratios when mapping coordinates, rather than carrying one ideal floating ratio through later annotation code. Save both resized dimensions and offsets with the result. A padded region does not represent observed desk content, and a future mask would need an explicit padding policy rather than silently assigning a real class to every new pixel.

Try it

  1. Calculate the fitted integer dimensions.
  2. Center the resized image on a 160-square dark canvas.
  3. Record actual x/y scales and top/left offsets.
Python · run in order
target_w, target_h = 160,160
fit_ratio = min(target_w/w,target_h/h)
new_w, new_h = round(w*fit_ratio),round(h*fit_ratio)
resized = cv2.resize(rgb,(new_w,new_h),interpolation=cv2.INTER_AREA)
left, top = (target_w-new_w)//2,(target_h-new_h)//2
letterboxed = np.full((target_h,target_w,3),(35,45,55),dtype=np.uint8)
letterboxed[top:top+new_h,left:left+new_w] = resized
scale_x, scale_y = new_w/w,new_h/h
fig, axes = plt.subplots(1,3,figsize=(11,3.6))
for ax,image,title in zip(axes,[rgb,cv2.resize(rgb,(160,160),interpolation=cv2.INTER_AREA),letterboxed],["Source","Direct square stretch","Fit plus padding"]):
    ax.imshow(image)
    ax.set_title(title)
    ax.axis("off")
fig.tight_layout()
print("Resized W,H:",new_w,new_h,"Offsets:",left,top,"Actual scales:",scale_x,scale_y)

Read the result

The letterbox keeps the field of view with only the small discretization difference caused by rounding. Its dark strips are explicit padding, not a dark region in the original drawing.

  • Check that top plus resized height plus bottom equals destination height.

Guided task 07

Pixel centers and pixel edges

Coordinate conventions must be stated before transforming annotations. In a discrete pixel-center convention, the first pixel center has coordinate zero. In a continuous pixel-edge convention, the image extends from zero to its width and height, and that same first pixel center is at one-half. A rectangle expressed by outer edges therefore follows a different formula from an integer-indexed keypoint.

Resize to 150 by 100. Edge coordinates scale directly by the realized axis ratios. For the center-coordinate convention used with linear resize, map a point by (coordinate + 0.5) times scale minus 0.5. The half-pixel terms convert to and from the edge-based coordinate system. Our plot uses Matplotlib's default integer-centered image axes, so an edge rectangle is drawn after subtracting 0.5 from its top-left coordinates. The point is already in that plot's center convention. These details matter even when an offset is visually small. They explain why blindly multiplying every kind of annotation by the same formula can create systematic drift. Keep the convention attached to coordinates instead of treating all x and y pairs as interchangeable.

Try it

  1. Define one keypoint using integer pixel-center coordinates and a book rectangle using pixel edges.
  2. Transform each using its stated convention.
  3. Overlay the mapped point and rectangle on the resized image.
Python · run in order
new_w, new_h = 150,100
resized = cv2.resize(rgb,(new_w,new_h),interpolation=cv2.INTER_LINEAR)
scales = np.array([new_w/w,new_h/h])

point_resized = (point+0.5)*scales-0.5
box_edges = np.array([12.0,20.0,81.0,109.0])

fig, axes = plt.subplots(1,2,figsize=(9,3.8))

    ax.scatter([p[0]],[p[1]],c="cyan",s=55,marker="+")
    ax.add_patch(plt.Rectangle((b[0]-0.5,b[1]-0.5),b[2]-b[0],b[3]-b[1],fill=False,edgecolor="yellow",linewidth=2))
    ax.set_title(title)
    ax.axis("off")
fig.tight_layout()
print("Point:",point_resized,"Edge rectangle:",box_resized)

Read the result

The rectangle describes outer boundaries, while the cyan marker describes a pixel-center location. The plotting conversion and resizing conversion both follow their declared conventions.

Guided task 08

Crops that extend outside an image

A requested window may extend beyond a source boundary, especially when keeping a fixed-size view around an object. Negative NumPy indices count from the end of an array; they do not automatically mean missing space that should be padded. An explicit intersection calculation avoids that accidental wraparound interpretation.

Define the requested window by integer outer edges: x from -12 to 88 and y from 12 to 128. Allocate its full 100 by 116 output, fill it with a stated colour and copy only the intersection with the source. A separate Boolean coverage array identifies pixels copied from the source. It records provenance, not an object category. The helper rejects nonpositive windows and windows with no overlap, so an entirely artificial image cannot silently pass as a successful crop. This policy is one deliberate choice; another application could choose to return a fully padded window, but it would need to state that behavior. Inspect both the crop and coverage, and preserve the window metadata so source coordinates can be recovered by adding the original origin.

Try it

  1. Validate the requested edge coordinates and compute their overlap with the source.
  2. Copy the valid intersection into the padded destination.
  3. Display the crop with a separate source-coverage map.
Python · run in order
def crop_with_padding(image,window,fill):
    x0,y0,x1,y1 = window
    if x1<=x0 or y1<=y0:
        raise ValueError("Window must have positive width and height")
    source_h,source_w = image.shape[:2]
    a,b,c,d = max(0,x0),max(0,y0),min(source_w,x1),min(source_h,y1)
    if a>=c or b>=d:
        raise ValueError("Window must overlap the source")
    output = np.full((y1-y0,x1-x0,3),fill,dtype=image.dtype)
    coverage = np.zeros((y1-y0,x1-x0),dtype=bool)
    output[b-y0:d-y0,a-x0:c-x0] = image[b:d,a:c]
    coverage[b-y0:d-y0,a-x0:c-x0] = True
    return output,coverage
window = (-12,12,88,128)
padded_crop,coverage = crop_with_padding(rgb,window,(35,45,55))
fig, axes = plt.subplots(1,3,figsize=(10,3.8))
axes[0].imshow(rgb)
axes[0].set_title("Source")
axes[1].imshow(padded_crop)
axes[1].set_title("Requested window with padding")
axes[2].imshow(coverage,cmap="gray",vmin=0,vmax=1)
axes[2].set_title("White = copied source")
for ax in axes:
    ax.axis("off")
fig.tight_layout()

Read the result

The left strip is padding, while the coverage map shows exactly which output positions came from the original. A plausible colour alone would not identify that distinction.
