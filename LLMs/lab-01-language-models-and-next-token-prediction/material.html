Language Models and Next-Token Prediction

MaterialPracticeQuiz

Start with a familiar message and make its next-token prediction task visible. Use small inspectable examples to separate generation mechanics from claims about language understanding.

What you will learn

  • Interpret a distribution over possible continuations.
  • Trace an autoregressive prediction-and-append loop.
  • Separate output format, supporting evidence and model capability.

import re
from collections import Counter, defaultdict
import numpy as np
import torch
import matplotlib.pyplot as plt
torch.set_num_threads(1)
torch.manual_seed(101)
rng = np.random.default_rng(101)
# Whitespace units are deliberately simple stand-ins for later tokenizer tokens.
messages = [
    "please return the key today .",
    "please return the key safely .",
    "please return the key soon .",
    "please return the book today .",
    "please collect the key today .",
    "please collect the key soon .",
    "please collect the parcel today .",
    "the room is ready ."
]
token_sequences = [message.split() for message in messages]

Guided task 01

The next-token task

A language model assigns a distribution to the next token given a preceding sequence. A token is a unit chosen by a tokenizer; it is not always an entire word. For this first lesson, whitespace-separated pieces are convenient visible stand-ins. Later labs replace that simplification with explicit tokenization and vocabulary rules. The period is separated by spaces so it becomes its own unit in these examples.

Take a short equipment-return message and expose the prediction opportunities along it. At each position, the available context ends immediately before the target. The target is supplied by the existing training example; it is not a separate human judgment about whether that token is the only sensible continuation. A natural message can have several plausible next words, yet a recorded example contains one observed continuation. Plot the context length at each target position and label the targets. This makes the directional task concrete without requiring a neural network. The plot describes this one constructed message, not the capacity or performance of a large language model.

Try it

  1. Split one stated message into visible units.
  2. Pair each nonempty prefix with the immediately following unit.
  3. Plot prefix lengths and label the observed targets.
Python · run in order
units = "please bring the charger tomorrow .".split()
prefixes = [units[:position] for position in range(1,len(units))]
targets = [units[position] for position in range(1,len(units))]
lengths = [len(prefix) for prefix in prefixes]
fig, ax = plt.subplots(figsize=(9,3.5))
ax.bar(np.arange(len(targets)),lengths,color="#327e9b")
ax.set_xticks(np.arange(len(targets)),targets)
ax.set(xlabel="Observed next unit",ylabel="Available context units",title="One message supplies several prediction opportunities")
fig.tight_layout()

Read the result

The context grows by one unit at each position, while the target is always just beyond its right edge. No later unit belongs in that position's available prefix.

Change and compare

  • Write the prefix and target for the word charger.
  • Replace tomorrow with tonight and identify which recorded target changes.

Guided task 02

Context changes the question

The next token depends on what came before it. Counting successors in a tiny collection gives a transparent first illustration. Compare the two-unit contexts return the and collect the. The same candidate word may appear after either context, but their observed successor counts need not match. A language model is therefore more than a global list of common words.

Scan each message separately, matching adjacent context units without crossing document boundaries. Count the unit immediately after each match and build a small context-by-candidate matrix. Repeated words elsewhere do not count unless they occupy that exact successor position. This is an empirical count table over eight constructed messages, not an LLM and not an estimate of all ordinary language. It cannot share knowledge between similar unseen contexts the way a trained neural model may. Its advantage here is inspectability: every cell can be traced to a source message. When interpreting the table, distinguish absence from this collection from impossibility in the world. The collection's limited wording determines what the table can show.

Try it

  1. Count successors of two specified adjacent-unit contexts.
  2. Keep message boundaries intact while scanning.
  3. Compare the resulting context-specific counts.
Python · run in order
contexts = [("return","the"),("collect","the")]
candidates = ["book","key","parcel"]
context_counts = []
for context in contexts:
    counts = Counter()
    for sequence in token_sequences:
        for position in range(len(sequence)-2):
            if tuple(sequence[position:position+2])==context:
                counts[sequence[position+2]] += 1
    context_counts.append(counts)
table = np.array([[counts[word] for word in candidates] for counts in context_counts])
fig, ax = plt.subplots(figsize=(7,3.4))
im = ax.imshow(table,cmap="Blues",vmin=0,vmax=max(1,int(table.max())))
ax.set_xticks(np.arange(3),candidates)
ax.set_yticks(np.arange(2),["return the","collect the"])
for row in range(2):
    for column in range(3):
        ax.text(column,row,str(table[row,column]),ha="center",va="center")
ax.set(xlabel="Observed successor",ylabel="Two-unit context",title="Counts conditioned on a specific prefix")
fig.colorbar(im,ax=ax,label="Occurrences")
fig.tight_layout()

Read the result

A candidate's global frequency would combine situations that this table keeps separate. Each row answers a particular conditional question rather than defining a permanent property of that candidate word.

Change and compare

  • Manually locate every message contributing to the collect the row.
  • Add one new message and predict which single cell it changes.

Guided task 03

A conditional probability distribution

Counts can be normalized into an empirical next-unit distribution. For return the, the observed candidates have counts one, three and zero in the order book, key and parcel. Dividing each count by the total makes nonnegative values summing to one. Those numbers describe this count baseline for this context, not confidence that a real-world event occurred.

Store the counts in a float32 PyTorch tensor. A tensor is an array with explicit shape and dtype; here it is a one-dimensional list of three numeric values. Tensor division computes the normalized values elementwise. Plot the distribution on a fixed zero-to-one scale so that heights have the stated probability interpretation. The largest value identifies the baseline's most frequent continuation, but a less frequent candidate can still be selected by a sampling rule. The zero assigned to parcel reflects no observation after this exact context in this tiny table. A neural language model typically produces scores for its full vocabulary and normalizes them by another procedure; that mechanism arrives later. Do not mistake this deliberately transparent counting example for a pretrained network.

Try it

  1. Store the observed counts as a float32 tensor.
  2. Normalize by their sum and inspect shape and total.
  3. Plot all candidates, including the unobserved one.
Python · run in order
candidate_words = ["book","key","parcel"]
counts = torch.tensor([1.0,3.0,0.0],dtype=torch.float32)
probabilities = counts/counts.sum()
fig, ax = plt.subplots(figsize=(7,3.4))
ax.bar(candidate_words,probabilities.numpy(),color="#447f9e")
ax.set(ylim=(0,1),ylabel="Empirical probability",title="Count baseline after 'return the'")
for index,value in enumerate(probabilities.tolist()):
    ax.text(index,value+0.025,f"{value:.2f}",ha="center")
fig.tight_layout()

Read the result

The distribution sums to one, while each entry refers to one candidate in a fixed order. The numeric values remain tied to the stated context and constructed count source.

Change and compare

  • Double all counts and compare the normalized result.
  • Explain why a zero count here does not prove parcel is an impossible continuation.

Guided task 04

Autoregressive feedback

Autoregressive generation builds a sequence one selection at a time. The selected token is appended to the context, then another distribution is obtained for the enlarged sequence. In a real decoder language model, many preceding tokens can influence that distribution. Our transparent baseline uses only the last unit, which deliberately exposes a severe context limitation.

Build adjacent-unit counts from the messages and start with please. At each step, choose the most frequent observed successor; use alphabetical order to resolve equal counts. Stop after a period, an unseen context or six added units. These explicit stopping rules prevent an accidental infinite loop, but do not make the text useful or correct. Plot the probability assigned by the count table to each selected successor. The generated continuation is an actual result of the stated baseline, not a manually supplied neural-model output. Notice that its short memory mixes counts from different messages. The code illustrates the predict-select-append mechanism while leaving the later neural architecture, training process and long-range contextual behavior to subsequent labs.

Try it

  1. Build successor counts without crossing message boundaries.
  2. Run the stated greedy loop with explicit tie and stopping rules.
  3. Record the probability of every selected successor.
Python · run in order
successors = defaultdict(Counter)
for sequence in token_sequences:
    for current,next_unit in zip(sequence[:-1],sequence[1:]):
        successors[current][next_unit] += 1
generated = ["please"]
selected_probabilities = []
for step in range(6):
    options = successors.get(generated[-1],Counter())
    if not options:
        break
    next_unit = min(options,key=lambda word:(-options[word],word))
    selected_probabilities.append(options[next_unit]/sum(options.values()))
    generated.append(next_unit)
    if next_unit==".":
        break
fig, ax = plt.subplots(figsize=(9,3.5))
ax.bar(np.arange(len(selected_probabilities)),selected_probabilities,color="#51817a")
ax.set_xticks(np.arange(len(selected_probabilities)),generated[1:])
ax.set(ylim=(0,1.1),xlabel="Selected next unit",ylabel="Conditional count probability",title="Actual greedy continuation: "+" ".join(generated))
fig.tight_layout()

Read the result

Every selected unit becomes the next lookup context. A high value at a later step can simply mean this tiny table has only one observed successor there.

Change and compare

  • Change the starting unit to collect and trace the same stopping rules.
  • Choose a starting unit absent from the table and verify that the loop stops without inventing a distribution.

Guided task 05

Selection rules and repeated sampling

A distribution and a selected token are different objects. Greedy selection takes a highest-probability candidate, using a tie rule if needed. Sampling draws a candidate according to the distribution, so it can choose a lower-probability option without changing the underlying probabilities. Multiple runs therefore need not produce the same selected token.

Use the three-candidate empirical distribution from a return request, but define it locally so the demonstration does not depend on a previous task's state. Draw two thousand independent choices with a local NumPy generator and record their frequencies. Compare those measured frequencies with the supplied probabilities on the same axes. The frequencies need not match exactly in a finite sample; a fixed seed makes this particular experiment replayable, not universally representative. Here parcel has probability zero, so it is never selected under this distribution. Both greedy and sampled choices inherit the limitations of the distribution that supplied them. A more varied selection rule does not add missing facts or guarantee more useful language. Later generation lessons will work with neural scores and explicit temperature and top-k controls.

Try it

  1. Define the candidate probabilities and greedy choice.
  2. Sample two thousand independent choices with seed 101.
  3. Compare empirical frequencies with the supplied distribution.
Python · run in order
words = ["book","key","parcel"]
p = np.array([0.25,0.75,0.0])
greedy_word = words[int(np.argmax(p))]
local_rng = np.random.default_rng(101)
draws = local_rng.choice(len(words),size=2000,p=p)
frequencies = np.bincount(draws,minlength=len(words))/len(draws)
positions = np.arange(len(words))
fig, ax = plt.subplots(figsize=(8,3.5))
ax.bar(positions-0.18,p,width=0.36,label="Supplied probability")
ax.bar(positions+0.18,frequencies,width=0.36,label="Measured frequency")
ax.set_xticks(positions,words)
ax.set(ylim=(0,1),ylabel="Proportion",title=f"Repeated sampling; greedy choice is {greedy_word}")
ax.legend()
fig.tight_layout()

Read the result

Sampling creates variation while preserving the stated choice mechanism. The small gap between supplied and observed proportions is a finite-sample result, not a change in the baseline's distribution.

Change and compare

  • Repeat with only twenty draws and compare the variability.
  • Reset the local seed and confirm that the exact draw sequence is replayed.

Guided task 06

What a limited context can retain

A model can only condition directly on information that reaches its input. A finite context policy may keep a suffix and discard earlier units. The resulting input can be identical for two messages whose earlier facts differ. That is an information-loss issue before any choice of neural architecture or trained weights.

Compare two key-return notes. Their opening clauses name different keys and rooms, but their final five units are the same request. Plot all units and highlight the retained suffix. For a deterministic model in evaluation mode with the same parameters and no other input, identical retained inputs lead to the same next-token distribution. The model cannot inspect discarded text merely because that text existed in the original document. Stored learned associations are different from direct access to the specific earlier note and may be wrong for its current facts. This example does not prescribe a universal five-unit context; that short limit is chosen to make truncation visible. Real tokenizer units and model context limits must be checked explicitly when preparing a request.

Try it

  1. Construct two notes with different early facts and a shared ending.
  2. Retain only their last five whitespace units.
  3. Visualize which source units remain available.
Python · run in order
notes = [
    "key A belongs to room cedar please return it today .",
    "key B belongs to room maple please return it today ."
]
note_units = [note.split() for note in notes]
retained = [units[-5:] for units in note_units]
visibility = np.zeros((2,len(note_units[0])),dtype=int)
visibility[:,-5:] = 1
fig, ax = plt.subplots(figsize=(12,3))
ax.imshow(visibility,cmap="Blues",vmin=0,vmax=1,aspect="auto")
for row,units in enumerate(note_units):
    for column,word in enumerate(units):
        ax.text(column,row,word,ha="center",va="center",fontsize=9,color="white" if visibility[row,column] else "black")
ax.set_xticks([])
ax.set_yticks([0,1],["Note A","Note B"])
ax.set_title("Blue cells are retained; earlier facts are outside this input")
fig.tight_layout()

Read the result

The highlighted inputs are identical even though the full notes are not. A truncation policy can remove precisely the information needed for a later request.

Change and compare

  • Increase the retained suffix until the room names are included.
  • Move the key identifier near the ending and inspect whether this specific policy retains it.

Guided task 07

Output form and factual support

A plausible-looking sentence and a supported statement are different evaluation questions. Likewise, following an output format does not establish factual correctness. Language models are useful for drafting, rewriting, classification and other language tasks, but a fluent continuation should not be treated as evidence that its factual content is true.

Inspect three manually constructed candidate replies to a library-opening request. The reference record says 09:00. Each candidate has an explicitly annotated claimed time, so our small checker does not pretend to understand arbitrary natural language. One mechanical check asks whether the reply ends with a period; another compares its annotated time with the supplied reference. A reply can pass the punctuation rule and fail factual support, or do the reverse. Plot the two checks separately instead of collapsing them into a vague quality score. These are properties of constructed candidates, not measured responses from a trained model. For a real language task, choose evaluation criteria that match the use and retain the evidence needed to verify important claims.

Try it

  1. Keep the reference fact separate from candidate wording.
  2. Compute a mechanical format check and an annotated fact check.
  3. Compare their results without treating either as general language understanding.
Python · run in order
reference_time = "09:00"
candidates = [
    {"text":"The library opens at 09:00.","claimed_time":"09:00"},
    {"text":"The library opens at 10:00.","claimed_time":"10:00"},
    {"text":"09:00","claimed_time":"09:00"}
]
checks = np.array([[row["text"].endswith("."),row["claimed_time"]==reference_time] for row in candidates],dtype=int)
fig, ax = plt.subplots(figsize=(8,3.5))
im = ax.imshow(checks,cmap="Blues",vmin=0,vmax=1,aspect="auto")
ax.set_xticks([0,1],["Ends with a period","Annotated time matches"])
ax.set_yticks(np.arange(3),["Reply 1","Reply 2","Reply 3"])
for row in range(3):
    for column in range(2):
        ax.text(column,row,"pass" if checks[row,column] else "fail",ha="center",va="center",color="white" if checks[row,column] else "black")
ax.set_title("Two separate checks on constructed replies")
fig.tight_layout()

Read the result

Reply 2 passes the punctuation rule while disagreeing with the reference. The checker is narrow and explicit; it is not an automated judge of every possible factual or stylistic issue.

Change and compare

  • Add a candidate with no claimed time and decide how the audit should represent missing evidence.
  • Replace the punctuation rule with a one-line output requirement without changing the reference fact.

Guided task 08

Data coverage and unsupported estimates

A tiny count baseline makes a model-development limitation easy to see: some requested contexts have no supporting observation. Returning a normalized distribution from a zero total would be invalid arithmetic. Silently inventing a uniform distribution would also conceal a new policy choice. Keep the absence explicit instead of presenting it as a learned result.

Audit four requested contexts against the constructed message collection. Record how many successor observations each receives. For a nonzero total, the empirical table could be normalized; for zero, this particular baseline has no estimate under its stated rule. A neural language model can often assign a distribution to an unseen exact phrase by combining learned representations, but that numerical ability is not proof that the available training data supports every requested fact or domain. This distinction closes the introductory lesson: token prediction is the central mechanism, while usefulness depends on architecture, data, training, prompting and evaluation. The following labs will make those pieces explicit. The support-count chart is a diagnostic for this baseline only, not a proxy for model accuracy or universal language coverage.

Try it

  1. Scan four requested contexts without joining message boundaries.
  2. Store successor counts and an explicit supported/unsupported status.
  3. Plot observation totals while leaving unknown contexts visible.
Python · run in order
requests = [("return","the"),("collect","the"),("charge","the"),("room","is")]
support_counts = []
statuses = []
for context in requests:
    observed = Counter()
    for sequence in token_sequences:
        for position in range(len(sequence)-2):
            if tuple(sequence[position:position+2])==context:
                observed[sequence[position+2]] += 1
    total = sum(observed.values())
    support_counts.append(total)
    statuses.append("empirical estimate" if total else "no estimate")
fig, ax = plt.subplots(figsize=(9,3.5))
ax.bar([" ".join(context) for context in requests],support_counts,color=["#447f9e" if value else "#bd7b59" for value in support_counts])
for index,status in enumerate(statuses):
    ax.text(index,support_counts[index]+0.12,status,ha="center",fontsize=9)
ax.set(ylim=(0,5),ylabel="Successor observations",title="Coverage of the constructed count baseline")
fig.tight_layout()

Read the result

A zero-height bar remains part of the report. It marks a limitation of the stated estimator and data, not proof that the request is meaningless or that every neural model must fail on it.

Change and compare

  • Add one charge the message and identify the status transition.
  • Explain why obtaining a neural probability for a new phrase would still require a separate factual check.
