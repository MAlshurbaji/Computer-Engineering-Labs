Residual Connections and Transformer Blocks

MaterialPracticeQuiz

Assemble the components into a transformer block you can inspect one branch at a time. You will test residual paths, registered layers and causal behavior before building a language model.

What you will learn

  • Add residual branches without changing token or feature dimensions.
  • Trace a pre-normalized attention and feed-forward block.
  • Register independent blocks and verify their gradients.
  • Test evaluation determinism and causal prefix consistency.

Python · shared setup
import math
import json
import tempfile
from pathlib import Path
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
import matplotlib.pyplot as plt
torch.set_num_threads(1)
torch.manual_seed(110)
rng = np.random.default_rng(110)
def as_array(tensor):
    return tensor.detach().cpu().numpy()
class CausalHeads(nn.Module):
    def __init__(self, width=16, heads=4, dropout=0.0):
        super().__init__()
        if width % heads:
            raise ValueError("width must be divisible by heads")
        self.width, self.heads, self.head_dim = width, heads, width // heads
        self.qkv = nn.Linear(width, 3*width, bias=False)
        self.proj = nn.Linear(width, width, bias=False)
        self.attn_drop = nn.Dropout(dropout)
    def forward(self, x):
        b,t,c = x.shape
        packed = self.qkv(x).reshape(b,t,3,self.heads,self.head_dim)
        q,k,v = packed.permute(2,0,3,1,4).unbind(0)
        scores = (q @ k.transpose(-2,-1)) / math.sqrt(self.head_dim)
        future = torch.triu(torch.ones(t,t,device=x.device,dtype=torch.bool),diagonal=1)
        weights = scores.masked_fill(future,float("-inf")).softmax(dim=-1)
        context = self.attn_drop(weights) @ v
        merged = context.transpose(1,2).contiguous().reshape(b,t,c)
        return self.proj(merged), weights
class FeedForward(nn.Module):
    def __init__(self,width=16,expansion=4):
        super().__init__()
        self.up = nn.Linear(width,expansion*width)
        self.act = nn.GELU()
        self.down = nn.Linear(expansion*width,width)
    def forward(self,x):
        return self.down(self.act(self.up(x)))
class TransformerBlock(nn.Module):
    def __init__(self,width=16,heads=4,dropout=0.0):
        super().__init__()
        self.norm1 = nn.LayerNorm(width)
        self.attention = CausalHeads(width,heads,dropout)
        self.norm2 = nn.LayerNorm(width)
        self.ff = FeedForward(width)
        self.drop = nn.Dropout(dropout)
    def forward(self,x):
        x = x + self.drop(self.attention(self.norm1(x))[0])
        return x + self.drop(self.ff(self.norm2(x)))

Guided task 01

Residual Addition Preserves a Stream

A residual connection adds a branch output to the tensor that entered the branch: y=x+f(x). It gives the network a direct path for carrying its current representation alongside a learned update. The shapes must match for the intended position-wise addition. Accidental broadcasting can produce valid Python output while implementing a different architecture.

Start with a width-eight token stream and a small learned linear branch. The branch changes features at each position, while the addition preserves batch size, sequence length and width. A zero branch makes the residual operation an exact identity; that is a useful boundary test. It does not mean that a normally initialized branch is zero or that the block automatically preserves all information. Inspect input, branch and combined output as separate arrays so the contribution of the shortcut is visible.

Try it

  1. Create a two-example, four-token residual stream.
  2. Compute one width-preserving branch.
  3. Add the branch and inspect all three arrays.
Python · run in order
x = torch.randn(2,4,8)
branch_layer = nn.Linear(8,8,bias=False)
branch = branch_layer(x)
residual = x + branch
fig,axes = plt.subplots(1,3,figsize=(11,3.4))
limit=max(float(torch.stack([x,branch.detach(),residual.detach()]).abs().max()),1e-8)
for ax,value,title in zip(axes,[x[0],branch[0],residual[0]],["Input stream","Branch update","Residual sum"]):
    artist=ax.imshow(as_array(value),cmap="coolwarm",vmin=-limit,vmax=limit,aspect="auto")
    ax.set(title=title,xlabel="Feature",ylabel="Token")
fig.colorbar(artist,ax=axes.tolist(),label="Feature value")

Read the result

The sum has the same positional grid as its input, but its values need not resemble either contribution alone. Matching shapes is the contract for this residual path, not evidence that the learned update is small or beneficial.

Change and compare

  • Replace the branch with zeros and verify exact identity.
  • Attempt a branch with a different feature width and distinguish an error from unintended broadcasting.

Guided task 02

Direct Gradient Paths

The derivative of x+f(x) includes an identity contribution as well as the branch derivative. That direct path can help gradients pass through a deep computation, but it is not a promise that every gradient will remain well scaled. Branch derivatives still interact with the shortcut and with each other across layers.

A scalar example isolates the idea. Apply eight stages of multiplication by 0.4, then compare with eight residual stages x+0.4x. The first derivative is 0.4 to the eighth power; the second is 1.4 to the eighth power. One shrinks and the other grows, showing both the benefit of a direct path and the need to control scale. This is an exact toy calculation, not a measured training comparison between language models. Use autograd to confirm the derivatives and inspect the analytical values rather than treating residual connections as a universal cure.

Try it

  1. Build two independent scalar computation graphs.
  2. Apply eight plain or residual stages.
  3. Compare actual autograd derivatives with the powers.
Python · run in order
plain_input = torch.tensor(1.,requires_grad=True)
skip_input = torch.tensor(1.,requires_grad=True)
plain,skip = plain_input,skip_input
for depth in range(8):
    plain = .4*plain
    skip = skip + .4*skip
plain.backward()
skip.backward()
derivatives = [float(plain_input.grad),float(skip_input.grad)]
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(["Plain stages","Residual stages"],derivatives)
ax.set(title="Eight-stage scalar derivatives",ylabel="Derivative magnitude")
fig.tight_layout()

Read the result

The residual example has a larger derivative, but it is also growing with depth. This controlled calculation explains a mechanism; it does not establish which architecture or initialization will train best on real text.

Change and compare

  • Replace 0.4 with −0.4 and recompute both paths.
  • Plot derivatives over depths one through eight to distinguish exponential shrinkage and growth.

Guided task 03

Pre-Normalized Attention Branch

A pre-normalized block sends a normalized copy of the residual stream into attention, then adds the attention output back to the original stream. The shortcut itself is not replaced by the normalized tensor. This ordering differs from post-normalization, where normalization follows an addition; names that sound similar can represent different computations.

Inspect the first half of the setup TransformerBlock explicitly: norm1(x), attention(norm1(x)), and x plus that branch. LayerNorm operates over features independently at each position, while causal attention mixes information from permitted prefix positions. Both return width eight here, so the addition is well defined. The block's dropout is zero for this trace, allowing exact comparisons with a manual expansion. Keep the attention weights available as a diagnostic, but do not interpret random head patterns as learned linguistic explanations.

Try it

  1. Normalize a copy of the input stream.
  2. Run two-head causal attention on that copy.
  3. Add its output to the original, unnormalized stream.
Python · run in order
block = TransformerBlock(8,2,dropout=0)
normalized = block.norm1(x)
attention_branch,weights = block.attention(normalized)
after_attention = x + attention_branch
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(weights[0,0])
artist = ax.imshow(shown,cmap="viridis",aspect="auto",vmin=0,vmax=max(float(shown.max()),1e-8))
ax.set(title="Attention branch inside the block",xlabel="Key position",ylabel="Query position")
fig.colorbar(artist,ax=ax)
ax.set_xticks(range(shown.shape[1]))
ax.set_yticks(range(shown.shape[0]))
fig.tight_layout()

Read the result

The displayed weights are causal even though the input stream carries arbitrary feature values. Normalization changes feature scale before attention; the residual sum keeps a direct route from the unnormalized stream into the next stage.

Change and compare

  • Compare x plus the branch with normalized plus the branch to identify the changed architecture.
  • Verify the first query can use only its own value position.

Guided task 04

Second Residual Branch

The feed-forward branch receives the stream after attention, not the original block input. Normalize that updated stream with a second LayerNorm, run the expanding nonlinear feature transformation, and add its output to the updated stream. The two normalization layers have distinct learned parameters even though they have the same shape.

This arrangement combines two kinds of computation: attention exchanges information across permitted positions, while the feed-forward module transforms the contextual vector at each position. A feed-forward layer can therefore work on information about earlier tokens without itself reading another position. Expand the entire block manually and compare against its forward method. Agreement checks operation order, shortcut sources and parameter reuse. It is more informative than a shape-only test, because several incorrect orderings would still return B,T,C.

Try it

  1. Normalize the post-attention stream.
  2. Compute and add the feed-forward update.
  3. Compare the expanded calculation with block(x).
Python · run in order
ff_input = block.norm2(after_attention)
ff_branch = block.ff(ff_input)
manual_block = after_attention + ff_branch
automatic_block = block(x)
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array((manual_block-automatic_block).abs()[0])
artist = ax.imshow(shown,cmap="viridis",aspect="auto",vmin=0,vmax=max(float(shown.max()),1e-8))
ax.set(title="Manual versus module difference",xlabel="Feature",ylabel="Token position")
fig.colorbar(artist,ax=ax)
ax.set_xticks(range(shown.shape[1]))
ax.set_yticks(range(shown.shape[0]))
fig.tight_layout()

Read the result

The difference should be zero within numerical precision. The manual trace uses the same registered modules and the same ordering as forward; separately initializing another block would not be an equivalent comparison.

Change and compare

  • Swap the shortcut source in a deliberate faulty calculation and observe the mismatch.
  • Check that norm1 and norm2 are distinct parameter objects.

Guided task 05

Registered Stacks with Independent Parameters

A transformer uses multiple blocks in sequence. Each block has its own parameters unless sharing is explicitly designed. Constructing a list by repeating one module object would reuse the same weights, even though the list contains several entries. A list comprehension that creates a new block on each iteration gives independent modules.

Store them in ModuleList so PyTorch registers their parameters and propagates train/eval mode changes. ModuleList is a container, not an automatic forward pipeline; iterate through it in order. The tensor shape remains B,T,C after every block, while the representation changes. Count parameters and inspect named state entries to verify the architecture you actually built. More blocks increase computation and parameter storage, but this structural lesson does not claim that a deeper random stack has stronger language abilities.

Try it

  1. Create two distinct width-eight transformer blocks.
  2. Store them in ModuleList and apply them sequentially.
  3. Record the activation norm after each stage.
Python · run in order
stack = nn.ModuleList([TransformerBlock(8,2,dropout=0) for _ in range(2)])
stream = x
stage_norms = [float(stream.detach().norm())]
for layer in stack:
    stream = layer(stream)
    stage_norms.append(float(stream.detach().norm()))
stack_count = sum(p.numel() for p in stack.parameters())
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(["Input","Block 1","Block 2"],stage_norms)
ax.set(title="Measured residual-stream norms",ylabel="Frobenius norm")
fig.tight_layout()

Read the result

Norms describe the current random computation and need not rise or fall monotonically. Registration ensures that an optimizer can see both blocks; separate object identity ensures the two parameter sets are not accidentally tied.

Change and compare

  • Compare new-module construction with repeating one module reference.
  • Inspect state_dict keys to see block indices attached to parameter names.

Guided task 06

Dropout Modes Across a Whole Block

Dropout can appear inside attention and on residual branch outputs. Calling eval on the containing block propagates the mode to its registered children, disabling their dropout behavior. Calling no_grad alone does not change those modes. A repeated forward pass can therefore remain random inside no_grad if the block is still training.

Use one block with dropout probability 0.3 and the same input for every call. Compare two training-mode outputs, then two evaluation-mode outputs, all without recording graphs. The output differences come from mode-dependent randomness rather than changed parameters. The evaluation pair should agree exactly in this CPU exercise. A stable result does not mean the weights are frozen for future optimization: trainability, gradient recording and module mode are separate controls that will recur in the training and fine-tuning lessons.

Try it

  1. Run two no_grad forwards in training mode.
  2. Switch the entire block to eval and repeat.
  3. Compare maximum differences by token position.
Python · run in order
stochastic = TransformerBlock(8,2,dropout=.3)
stochastic.train()
with torch.no_grad():
    train_a = stochastic(x)
    train_b = stochastic(x)
stochastic.eval()
with torch.no_grad():
    eval_a = stochastic(x)
    eval_b = stochastic(x)
differences = torch.stack([(train_a-train_b).abs().amax(-1)[0],(eval_a-eval_b).abs().amax(-1)[0]])
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(differences)
artist = ax.imshow(shown,cmap="viridis",aspect="auto",vmin=0,vmax=max(float(shown.max()),1e-8))
ax.set(title="Repeated-call differences by mode",xlabel="Token position",ylabel="Train pair / eval pair")
fig.colorbar(artist,ax=ax)
ax.set_xticks(range(shown.shape[1]))
ax.set_yticks([0,1],["Training", "Evaluation"])
fig.tight_layout()

Read the result

The training row can contain nonzero differences even though no graph was recorded. The evaluation row should be zero. This test depends on registered child modules receiving the parent's mode change.

Change and compare

  • Check the training flags of the attention-dropout and residual-dropout children.
  • Set dropout to zero and repeat both modes.

Guided task 07

Causality Survives the Block Stack

A stack remains causal when every operation respects the same information boundary. Causal attention uses only earlier and current positions; LayerNorm and feed-forward layers act within one position; residual addition combines matching positions. None of those operations should introduce a route from a changed future token to an earlier output.

Test the whole registered stack rather than assuming correctness from its parts. Replace the final two positions of a five-token input while preserving the first three. In evaluation mode, the prefix outputs should match. This invariant can expose an attention-mask error or an axis-mixing mistake in head merging. It does not address every data issue: incorrect shifted targets or overlapping training/test documents can still undermine a language-model experiment even when the architecture itself is causal. Architectural and dataset tests complement each other.

Try it

  1. Create two inputs with an identical three-token prefix.
  2. Run both through the same evaluation-mode stack.
  3. Measure differences at every output position.
Python · run in order
stack.eval()
prefix_input = torch.randn(1,5,8)
suffix_changed = prefix_input.clone()
suffix_changed[:,3:] = torch.randn(1,2,8)*3
with torch.no_grad():
    base,altered = prefix_input,suffix_changed
    for layer in stack:
        base = layer(base)
        altered = layer(altered)
position_difference = (base-altered).abs().amax(-1)[0]
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(list(range(5)),as_array(position_difference))
ax.set(title="Stack response to a changed suffix",ylabel="Maximum absolute difference")
fig.tight_layout()

Read the result

Earlier positions have no permitted route to the altered suffix. Later positions may respond through their own vectors and through earlier allowed positions. A passing test validates this structural invariant, not the usefulness of the representation.

Change and compare

  • Run the same test after adding a third independent block.
  • Explain why normalizing across token positions would violate the intended dependency rule.

Guided task 08

One Optimizer Step Through the Stack

A registered block stack can be optimized using ordinary autograd and an optimizer. Use a deliberately simple mechanics objective: make its output approach a supplied zero tensor. This is not next-token prediction and does not teach the model language. Its purpose is to verify that gradients reach registered parameters and that an optimizer step changes them.

Clear existing gradients before backward, compute a scalar mean squared error, backpropagate, and step with a small SGD learning rate. Measure the objective before and after without assuming that every possible step size guarantees a decrease. Preserve a copy of one parameter tensor to verify an actual update. The language-model objective will arrive after the output vocabulary head is built. Keeping this probe separate prevents a small synthetic optimization demonstration from being mistaken for successful language-model pretraining.

Try it

  1. Run the registered stack on a fixed input.
  2. Backpropagate a zero-target mechanics loss.
  3. Update parameters once and measure the resulting objective.
Python · run in order
stack.train()
optimizer = torch.optim.SGD(stack.parameters(),lr=.005)
parameter_before = stack[0].ff.up.weight.detach().clone()
optimizer.zero_grad(set_to_none=True)
stream = x
for layer in stack:
    stream = layer(stream)
loss_before = stream.square().mean()
loss_before.backward()
optimizer.step()
with torch.no_grad():
    updated = x
    for layer in stack:
        updated = layer(updated)
    loss_after = updated.square().mean()
loss_values = [float(loss_before.detach()),float(loss_after)]
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(["Before step","After step"],loss_values)
ax.set(title="One mechanics-objective update",ylabel="Mean squared output")
fig.tight_layout()

Read the result

The bars are actual values from this one update. They are not language-model validation losses or evidence of generalization. Parameter movement and finite gradients verify the training plumbing before a more appropriate objective is introduced.

Change and compare

  • Repeat with learning rate zero and verify no parameter change.
  • Use a different target tensor while keeping the optimizer procedure fixed.
