Tokens, Vocabularies and Special Tokens

MaterialPracticeQuiz

Turn short notices into explicit units and reversible ID lookups. Inspect what each text-processing choice preserves, changes or loses before using the IDs in a model.

Python · shared setup
import re
from collections import Counter, defaultdict
import numpy as np
import torch
import matplotlib.pyplot as plt
torch.set_num_threads(1)
torch.manual_seed(103)
rng = np.random.default_rng(103)
import unicodedata
# This deliberately small regex tokenizer preserves punctuation as separate pieces.
TOKEN_PATTERN = r"\w+|[^\w\s]"
def tokenize(text):
    return re.findall(TOKEN_PATTERN,text)
training_texts = [
    "Room Cedar opens at nine.",
    "Return the key to Room Cedar.",
    "Bring a USB-C cable, please.",
    "Room Maple closes at five."
]

Guided task 01

Segmentation rules

Tokenization defines the units that a model receives. A whitespace split treats USB-C as one piece and may leave punctuation attached to words. Our small regex tokenizer instead matches runs of word characters or one non-word, non-whitespace character. It therefore separates a hyphen and surrounding letters, and it keeps punctuation as explicit pieces. This is a teaching tokenizer, not a claim that it matches a production language model's vocabulary.

Compare both routes on a room-equipment notice. Plot the actual token sequences in order so that a changed boundary is visible, rather than looking only at the total count. Python's word-character rule includes Unicode letters, digits and underscore, with details that matter for some scripts and combining marks. Neither route can be chosen solely because it makes fewer tokens. The rule must agree with the model's vocabulary and intended treatment of text. Spaces are not retained as separate pieces in this regex policy, which will limit exact text reconstruction. Record the segmentation rule as part of the input contract before assuming that two ID sequences refer to the same original text.

Try it

  1. Split the notice by whitespace and by the stated regex.
  2. Display both ordered piece sequences.
  3. Identify punctuation and hyphen boundaries changed by the rule.
Python · run in order
notice = "Room Cedar: bring 2 USB-C cables, please."
space_pieces = notice.split()
regex_pieces = re.findall(TOKEN_PATTERN,notice)
fig, axes = plt.subplots(2,1,figsize=(12,3.3))
limit = max(len(space_pieces),len(regex_pieces))
for ax,pieces,title in zip(axes,[space_pieces,regex_pieces],["Whitespace pieces","Regex pieces"]):
    for position,piece in enumerate(pieces):
        ax.add_patch(plt.Rectangle((position,0),0.94,0.8,facecolor="#d3e6ee",edgecolor="#447f9e"))
        ax.text(position+0.47,0.4,piece,ha="center",va="center",fontsize=8)
    ax.set(xlim=(0,limit),ylim=(0,1),title=title)
    ax.axis("off")
fig.tight_layout()

Read the result

The same notice produces different unit boundaries under the two policies. Those boundaries affect sequence length and vocabulary entries before any parameter is learned.

Change and compare

  • Try a product code containing an underscore and inspect the regex result.
  • Insert a second space and determine which representation retains that difference.

Guided task 02

Token round trips and text round trips

Decoding token pieces into readable text is not always an exact inverse of tokenization. If a tokenizer discarded whitespace, it cannot know whether a gap was one space, two spaces or a line break. A formatting rule can produce a conventional readable rendering, but that rendering is newly chosen formatting rather than recovered evidence.

Tokenize a short note with a doubled space, join the pieces with spaces, and then remove spaces immediately before common sentence punctuation. Display all three strings with their actual character counts. The formatting pass leaves spaces around the hyphen because we did not define a hyphen rule. Retokenizing the readable output still recovers the same regex pieces for this example, even though its characters differ from the source. Separate these two round-trip claims: piece-sequence equality and exact original-string equality. A production tokenizer can preserve more text information through its own byte or whitespace conventions, but that ability must come from its defined representation. Do not repair formatting after decoding in a way that silently changes identifiers, code or other text where spacing carries meaning.

Try it

  1. Create the piece sequence and a space-joined rendering.
  2. Apply only the stated punctuation-spacing rule.
  3. Compare character-level and token-level round trips.
Python · run in order
source = "Bring  USB-C, please."
pieces = tokenize(source)
spaced = " ".join(pieces)
readable = re.sub(r" +([.,:!?])",lambda match:match.group(1),spaced)
renderings = [source,spaced,readable]
fig, ax = plt.subplots(figsize=(11,3.5))
for row,(name,text) in enumerate(zip(["Original","Space-joined","Punctuation formatted"],renderings)):
    ax.text(0.01,0.83-row*0.3,f"{name}: {text!r}",fontfamily="monospace",fontsize=11,transform=ax.transAxes)
    ax.text(0.01,0.70-row*0.3,f"{len(text)} characters",fontsize=9,transform=ax.transAxes)
ax.set_title("Exact text equality and token equality are different checks")
ax.axis("off")
fig.tight_layout()

Read the result

A readable rendering can preserve the tokenizer's pieces without restoring the original spacing. The two equality tests answer different questions and should not be substituted for one another.

Change and compare

  • Add a line break to the source and inspect which information survives.
  • Design an explicit hyphen-spacing policy and discuss when it could be inappropriate.

Guided task 03

Deterministic vocabulary construction

A vocabulary maps supported pieces to integer IDs. Build the vocabulary from the training texts available at this stage, rather than quietly adding entries after inspecting evaluation text. Sorting the unique pieces gives a reproducible order for this teaching tokenizer. A different declared ordering can also work, but the mapping must stay fixed once a model's rows depend on it.

Collect the regex pieces from every training notice, remove duplicates and sort them. Enumerate the resulting list to create string-to-ID and ID-to-string dictionaries. Display the first twelve entries as an actual lookup table, while retaining the full vocabulary in memory. An ID is an index, not a measurement of a word's size, meaning or importance. ID 12 is not more similar to ID 13 than to ID 2 merely because the integers are close. Future embedding layers will associate each ID with a learned vector, and those vector values—not the numeric ID itself—can express useful relationships. Case remains significant under this policy, so Room and room would be different pieces if both were present.

Try it

  1. Collect pieces from the stated training texts only.
  2. Sort unique pieces and create both mapping directions.
  3. Inspect actual entries without treating IDs as semantic quantities.
Python · run in order
all_pieces = [piece for text in training_texts for piece in tokenize(text)]
vocabulary = sorted(set(all_pieces))
token_to_id = {piece:index for index,piece in enumerate(vocabulary)}
id_to_token = {index:piece for piece,index in token_to_id.items()}
shown = vocabulary[:12]
fig, ax = plt.subplots(figsize=(7,4.4))
table = ax.table(cellText=[[piece,token_to_id[piece]] for piece in shown],colLabels=["Piece","Lookup ID"],loc="center",cellLoc="left")
table.auto_set_font_size(False)
table.set_fontsize(10)
table.scale(1,1.3)
ax.set_title(f"First 12 entries of a {len(vocabulary)}-piece training vocabulary")
ax.axis("off")
fig.tight_layout()

Read the result

The table is deterministic because the input pieces and ordering rule are stated. Its integer spacing is an indexing convenience, not a semantic geometry.

Change and compare

  • Add one new training piece and inspect which later sorted IDs would move.
  • Compare a sorted vocabulary with first-occurrence order while keeping the underlying piece set fixed.

Guided task 04

Encoding and decoding known pieces

Encoding maps each piece to its vocabulary ID while preserving sequence order. Decoding performs the inverse lookup for each ID. With a complete matching vocabulary, the decoded piece sequence should equal the encoded piece sequence exactly. Reconstructing the source's original whitespace remains a separate question.

Build the same deterministic vocabulary locally and encode a new short return notice made entirely of known pieces. Display the pieces, numeric IDs and recovered pieces in aligned columns. Repetition remains repetition: every occurrence of the same known piece receives the same ID, regardless of position. That ID alone does not yet contain positional information; a later embedding lesson adds a separate representation for position. Direct dictionary lookup deliberately raises an error for an unknown piece, so this version has an explicit narrow input contract rather than silently changing the vocabulary. The next activity introduces an unknown marker as an alternative policy. Keeping failure behavior visible makes it easier to distinguish an unsupported word from a corrupt sequence or an incompatible model checkpoint.

Try it

  1. Create a known-piece notice under the training vocabulary.
  2. Encode its ordered pieces and decode the resulting IDs.
  3. Check exact piece-sequence equality.
Python · run in order
vocabulary = sorted({piece for text in training_texts for piece in tokenize(text)})
token_to_id = {piece:index for index,piece in enumerate(vocabulary)}
id_to_token = {index:piece for piece,index in token_to_id.items()}
pieces = tokenize("Return the key.")
encoded = [token_to_id[piece] for piece in pieces]
decoded = [id_to_token[index] for index in encoded]
fig, ax = plt.subplots(figsize=(8,3))
table = ax.table(cellText=[pieces,[str(index) for index in encoded],decoded],rowLabels=["Pieces","IDs","Recovered"],loc="center",cellLoc="center")
table.auto_set_font_size(False)
table.set_fontsize(11)
table.scale(1,1.8)
ax.set_title("Order-preserving lookup with a matching vocabulary")
ax.axis("off")
fig.tight_layout()

Read the result

The recovered pieces agree exactly because both directions use the same mapping. The numbers are identifiers; their magnitudes do not express probabilities or positions.

Change and compare

  • Encode a notice that repeats the word Room and compare its repeated IDs.
  • Try a piece absent from the vocabulary and inspect the direct lookup's explicit failure.

Guided task 05

Unknown pieces and reserved IDs

An unknown-piece policy defines what happens when new text contains a piece absent from the vocabulary. Direct lookup can reject the input. An alternative reserves an unknown marker and maps every unsupported piece to that ID. This allows a numeric sequence to be produced, but it loses the identity of the unknown pieces: two different unseen words can collapse to the same marker.

Reserve IDs zero, one and two for UNK, EOS and PAD, then place sorted ordinary pieces after them. Encode a return notice containing lantern and Birch, which are absent from the training vocabulary. Display the original pieces beside their recovered vocabulary entries. The UNK markers show the information loss directly. EOS will represent a document ending in the next task; PAD will later represent batch filler, which requires a corresponding masking policy rather than ordinary language semantics. Reserved IDs must be stable and within the model's supported range. Do not append new vocabulary rows at inference without also addressing the model's embeddings and output head. Subword and byte-based tokenizers offer different coverage tradeoffs, introduced in the following lesson.

Try it

  1. Reserve UNK, EOS and PAD before ordinary vocabulary entries.
  2. Map unsupported pieces through the explicit UNK policy.
  3. Inspect which original identities cannot be recovered.
Python · run in order
reserved = ["<UNK>","<EOS>","<PAD>"]
ordinary = sorted({piece for text in training_texts for piece in tokenize(text)})
vocabulary = reserved+ordinary
token_to_id = {piece:index for index,piece in enumerate(vocabulary)}
pieces = tokenize("Return the lantern to Room Birch.")
encoded = [token_to_id.get(piece,token_to_id["<UNK>"]) for piece in pieces]
recovered = [vocabulary[index] for index in encoded]
unknown_positions = [position for position,index in enumerate(encoded) if index==token_to_id["<UNK>"]]
fig, ax = plt.subplots(figsize=(10,3))
table = ax.table(cellText=[pieces,[str(index) for index in encoded],recovered],rowLabels=["Source","IDs","Recovered"],loc="center",cellLoc="center")
table.auto_set_font_size(False)
table.set_fontsize(10)
table.scale(1,1.8)
ax.set_title("An unknown marker keeps sequence slots but loses the missing identities")
ax.axis("off")
fig.tight_layout()

Read the result

The two different unseen words both decode to UNK. The resulting numeric sequence is usable under the policy, but it no longer contains enough information to reconstruct those original words.

Change and compare

  • Compare this policy with raising an explicit error for the same text.
  • Explain what extra storage would be needed to recover the original unknown spellings.

Guided task 06

Document boundaries and special-token meaning

An end-of-sequence marker is a dedicated vocabulary entry used to represent a boundary under a declared data format. It is different from a literal period: a document may contain several sentences, and punctuation alone does not necessarily identify where one source ends. A special token gets its operational meaning from data preparation and training conventions, not from its printed name.

Encode two short notices separately and append one EOS ID to each. Compare their plain concatenation with a stream containing explicit endings. The marker makes the source boundary observable in that stream, but inserting EOS does not automatically reset an attention cache, prevent cross-document attention or enforce independent training windows. Those behaviors require their own policies. In the next lesson, windows are created within already split documents to keep source boundaries explicit. Here special markers are inserted structurally by the program after tokenization rather than recognized from arbitrary matching text. A full tokenizer must specify how literal text resembling a special marker is treated. Keep EOS distinct from padding even if a particular pretrained interface later chooses to reuse an ID and relies on masks to distinguish the roles.

Try it

  1. Encode each notice independently using stable reserved IDs.
  2. Append one EOS marker per document.
  3. Compare streams with and without explicit boundary entries.
Python · run in order
vocabulary = ["<UNK>","<EOS>","<PAD>"]+sorted({piece for text in training_texts for piece in tokenize(text)})
token_to_id = {piece:index for index,piece in enumerate(vocabulary)}
documents = ["Return the key.","Bring a cable."]
encoded_documents = [[token_to_id.get(piece,0) for piece in tokenize(text)] for text in documents]
plain_stream = [index for document in encoded_documents for index in document]
bounded_stream = [index for document in encoded_documents for index in document+[token_to_id["<EOS>"]]]
fig, axes = plt.subplots(2,1,figsize=(12,3.5))
for ax,stream,title in zip(axes,[plain_stream,bounded_stream],["Plain concatenation","One EOS appended per document"]):
    for position,index in enumerate(stream):
        color = "#e4bb69" if index==token_to_id["<EOS>"] else "#d3e6ee"
        ax.add_patch(plt.Rectangle((position,0),0.94,0.8,facecolor=color,edgecolor="#5a6d77"))
        ax.text(position+0.47,0.4,vocabulary[index],ha="center",va="center",fontsize=8)
    ax.set(xlim=(0,len(bounded_stream)),ylim=(0,1),title=title)
    ax.axis("off")
fig.tight_layout()

Read the result

The added markers identify boundaries in the representation. They do not, by themselves, change a future model's attention policy or partition related documents into independent data.

Change and compare

  • Use a two-sentence document and append EOS only at its true ending.
  • Describe which additional policy would stop windows from crossing source documents.

Guided task 07

Vocabulary compatibility

Numeric IDs cannot be interpreted without the exact vocabulary that assigned them. Two vocabularies can contain the same pieces and have the same size while assigning different IDs to each piece. An encoded sequence can therefore stay within range and still decode to the wrong text when paired with an incompatible mapping.

Create two vocabularies containing the same training pieces: one sorted and the other in reverse order. Encode a known notice under the first and decode those same numbers under both. Display the mismatch and retain a tokenizer record containing the pattern, case policy and ordered vocabulary. Merely recording vocabulary size is insufficient. A trained embedding table associates row i with the piece assigned ID i during training; swapping the mapping changes which learned vector every input selects. The output head's candidate order must agree as well. When adding special tokens or loading a checkpoint later, verify this identity alongside architecture dimensions. A valid shape check catches some incompatibilities, but it cannot detect an in-range semantic permutation by itself.

Try it

  1. Encode a known notice with a sorted vocabulary.
  2. Decode its IDs with both the matching and reversed mappings.
  3. Record the ordered vocabulary rather than only its size.
Python · run in order
vocab_a = sorted({piece for text in training_texts for piece in tokenize(text)})
vocab_b = list(reversed(vocab_a))
lookup_a = {piece:index for index,piece in enumerate(vocab_a)}
pieces = tokenize("Room Cedar opens.")
ids = [lookup_a[piece] for piece in pieces]
correct = [vocab_a[index] for index in ids]
wrong = [vocab_b[index] for index in ids]
tokenizer_record = {"pattern":TOKEN_PATTERN,"case_sensitive":True,"ordered_vocabulary":list(vocab_a)}
fig, ax = plt.subplots(figsize=(9,3.6))
table = ax.table(cellText=[pieces,[str(index) for index in ids],correct,wrong],rowLabels=["Source","IDs from A","Decode with A","Decode with B"],loc="center",cellLoc="center")
table.auto_set_font_size(False)
table.set_fontsize(10)
table.scale(1,1.7)
ax.set_title("Same vocabulary size does not establish mapping compatibility")
ax.axis("off")
fig.tight_layout()

Read the result

Every ID is valid in both vocabularies, yet only the matching mapping recovers the intended pieces. Numeric range validation and tokenizer-identity validation serve different purposes.

Change and compare

  • Swap just two vocabulary entries and find which input pieces are affected.
  • List the tokenizer information that must accompany a saved model checkpoint.

Guided task 08

Unicode and normalization policy

Text that looks similar can have different character sequences. The accented word Café can store its final character as one composed code point or as a plain e followed by a combining accent. Unicode NFC normalization gives canonically equivalent forms a consistent composed representation where available. Case folding is a separate operation that can merge distinctions between uppercase and lowercase text.

Compare composed, decomposed, lowercase and uppercase versions. Measure their Python character counts before and after NFC, then tokenize the NFC forms. The regex's word-character behavior can treat a combining mark differently before normalization, so the text policy changes the resulting pieces. Apply case folding separately and inspect its deliberate additional collapse. Neither operation should be added silently to an existing tokenizer: case can matter in room codes, names, programming text or other identifiers. Record the chosen policy and use it consistently with the vocabulary and model. This small Latin-script example illustrates why visible appearance is not a sufficient compatibility test; it does not establish that one normalization or segmentation policy is appropriate for every writing system or task.

Try it

  1. Normalize four explicit Unicode variants with NFC.
  2. Compare character counts and tokenize the normalized strings.
  3. Inspect case folding as a separate declared choice.
Python · run in order
variants = ["Café","Cafe\u0301","café","CAFÉ"]
normalized = [unicodedata.normalize("NFC",text) for text in variants]
normalized_tokens = [tokenize(text) for text in normalized]
folded = [text.casefold() for text in normalized]
raw_lengths = [len(text) for text in variants]
normalized_lengths = [len(text) for text in normalized]
positions = np.arange(4)
fig, ax = plt.subplots(figsize=(9,3.5))
ax.bar(positions-0.18,raw_lengths,width=0.36,label="Original code points")
ax.bar(positions+0.18,normalized_lengths,width=0.36,label="After NFC")
ax.set_xticks(positions,["Composed title","Decomposed","Lowercase","Uppercase"])
ax.set(ylabel="Python string length",title="Normalization and case policy are separate decisions",ylim=(0,6))
ax.legend()
fig.tight_layout()

Read the result

NFC reconciles the first two canonical forms here without lowercasing them. Case folding merges more variants, which can be intentional but changes the representation policy.

Change and compare

  • Compare the raw regex pieces of the decomposed form with its NFC pieces.
  • Name a kind of identifier for which automatic case folding would require an explicit decision.
