Subword Tokenization and Training Windows

MaterialPracticeQuiz

Move from whole-piece lookups to a tokenizer that can represent unfamiliar text through bytes. Then turn each already split document into explicit next-token examples and inspect the batches a model will receive.

What you will learn

  • Recover Unicode text by joining token bytes before decoding.
  • Create input/target windows shifted exactly once.
  • Keep source splits intact while varying stride and minibatch size.

documents = [
    {"id":"booking","group":"booking-note","split":"train","text":"book a room for lunch."},
    {"id":"return","group":"return-note","split":"train","text":"return the blue book."},
    {"id":"charging","group":"charging-note","split":"train","text":"charge the spare phone."},
    {"id":"pickup","group":"pickup-note","split":"train","text":"collect the parcel today."},
    {"id":"coffee","group":"coffee-note","split":"validation","text":"bring a café cup."},
    {"id":"key","group":"key-note","split":"test","text":"leave the brass key."}

# A minimal byte-pair learner: no downloads and no claim of GPT-2 compatibility.
def merge_pair(sequence,pair,new_id):
    output = []
    position = 0
    while position<len(sequence):
        if position+1<len(sequence) and (sequence[position],sequence[position+1])==pair:
            output.append(new_id)
            position += 2
        else:
            output.append(sequence[position])
            position += 1
    return output

def fit_byte_merges(texts,num_merges):
    vocabulary = {index:bytes([index]) for index in range(256)}
    sequences = [list(text.encode("utf-8")) for text in texts]
    merges,history = [],[]
    for step in range(num_merges):
        counts = Counter(pair for sequence in sequences for pair in zip(sequence[:-1],sequence[1:]))
        if not counts:
            break
        pair = min(counts,key=lambda candidate:(-counts[candidate],candidate))
        if counts[pair]<2:
            break
        new_id = len(vocabulary)
        vocabulary[new_id] = vocabulary[pair[0]]+vocabulary[pair[1]]
        before = sum(map(len,sequences))
        sequences = [merge_pair(sequence,pair,new_id) for sequence in sequences]
        after = sum(map(len,sequences))
        merges.append((pair,new_id))
        history.append({"pair":pair,"new_id":new_id,"frequency":counts[pair],"before":before,"after":after})
    return vocabulary,merges,history

def encode_bytes(text,merges):
    sequence = list(text.encode("utf-8"))
    for pair,new_id in merges:
        sequence = merge_pair(sequence,pair,new_id)
    return sequence

def decode_bytes(ids,vocabulary):
    return b"".join(vocabulary[index] for index in ids).decode("utf-8")

Guided task 01

Bytes as a complete fallback alphabet

A whole-word vocabulary may fail on an unfamiliar spelling. A byte-level representation instead begins with the 256 possible byte values. UTF-8 encodes every valid Python text string into a sequence of bytes, so this starting alphabet can represent characters not seen in the training notices. One displayed character can occupy several bytes; a byte is not necessarily a complete character.

Compare an ASCII word, an accented word and a teapot symbol. Count Python string code points and UTF-8 bytes separately, then verify recovery by decoding each complete byte sequence. This establishes a fallback representation rather than a claim that one-byte tokens are efficient language units. Long byte sequences can later be shortened by merging frequently occurring adjacent pieces. Our course helper implements a small raw-byte merging scheme on complete strings, including spaces and punctuation. It is not the production GPT-2 tokenizer: that tokenizer has its own pretokenization, merge ranks and vocabulary identity. A saved model needs the tokenizer it was trained with, not any tokenizer that happens to use the name BPE.

Try it

  1. Encode three explicit strings as UTF-8 bytes.
  2. Compare code-point and byte counts.
  3. Decode each complete byte sequence to verify recovery.
Python · run in order
texts = ["room","café","🫖"]
labels = ["ASCII word","Accented word","Teapot symbol"]
byte_sequences = [list(text.encode("utf-8")) for text in texts]
character_counts = [len(text) for text in texts]

The byte count and character count answer different questions. Recovery succeeds from each complete encoded sequence even when individual bytes cannot be decoded as characters on their own.

Guided task 02

Pair counts and nonoverlapping replacement

Byte-pair merging replaces an adjacent pair of existing symbols with a new symbol whose stored bytes are their concatenation. Pair selection can count overlapping adjacent occurrences, but one replacement pass consumes symbols without overlap. This distinction matters for repeated symbols: a sequence of five a bytes contains four adjacent aa positions, yet a left-to-right pass can merge only two disjoint pairs.

Trace that case with a final b byte. Count adjacent pairs, choose aa as the explicit demonstration pair and replace it with ID 256. The merge helper advances by two after a match and by one otherwise, so it never reuses a consumed symbol. Store the new symbol's bytes as aa and reconstruct the original byte sequence from the result. The replacement changes token boundaries without changing the byte content. New IDs must remain distinct from existing symbols, and a later merge can combine previously merged symbols as well as base bytes. The chart compares potential pair occurrences with actual replacements for this controlled example; it is not a language-model loss or a guarantee of the best tokenizer vocabulary.

Try it

  1. Count adjacent byte pairs in aaaaab.
  2. Apply one nonoverlapping left-to-right aa merge.
  3. Verify that concatenating stored token bytes recovers the exact source.
Python · run in order
sequence = list(b"aaaaab")
pair_counts = Counter(zip(sequence[:-1],sequence[1:]))
pair = (ord("a"),ord("a"))
merged = merge_pair(sequence,pair,256)
byte_vocabulary = {index:bytes([index]) for index in range(256)}
byte_vocabulary[256] = b"aa"
reconstructed = b"".join(byte_vocabulary[index] for index in merged)
replacement_count = len(sequence)-len(merged)
fig, axes = plt.subplots(1,2,figsize=(9,3.5))
axes[0].bar(["aa","ab"],[pair_counts[(97,97)],pair_counts[(97,98)]],color="#447f9e")
axes[0].set(ylabel="Adjacent occurrences",title="Potential pairs can overlap")
axes[1].bar(["Source symbols","Merged symbols","Replacements"],[len(sequence),len(merged),replacement_count],color="#8d795d")
axes[1].set(ylabel="Count",title="One nonoverlapping replacement pass")
fig.tight_layout()

Read the result

Four potential aa occurrences become two actual merges because consumed bytes cannot participate twice in one pass. Exact byte reconstruction is preserved despite the shorter symbol sequence.

  • Apply the same helper when the requested pair is absent.

Guided task 03

Learning an ordered merge list

A small BPE-style learner repeatedly counts adjacent pairs in the current training sequences, chooses a frequent pair, creates its new ID and applies that replacement. Counts must be recomputed after every merge because the symbol sequences have changed. Our deterministic tie rule chooses the smallest numeric pair among equal-frequency candidates, and training stops if no pair occurs at least twice.

Fit at most eight merges using only documents already assigned to training. Inspect the helper's recorded frequency and total symbol counts at each step. Every new vocabulary entry stores the concatenated bytes of its two parents, so decoding remains possible. The merge order is part of the tokenizer: a later encoding must replay the same ranked rules rather than independently selecting frequent pairs in its input. The counts describe compression of this small training representation, not semantic understanding or a neural model's objective. Validation and test text do not contribute new merge decisions. Their unseen spellings can still be represented by the base byte alphabet, although their token lengths may differ from familiar training patterns. Keep the learned vocabulary and merge list together.

Try it

  1. Fit the deterministic teaching learner on training texts only.
  2. Inspect each recorded merge frequency and before/after length.
  3. Verify that the resulting vocabulary and merge sequence are consistent.
Python · run in order
vocabulary,merges,history = fit_byte_merges(training_texts,8)
steps = np.arange(1,len(history)+1)
frequencies = [row["frequency"] for row in history]
before_counts = [row["before"] for row in history]
after_counts = [row["after"] for row in history]
fig, axes = plt.subplots(1,2,figsize=(10,3.5))
axes[0].bar(steps,frequencies,color="#447f9e")
axes[0].set(xlabel="Merge step",ylabel="Selected pair occurrences",title="Recounted frequencies")
axes[1].plot(np.arange(len(history)+1),[before_counts[0]]+after_counts,"o-")
axes[1].set(xlabel="Completed merges",ylabel="Training symbols",title="Actual representation lengths")
fig.tight_layout()

Read the result

The symbol count decreases while exact underlying bytes stay recoverable. A frequent pair can include a space or punctuation in this raw-byte teaching scheme and need not be a complete word.

  • Fit fewer merges and compare token lengths without claiming that shorter automatically means better language modeling.

Guided task 04

Replaying merges on unfamiliar text

Encoding new text starts with its UTF-8 byte IDs and replays the learned merges in their fixed order. It does not relearn the most frequent pairs from the new input. That distinction keeps token IDs compatible with the model and prevents evaluation text from silently changing a trained tokenizer's vocabulary.

Encode a new room-booking phrase containing café. Display a preview of the actual token byte strings and compare its character, raw-byte and merged-token counts. A piece can contain several characters, one character, or only part of a multibyte character. Use repr on the stored bytes for inspection and join all token bytes before UTF-8 decoding. Decoding each partial piece independently with replacement characters would discard information and can corrupt an otherwise exact round trip. The byte fallback means this small tokenizer can encode the new valid Unicode text without an UNK marker. It does not guarantee efficient segmentation, sensible semantic units or compatibility with any pretrained network. Preserve the fitted vocabulary and verify that encoding has not altered it.

Try it

  1. Fit once on the declared training texts and save the vocabulary size.
  2. Encode the unfamiliar phrase by replaying the merge list.
  3. Inspect stored bytes and verify exact full-text recovery.

Some byte pieces are readable as text fragments and others may be partial encodings. The exact recovery check belongs after their byte contents have been joined in order.

Guided task 05

Input windows and one target shift

A next-token training example pairs each input position with the token immediately after it in the source. For context length T, a full example therefore needs T plus one consecutive source tokens. The first T become inputs and the last T become targets. The shared overlap is intentional: target position zero follows input position zero, rather than naming the input token itself.

Encode one training document and create length-six windows with stride three. Keep the starting source index for each window and display the first two input/target pairs as numeric alignments. The IDs are labels for vocabulary entries, so the colour map is only a visual aid; closeness of ID numbers does not imply semantic similarity. This course's from-scratch route supplies already shifted targets to its later loss calculation and must not shift them a second time. Other APIs can shift internally, so their contracts need separate checking. No model is trained in this activity. Its purpose is to make the supervision alignment verifiable before a low training loss could hide a wrong target convention.

Try it

  1. Encode one training document with the fitted byte-pair tokenizer.
  2. Slice complete T+1 blocks into length-six inputs and targets.
  3. Display two windows with their source start indices.
Python · run in order
vocabulary,merges,history = fit_byte_merges(training_texts,8)
ids = encode_bytes(documents[0]["text"],merges)
context_length,stride = 6,3
starts = list(range(0,len(ids)-context_length,stride))
inputs = [ids[start:start+context_length] for start in starts]
targets = [ids[start+1:start+context_length+1] for start in starts]
shown_rows = np.array([inputs[0],targets[0],inputs[1],targets[1]])
fig, ax = plt.subplots(figsize=(9,3.5))
ax.imshow(np.zeros_like(shown_rows),cmap="Blues",aspect="auto",vmin=0,vmax=1)
ax.set_xticks(range(context_length))
ax.set_yticks(range(4),[f"input start {starts[0]}",f"target start {starts[0]+1}",f"input start {starts[1]}",f"target start {starts[1]+1}"])
for row in range(4):
    for column in range(context_length):
        ax.text(column,row,str(shown_rows[row,column]),ha="center",va="center",fontsize=9,color="black")
ax.set(xlabel="Position within the training example",title="Targets are the source sequence shifted once")
fig.tight_layout()

Read the result

Every target except the final one is visible one position later in its paired input window. The last target requires the extra source token beyond the input's end.

Guided task 06

Stride, overlap and target coverage

Stride determines how far the next window's source start moves. With a small stride, neighboring windows reuse many source positions. That creates more training examples, but not more independent documents. It also changes how often each source token becomes a supervised target during one traversal of the window dataset.

Use the same encoded notice and context length for strides one, three and six. Count how many windows supervise each original source position, then display the coverage map. Position zero has no preceding token in this simple setup and is never a target; we have not inserted a beginning marker. A remainder near the document's end can be omitted when only complete windows are kept. The coverage pattern follows the exact range and slice rules rather than an assumption that every token appears equally often. Repeated supervision is a deliberate dataset design choice, not automatically an error. Keep it visible when comparing examples or validation accounting, and do not interpret a larger number of overlapping windows as a larger independent evaluation set.

Try it

  1. Create complete windows for three strides with fixed context length.
  2. Count target uses by original source position.
  3. Inspect overlap and any positions not covered by a complete window.
Python · run in order
vocabulary,merges,history = fit_byte_merges(training_texts,8)
ids = encode_bytes(documents[0]["text"],merges)
context_length = 6
strides = [1,3,6]
coverage = np.zeros((len(strides),len(ids)),dtype=int)
window_counts = []
for row,stride in enumerate(strides):
    starts = list(range(0,len(ids)-context_length,stride))
    window_counts.append(len(starts))
    for start in starts:
        coverage[row,start+1:start+context_length+1] += 1
fig, ax = plt.subplots(figsize=(11,3.5))
im = ax.imshow(coverage,cmap="Blues",aspect="auto",vmin=0)
ax.set_yticks(range(3),[f"stride {stride}: {count} windows" for stride,count in zip(strides,window_counts)])
ax.set_xticks(range(len(ids)))
ax.set(xlabel="Original token position",title="How often each source token is supervised as a target")
fig.colorbar(im,ax=ax,label="Target uses")
fig.tight_layout()

Read the result

The coverage distribution can be uneven even when every individual window has a correct one-step shift. Larger window counts mainly reflect overlap here, not additional independent source material.

Change and compare

  • Compare the sum of each coverage row with window count times context length.
  • Change the context length and identify how complete-window truncation affects the tail.

Guided task 07

Document-isolated window datasets

Window extraction must preserve the split and identity of its source. Concatenating all document IDs first and then cutting windows can create artificial continuations from one document's ending into another's beginning. Randomly splitting those windows can also distribute related source text across training and evaluation. A boundary marker alone does not repair either policy.

Fit the tokenizer on training documents only, then encode and window each document separately. Keep document ID, group, split and start offset with every example. The validation and test documents use the same fixed tokenizer, including its fallback bytes for unfamiliar text. Plot source-document counts beside window counts for each partition. A partition can have more windows without more independent documents, and a short document can contribute no complete windows under the selected length. Verify that each example's IDs match slices of its own recorded source. This audit makes the data route explicit before later training loops introduce shuffling or batching, which should rearrange examples without changing their provenance.

Try it

  1. Use only training text to fit the tokenizer.
  2. Create windows separately inside each split source document.
  3. Retain source metadata and compare document versus window counts.
Python · run in order
vocabulary,merges,history = fit_byte_merges(training_texts,8)
window_records = []
context_length,stride = 5,5
encoded_by_id = {}
for document in documents:
    ids = encode_bytes(document["text"],merges)
    encoded_by_id[document["id"]] = ids
    for start in range(0,len(ids)-context_length,stride):
        window_records.append({"document_id":document["id"],"group":document["group"],"split":document["split"],"start":start,"input":ids[start:start+context_length],"target":ids[start+1:start+context_length+1]})
split_names = ["train","validation","test"]
document_counts = [sum(d["split"]==split for d in documents) for split in split_names]
window_counts = [sum(row["split"]==split for row in window_records) for split in split_names]
positions = np.arange(3)
fig, ax = plt.subplots(figsize=(9,3.5))
ax.bar(positions-0.18,document_counts,width=0.36,label="Source documents")
ax.bar(positions+0.18,window_counts,width=0.36,label="Complete windows")
ax.set_xticks(positions,split_names)
ax.set(ylabel="Count",title="Windows inherit their source identity and split")
ax.legend()
fig.tight_layout()

Read the result

Every window can be traced to a single source document. A larger window total in one partition is not a claim that it contains that many independent notices.

  • Verify that no group appears in two partitions after window extraction.

Guided task 08

Dataset and DataLoader batch contracts

A dataset exposes examples, while a data loader groups and optionally shuffles them. Implement a small map-style Dataset whose length is the number of windows and whose indexed item returns input IDs, target IDs and the window's index. PyTorch's default collation stacks equal-length ID tensors into a batch with shape B by T.

Build windows only from the training documents, then use batch size three, a seeded shuffle generator and drop_last=False. The final batch may contain fewer examples; keeping it ensures this traversal visits every intended window. Inspect the first batch's inputs and targets together and record all visited window indices. Shuffling changes order, not target alignment or source membership. Integer token IDs use torch.long; they are not floating embeddings yet. The targets are already shifted by the dataset, so a later from-scratch training function must consume them under that contract. Batching is a transport mechanism, not a second tokenizer, split or target-shift operation. Keep those responsibilities separate when debugging a model that appears to train but receives the wrong examples.

Try it

  1. Implement indexed access to complete training windows.
  2. Batch and shuffle with a local seeded generator.
  3. Check first-batch alignment and full-traversal example coverage.
Python · run in order
vocabulary,merges,history = fit_byte_merges(training_texts,8)
pairs = []
for text in training_texts:
    ids = encode_bytes(text,merges)
    for start in range(0,len(ids)-5,3):
        pairs.append((ids[start:start+5],ids[start+1:start+6]))
class WindowDataset(Dataset):
    def __init__(self,pairs):
        self.pairs = pairs
    def __len__(self):
        return len(self.pairs)
    def __getitem__(self,index):
        x,y = self.pairs[index]
        return torch.tensor(x,dtype=torch.long),torch.tensor(y,dtype=torch.long),index
dataset = WindowDataset(pairs)
loader = DataLoader(dataset,batch_size=3,shuffle=True,drop_last=False,num_workers=0,generator=torch.Generator().manual_seed(104))
batches = list(loader)
first_x,first_y,first_indices = batches[0]
visited = [int(index) for _,_,indices in batches for index in indices]
fig, axes = plt.subplots(1,2,figsize=(10,3.5))
for ax,tensor,title in zip(axes,[first_x,first_y],["First batch inputs","Corresponding shifted targets"]):
    im = ax.imshow(np.zeros_like(tensor.numpy()),cmap="Blues",aspect="auto",vmin=0,vmax=1)
    ax.set_xticks(range(5))
    ax.set_yticks(range(len(tensor)),[f"window {int(index)}" for index in first_indices])
    for row in range(tensor.shape[0]):
        for column in range(5):
            ax.text(column,row,str(int(tensor[row,column])),ha="center",va="center",fontsize=8)
    ax.set(xlabel="Position",title=title)
fig.tight_layout()

Read the result

Each row keeps its corresponding shifted target after shuffling. The visited-index audit confirms coverage even when the final batch is smaller than the requested batch size.

  • Recreate the loader with a fresh generator using the same seed and compare its index order.
