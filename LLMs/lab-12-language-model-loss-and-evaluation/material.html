Language-Model Loss and Evaluation

MaterialPracticeQuiz

Turn next-token scores into an objective you can measure correctly. You will trace target alignment, padding and evaluation denominators before interpreting any loss value.

What you will learn

  • Shift inputs and targets exactly once within document boundaries.
  • Compute stable token cross-entropy and ignore only padding targets.
  • Aggregate held-out loss by supervised token count.
  • Distinguish loss, perplexity and evidence of useful language behavior.

Before this lab: Use the small GPT forward pass, logits, softmax and train/eval modes.

import math
import json

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
import matplotlib.pyplot as plt
torch.set_num_threads(1)
torch.manual_seed(112)
rng = np.random.default_rng(112)
def as_array(tensor):
    return tensor.detach().cpu().numpy()
class CausalHeads(nn.Module):
    def __init__(self, width=16, heads=4, dropout=0.0):
        super().__init__()
        if width % heads:
            raise ValueError("width must be divisible by heads")
        self.width, self.heads, self.head_dim = width, heads, width // heads
        self.qkv = nn.Linear(width, 3*width, bias=False)
        self.proj = nn.Linear(width, width, bias=False)
        self.attn_drop = nn.Dropout(dropout)
    def forward(self, x):
        b,t,c = x.shape
        packed = self.qkv(x).reshape(b,t,3,self.heads,self.head_dim)
        q,k,v = packed.permute(2,0,3,1,4).unbind(0)
        scores = (q @ k.transpose(-2,-1)) / math.sqrt(self.head_dim)
        future = torch.triu(torch.ones(t,t,device=x.device,dtype=torch.bool),diagonal=1)
        weights = scores.masked_fill(future,float("-inf")).softmax(dim=-1)
        context = self.attn_drop(weights) @ v
        merged = context.transpose(1,2).contiguous().reshape(b,t,c)
        return self.proj(merged), weights
class FeedForward(nn.Module):
    def __init__(self,width=16,expansion=4):
        super().__init__()
        self.up = nn.Linear(width,expansion*width)
        self.act = nn.GELU()
        self.down = nn.Linear(expansion*width,width)
    def forward(self,x):
        return self.down(self.act(self.up(x)))
class TransformerBlock(nn.Module):
    def __init__(self,width=16,heads=4,dropout=0.0):
        super().__init__()
        self.norm1 = nn.LayerNorm(width)
        self.attention = CausalHeads(width,heads,dropout)
        self.norm2 = nn.LayerNorm(width)
        self.ff = FeedForward(width)
        self.drop = nn.Dropout(dropout)
    def forward(self,x):
        x = x + self.drop(self.attention(self.norm1(x))[0])
        return x + self.drop(self.ff(self.norm2(x)))
class TinyGPT(nn.Module):
    def __init__(self,vocab_size,context=12,width=16,heads=4,layers=2,dropout=0.0):
        super().__init__()
        self.config = dict(vocab_size=vocab_size,context=context,width=width,heads=heads,layers=layers,dropout=dropout)
        self.token = nn.Embedding(vocab_size,width)
        self.position = nn.Embedding(context,width)
        self.drop = nn.Dropout(dropout)
        self.blocks = nn.ModuleList([TransformerBlock(width,heads,dropout) for _ in range(layers)])
        self.final_norm = nn.LayerNorm(width)
    def forward(self,ids):
        if ids.ndim != 2 or ids.shape[1] == 0 or ids.shape[1] > self.config["context"]:
            raise ValueError("Expected nonempty B,T IDs within context")
        positions = torch.arange(ids.shape[1],device=ids.device)
        x = self.drop(self.token(ids) + self.position(positions)[None])
        for block in self.blocks:
            x = block(x)
        x = self.final_norm(x)
        return F.linear(x,self.token.weight)  # Tied input/output weights.
vocab = ["<pad>","<eos>","<unk>","library","opens","at","nine","ten","room","is","free","busy","please","return","the","book","today","tomorrow","desk","closes","six","seven","reserve","a","quiet","seat","now"]
stoi = {word:i for i,word in enumerate(vocab)}
def encode(text,eos=False):
    ids = [stoi.get(word,stoi["<unk>"]) for word in text.lower().split()]
    return ids + ([stoi["<eos>"]] if eos else [])
def decode(ids):
    return " ".join(vocab[int(i)] for i in ids)
train_documents = ["library opens at nine","please return the book today","room is free today","reserve a quiet seat","desk closes at six","room is busy now"]
validation_documents = ["library closes at seven","please return the book tomorrow"]
test_documents = ["room is free tomorrow","desk opens at ten"]
# Shift exactly once. Padding is outside each document's true target positions.
def make_batch(documents):
    sequences = [encode(text,eos=True) for text in documents]
    if not sequences or any(len(sequence)<2 for sequence in sequences):
        raise ValueError("Need nonempty documents with at least one word")
    lengths = torch.tensor([len(sequence) for sequence in sequences])
    padded = torch.full((len(sequences),int(lengths.max())),stoi["<pad>"],dtype=torch.long)
    for row,sequence in enumerate(sequences):
        padded[row,:len(sequence)] = torch.tensor(sequence)
    inputs = padded[:,:-1].clone()
    targets = padded[:,1:].clone()
    valid = torch.arange(targets.shape[1])[None] < (lengths-1)[:,None]
    targets[~valid] = -100
    return inputs,targets

Guided task 01

Documents Before Training Windows

A next-token dataset can produce many overlapping windows from one document. Those windows remain related examples, so assign whole documents or broader source groups before creating them. Randomly splitting the windows afterwards can place nearly identical text in training and validation, making the evaluation question misleading. Exact duplicates and related announcements also need a grouping policy in a real collection.

The setup provides separate original lists for training, validation and final test. We inspect token counts to understand batching, without fitting a tokenizer or selecting settings from the final test text. The word vocabulary was fixed in advance for these constructed examples. This tiny collection is useful for verifying mechanics, not for claiming representative language performance. Keeping data roles explicit now prevents a later training loop from quietly using validation examples as extra updates or treating repeated test inspection as harmless exploration.

Try it

  1. Review the assigned document lists.
  2. Count tokens including EOS within training and validation.
  3. Keep final-test documents outside all guided evaluation calls.

train_lengths = [len(encode(text,eos=True)) for text in train_documents]
val_lengths = [len(encode(text,eos=True)) for text in validation_documents]
fig,ax=plt.subplots(figsize=(8,3.4))
lengths=train_lengths+val_lengths
labels=[f"train {i}" for i in range(len(train_lengths))]+[f"val {i}" for i in range(len(val_lengths))]
ax.bar(range(len(lengths)),lengths,color=["#477fa1"]*len(train_lengths)+["#bf854c"]*len(val_lengths))

Document lengths determine how many prediction targets each example contributes. They do not determine how much an example should matter to an application, but they must be accounted for when reporting a token-averaged language-model loss.

Guided task 02

Shift Once and Preserve EOS

For a document ending in EOS, inputs omit the final token and targets omit the first token. Each input position therefore predicts the following token, including EOS after the last word. The from-scratch TinyGPT returns unshifted logits at every input position; it does not perform another label shift internally. Passing already aligned targets to a second shifting routine would move the task two positions ahead.

Batching documents of different lengths adds right padding. The setup make_batch helper marks only positions beyond each document's real shifted targets with −100. EOS remains an ordinary supervised target, while padding is excluded. Because padding is on the right and attention is causal, valid earlier queries cannot read those later padding keys. Padded query outputs can still exist, but they contribute no loss. This is a specific right-padding contract, not a general solution for arbitrary left padding or every attention implementation.

Try it

  1. Batch one shorter and one longer document.
  2. Inspect input IDs and shifted target IDs.
  3. Distinguish genuine EOS targets from ignored padding.
Python · run in order
inputs,targets = make_batch([train_documents[0],train_documents[1]])
fig,axes=plt.subplots(2,1,figsize=(9,3.8))
for ax,values,title in zip(axes,[inputs,targets],["Input IDs","Next-token targets (-100 = ignore)"]):
    artist=ax.imshow(as_array(values!=-100),aspect="auto",cmap="Blues",vmin=0,vmax=1)
    ax.set(title=title,xlabel="Position",ylabel="Document")
    ax.set_xticks(range(values.shape[1]))
    ax.set_yticks(range(values.shape[0]))

Read across each row as a prediction alignment. The shorter document still teaches its last word to predict EOS, then stops contributing targets. An ignored location is a batching artifact rather than a missing word to infer.

Guided task 03

Cross-Entropy on Vocabulary Logits

Cross-entropy receives raw vocabulary logits and integer target IDs. It combines a numerically stable log-softmax with selection of the target coordinate, so applying softmax first is unnecessary and changes the expected input contract. Flatten batch and time together while keeping vocabulary as the last dimension. The flattened target order must match that same batch-time ordering.

Request unreduced losses to inspect every prediction site, using ignore_index=−100 for the padded targets. The ignored entries contribute zero to the summed loss and must also be excluded from the denominator. A mean across the entire padded grid would dilute the metric for shorter documents. Backpropagate the supervised-token mean through the small model to verify a real training path, but do not step an optimizer yet. The measured loss belongs to random weights and the supplied examples, not to a trained assistant.

Try it

  1. Run TinyGPT on the aligned input batch.
  2. Compute unreduced cross-entropy with ignored padding.
  3. Average over valid targets and backpropagate once.
Python · run in order
model = TinyGPT(len(vocab),context=12,width=16,heads=4,layers=2,dropout=0)
logits = model(inputs)
token_losses = F.cross_entropy(logits.reshape(-1,len(vocab)),targets.reshape(-1),ignore_index=-100,reduction="none").reshape_as(targets)
valid = targets!=-100
loss = token_losses.sum()/valid.sum()
model.zero_grad(set_to_none=True)
loss.backward()
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(token_losses)
artist = ax.imshow(shown,cmap="viridis",aspect="auto")
ax.set(title="Measured next-token losses",xlabel="Position",ylabel="Document")
ax.set_xticks(range(shown.shape[1]))
ax.set_yticks(range(shown.shape[0]))
fig.colorbar(artist,ax=ax,label="Value")
fig.tight_layout()

Read the result

Different target positions can have very different losses. A zero cell at an ignored location means excluded supervision, not a perfect prediction. The reported mean uses exactly the positions that contribute to its numerator.

Guided task 04

Negative Log-Likelihood and Stability

The loss for a target is the negative logarithm of its predicted probability. A more probable target has a smaller loss, but the complete score depends on the entire vocabulary normalization. Work through supplied logits and target IDs using log_softmax followed by gather. This reconstructs cross-entropy while keeping the target-selection step visible.

One row has logits near 1000 to demonstrate numerical stability. Direct exponentiation can overflow even though differences among logits are modest. Log-softmax evaluates the equivalent normalized quantity stably; adding the same constant to every logit in a row does not change the distribution or its loss. These fixed rows are arithmetic fixtures, not model outputs. Comparing the manual calculation against cross_entropy verifies the formula without presenting fabricated accuracy or training results. Use natural logarithms, so the resulting loss is measured in nats per supervised token.

Try it

  1. Create two supplied logit rows and targets.
  2. Select target log probabilities with gather.
  3. Compare with cross_entropy and a constant-shifted version.
Python · run in order
example_logits = torch.tensor([[2.,0.,-1.],[1000.,1001.,999.]],dtype=torch.float64)
example_targets = torch.tensor([0,2])
log_probabilities = F.log_softmax(example_logits,dim=-1)
nll = -log_probabilities.gather(1,example_targets[:,None]).squeeze(1)
reference_loss = F.cross_entropy(example_logits,example_targets,reduction="none")
shifted_loss = F.cross_entropy(example_logits+5000,example_targets,reduction="none")
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(["Fixture row 0","Fixture row 1"],as_array(nll))
ax.set(title="Stable target negative log-likelihood",ylabel="Nats")
fig.tight_layout()

Read the result

Large absolute logits do not automatically mean high confidence; relative differences determine softmax. The constant shift changes stored scores dramatically while preserving both probabilities and target losses.

  • Subtract each row's maximum before a manual softmax and compare probabilities.
  • Change only the target ID to distinguish probability construction from target selection.

Guided task 05

Token-Weighted Evaluation Across All Batches

A validation collection can contain batches with unequal numbers of supervised tokens. Averaging batch means gives each batch equal influence rather than each token equal influence. Instead accumulate summed cross-entropy and the corresponding valid-target count, then divide once after every intended batch has been processed. A final short batch must not be silently dropped.

The evaluation function below switches to eval mode, runs under no_grad and restores the caller's original mode afterwards. It uses the same document batching and target convention as training. Compare batch sizes one and two on the same held-out list; the token-weighted result should agree within floating-point tolerance. This is a metric implementation check, not a reason to change validation content until a desirable number appears. A separate final test remains unused during these demonstrations.

Try it

  1. Evaluate every validation document in batches.
  2. Accumulate loss sums and valid-token counts.
  3. Compare results under two batch sizes.
Python · run in order
def evaluate(model,documents,batch_size):
    if not documents or batch_size<=0:
        raise ValueError("Need documents and positive batch size")
    previous = model.training
    model.eval()
    loss_sum,count = 0.0,0
    try:
        with torch.no_grad():
            for start in range(0,len(documents),batch_size):
                batch_x,batch_y = make_batch(documents[start:start+batch_size])
                batch_logits = model(batch_x)
                batch_loss = F.cross_entropy(batch_logits.reshape(-1,len(vocab)),batch_y.reshape(-1),ignore_index=-100,reduction="sum")
                loss_sum += float(batch_loss)
                count += int((batch_y!=-100).sum())
    finally:
        model.train(previous)
    return loss_sum/count,count
loss_one,count_one = evaluate(model,validation_documents,1)
loss_two,count_two = evaluate(model,validation_documents,2)
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(["Batch size 1","Batch size 2"],[loss_one,loss_two])
ax.set(title="Same token-weighted validation objective",ylabel="Nats per supervised token")
fig.tight_layout()

Read the result

The two bars answer the same metric question despite different batching. The returned token count makes the denominator auditable and helps detect missing documents, ignored EOS targets or accidental padding contributions.

Change and compare

  • Evaluate a three-document training subset with batch size two and retain the final short batch.
  • Construct unequal batch token counts and compare token weighting with an unweighted mean of means.

Guided task 06

Evaluation Mode and Graph Recording

Evaluation requires two distinct controls in this architecture. eval disables dropout behavior, while no_grad avoids building graphs for a metric that will not be backpropagated. Neither one automatically performs the other's job. The evaluation helper uses both and restores the previous mode, so a training loop can call it without accidentally leaving dropout disabled for subsequent updates.

Create a model with dropout 0.3 and leave it in train mode. Compare a single no_grad training-mode loss with two calls to the evaluation helper. The training-mode value can depend on the sampled dropout mask, while repeated evaluation should be stable for unchanged weights and data. Do not interpret a difference between these values as immediate evidence of overfitting: the model mode changed the computation. Learning curves need a clearly defined and consistent measurement procedure.

Try it

  1. Measure one training-mode forward without gradients.
  2. Run the deterministic evaluation helper twice.
  3. Verify that the helper restores training mode.
Python · run in order
drop_model = TinyGPT(len(vocab),context=12,width=16,heads=4,layers=2,dropout=.3)
drop_model.train()
batch_x,batch_y = make_batch(validation_documents)
with torch.no_grad():
    raw_logits = drop_model(batch_x)
    train_mode_loss = float(F.cross_entropy(raw_logits.reshape(-1,len(vocab)),batch_y.reshape(-1),ignore_index=-100))
eval_loss_a,_ = evaluate(drop_model,validation_documents,2)
eval_loss_b,_ = evaluate(drop_model,validation_documents,2)
mode_restored = drop_model.training
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(["Train mode","Eval call 1","Eval call 2"],[train_mode_loss,eval_loss_a,eval_loss_b])
ax.set(title="Mode-controlled metric calls",ylabel="Nats per supervised token")
fig.tight_layout()

Read the result

The repeated evaluation values should agree. The training-mode value is a differently configured computation, even though it uses the same held-out text. No gradients or optimizer updates are taken from these validation calls.

Change and compare

  • Check requires_grad on outputs computed inside no_grad.
  • Start the helper from eval mode and verify that it restores eval rather than always forcing train.

Guided task 07

Perplexity and a Uniform Baseline

Perplexity is the exponential of mean next-token negative log-likelihood when the loss uses natural logarithms. It summarizes the geometric average inverse probability assigned to the observed targets. A uniform distribution over V tokens has loss log(V) and perplexity V, regardless of which in-vocabulary target appears.

Compute both the actual untrained-model validation perplexity and the uniform-vocabulary baseline. They are comparable here because they use the same vocabulary and target positions. Perplexities from different tokenizers are not directly comparable without considering their different prediction units. A lower held-out loss under a fixed protocol is useful evidence about that objective, but neither loss nor perplexity guarantees factual accuracy, safety or instruction-following quality. The tiny constructed documents are for checking arithmetic and workflow, not for ranking practical language systems.

Try it

  1. Convert the measured validation loss using exp.
  2. Compute the uniform baseline for the same vocabulary.
  3. Display both on a labeled logarithmic scale.
Python · run in order

ax.bar(["Untrained model","Uniform vocabulary"],[perplexity,uniform_perplexity])

ax.set(ylabel="Perplexity (log axis)",title="Same-vocabulary reference comparison")

The measured random-model result may be worse than uniform because its logits can assign very low probability to some targets. The baseline is a mathematical reference, not an invented trained-model score.

Guided task 08

Alignment Regression Tests

A small synthetic logit fixture can test label alignment independently of the model. Create logits that deliberately favor the correct next token at every position of one known sequence. The loss should be much lower under the intended shifted targets than under the current input IDs used incorrectly as targets. This test makes a one-position bug visible without needing a trained network.

The supplied fixture is explicitly constructed for this diagnostic; its low loss is not a model achievement. Keep EOS in the target row so the test also checks document termination supervision. A second shift or an unshifted target can still produce legal tensor shapes and finite losses, so those properties alone do not establish correctness. Save a transparent alignment test alongside metric tests when refactoring data loaders or adopting an API that performs its own internal label shift.

Try it

  1. Build one correctly shifted library sequence.
  2. Construct diagnostic logits favoring those targets.
  3. Compare aligned and deliberately unshifted losses.
Python · run in order
check_x,check_y = make_batch(["library opens at nine"])
diagnostic = torch.full((1,4,len(vocab)),-3.)
diagnostic.scatter_(2,check_y[...,None],3.)
aligned_loss = F.cross_entropy(diagnostic.reshape(-1,len(vocab)),check_y.reshape(-1))
unshifted_loss = F.cross_entropy(diagnostic.reshape(-1,len(vocab)),check_x.reshape(-1))
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(["Correct shift","Fault: current token"],[float(aligned_loss),float(unshifted_loss)])
ax.set(title="Constructed alignment diagnostic",ylabel="Cross-entropy nats")
fig.tight_layout()

Read the result

The deliberately favorable logits reveal whether the data pipeline asks the intended question. The chart is labeled as a constructed diagnostic so it cannot be mistaken for a training result or held-out model performance.

  • Describe how this test must change for an API that shifts labels internally.
