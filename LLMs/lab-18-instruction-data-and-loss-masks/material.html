Instruction Data and Loss Masks

MaterialPracticeQuiz

Make a short request and its desired reply into an inspectable learning example. You will trace exactly which tokens contribute to the objective before training a model.

import copy, json, re, tempfile
from pathlib import Path
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
import matplotlib.pyplot as plt
torch.set_num_threads(1)
torch.manual_seed(118)
# Fixed character vocabulary: never fitted on held-out responses.
characters = '\n' + ''.join(chr(i) for i in range(32,127))
char_to_id = {character:i+3 for i,character in enumerate(characters)}
id_to_char = {value:key for key,value in char_to_id.items()}
BOS, EOS, PAD = 1, 2, 2
VOCAB_SIZE = len(char_to_id)+3
instruction_rows = [
    {'id':'train0','split':'train','input':'library','response':'bring a book'},
    {'id':'train1','split':'train','input':'park','response':'bring water'},
    {'id':'train2','split':'train','input':'rain','response':'bring an umbrella'},
    {'id':'train3','split':'train','input':'gym','response':'bring a towel'},
    {'id':'train4','split':'train','input':'school','response':'bring a book'},
    {'id':'train5','split':'train','input':'picnic','response':'bring water'},
    {'id':'train6','split':'train','input':'showers','response':'bring an umbrella'},
    {'id':'train7','split':'train','input':'swimming','response':'bring a towel'},
    {'id':'val0','split':'validation','input':'reading cafe','response':'bring a book'},
    {'id':'val1','split':'validation','input':'workout','response':'bring a towel'},
    {'id':'test0','split':'test','input':'hot day','response':'bring water'},
    {'id':'test1','split':'test','input':'wet weather','response':'bring an umbrella'},
]
for row in instruction_rows:
    row['instruction'] = 'name one useful item'
    row['group'] = row['id']  # Each supplied situation has one record.

def encode_text(text):
    if any(character not in char_to_id for character in text):
        raise ValueError('Only the declared character vocabulary is supported.')
    return [char_to_id[character] for character in text]

def format_prompt(row):
    return 'Task: '+row['instruction']+'\nInput: '+row['input']+'\nReply: '

def instruction_parts(row):
    response = row['response'].strip()
    if not response:
        raise ValueError('A response must contain visible text.')
    prefix = [BOS]+encode_text(format_prompt(row))
    target = encode_text(response)+[EOS]
    return prefix,target

def pack_instructions(rows,max_length=128):
    if not rows:
        raise ValueError('Cannot collate an empty batch.')
    parts = [instruction_parts(row) for row in rows]
    lengths = [len(prefix)+len(target) for prefix,target in parts]
    if any(length>max_length for length in lengths):
        raise ValueError('Complete response and EOS must fit; shorten or reject the record.')
    ids = torch.full((len(rows),max(lengths)),PAD,dtype=torch.long)
    valid = torch.zeros_like(ids,dtype=torch.bool)
    labels = torch.full_like(ids,-100)
    for i,(prefix,target) in enumerate(parts):
        sequence = prefix+target
        ids[i,:len(sequence)] = torch.tensor(sequence)
        valid[i,:len(sequence)] = True
        labels[i,len(prefix):len(sequence)] = torch.tensor(target)
    return ids,valid,labels
# Small plotting helpers display measured tensors and counts.
def bar_plot(labels, values, title, ylabel):
    fig, ax = plt.subplots(figsize=(7, 3.5))
    ax.bar(labels, np.asarray(values))
    ax.set(title=title, ylabel=ylabel)
    if np.all(np.asarray(values)==0):
        ax.set_ylim(0,1)
        ax.text(0.5,0.5,'All values are zero',transform=ax.transAxes,ha='center')
    fig.tight_layout()
    return fig

def heat_plot(values, title, xlabel, ylabel, label):
    array = values.detach().cpu().numpy() if isinstance(values, torch.Tensor) else np.asarray(values)
    fig, ax = plt.subplots(figsize=(7, 3.5))
    if np.any(array < 0):
        bound = max(float(np.abs(array).max()), 1e-8)
        view = ax.imshow(array, aspect='auto', interpolation='nearest', cmap='coolwarm', vmin=-bound, vmax=bound)
    else:
        view = ax.imshow(array, aspect='auto', interpolation='nearest', cmap='viridis', vmin=0, vmax=max(float(array.max()),1e-8))
    ax.set_xticks(np.unique(np.linspace(0,array.shape[1]-1,min(8,array.shape[1])).astype(int)))
    ax.set_yticks(np.unique(np.linspace(0,array.shape[0]-1,min(8,array.shape[0])).astype(int)))
    ax.set(title=title, xlabel=xlabel, ylabel=ylabel)
    fig.colorbar(view, ax=ax, label=label)
    fig.tight_layout()
    return fig

Guided task 01

Separate the request from its desired reply

An instruction record contains a task description, an input situation and a desired response. The task here asks for one useful item to take somewhere. A library visit is paired with bringing a book; rain is paired with bringing an umbrella. These are small constructed examples for inspecting data preparation, not a comprehensive advice service. Their responses are selected references rather than claims that only one answer could ever be reasonable.

The formatter puts the instruction and input into a reproducible prompt ending in Reply followed by a colon and space. The desired response stays in a separate field until training collation. At generation time, only the prompt is available. Keeping that boundary explicit prevents accidental evaluation with the answer already supplied. Each supplied situation has its own group and preassigned role. If multiple phrasings were later added, all versions of a situation would inherit that group and split. Count prompt characters and response characters independently before thinking about model capacity: their lengths play different roles in the objective and generation budget.

Try it

  1. Format the first four training requests without their responses.
  2. Count prompt and response characters separately.
  3. Plot measured lengths while preserving record order.
Python · run in order
rows=instruction_rows[:4]
prompts=[format_prompt(row) for row in rows]
prompt_lengths=[len(prompt) for prompt in prompts]
response_lengths=[len(row['response']) for row in rows]
fig,ax=plt.subplots(figsize=(7,3.5))
x=np.arange(len(rows))
ax.bar(x-0.18,prompt_lengths,width=0.36,label='Prompt')

ax.set(xticks=x,xticklabels=[row['input'] for row in rows],ylabel='Characters',title='Request and reply have separate roles')

Guided task 02

Make the token boundary explicit

Our fixed vocabulary contains a newline and the printable ASCII characters. It is declared independently of these examples, so reading validation text does not fit a vocabulary on held-out data. A beginning marker uses ID one and an end marker uses ID two. Zero is reserved and not used as a character. This compact scheme is intentionally different from GPT-2 subwords; it makes every formatting character and boundary visible on a short sequence.

instruction_parts returns two lists. The prefix contains the beginning marker and formatted prompt. The target contains the response characters followed by EOS. The first response token therefore occupies position len(prefix) in the joined training sequence. Store this measured boundary rather than searching for a word inside decoded text, where the same word could occur in the request. A real subword tokenizer can merge text differently around spaces, so later extensions define how prompt and response segments are encoded. The essential requirement is a boundary that matches the actual token IDs supplied to the model.

Try it

  1. Encode one record into prefix and target lists.
  2. Join them without inserting an extra separator.
  3. Visualize which positions belong to each segment.
Python · run in order
prefix,target=instruction_parts(instruction_rows[0])
sequence=prefix+target
boundary=len(prefix)
roles=torch.zeros((1,len(sequence)),dtype=torch.long)
roles[:,boundary:]=1
roles[0,-1]=2
fig=heat_plot(roles,'Token roles: prompt 0, response 1, EOS 2','Sequence position','Record','Role code')

Read the result

The first response position comes from encoding the declared prompt. EOS is part of the target even though it does not decode to a visible character.

Guided task 03

Distinguish EOS from storage padding

A batch needs a rectangular tensor even when complete examples have different lengths. This lab fills unused positions with the EOS ID, matching a common decoder-only padding arrangement. The final real EOS and an unused padded slot consequently have the same numeric value. Comparing IDs with EOS cannot tell which position represents meaningful termination.

The validity mask records sequence membership instead. True means the position belongs to the complete example, including its real EOS; false means it is storage padding. A separate labels tensor decides where loss is supervised. Prompt positions are valid but ignored by this objective. The final EOS is both valid and supervised. Padded positions are invalid and ignored. These two decisions must remain separate throughout collation, attention and loss calculation. Removing all EOS-valued labels would remove the termination signal we want the model to learn. Allowing all EOS-valued slots to contribute would teach artificial repetitions determined by batch width rather than the actual response.

Try it

  1. Collate records with different complete lengths.
  2. Locate all EOS-valued input positions.
  3. Compare numeric identity, validity and supervision masks.
Python · run in order
ids,valid,labels=pack_instructions(instruction_rows[:4])
eos_identity=ids==EOS
fig,axes=plt.subplots(1,3,figsize=(11,3.5))
for ax,values,title in zip(axes,[eos_identity,valid,labels!=-100],['ID equals EOS','Valid sequence position','Supervised target']):
    ax.imshow(values.numpy(),aspect='auto',interpolation='nearest',vmin=0,vmax=1)
    ax.set(title=title,xlabel='Position',ylabel='Record',yticks=range(4))
fig.tight_layout()

Read the result

The genuine EOS appears inside each valid sequence; additional EOS IDs can appear outside it. Only the real endpoint contributes a termination target.

Guided task 04

Shift next-token targets once

A causal logit at sequence position t predicts the token at t plus one. Our local model returns one logit vector at every input position without shifting anything internally. Training must therefore pair logits excluding the last position with labels excluding the first position. The response mask travels with those labels. The last prompt position predicts the first response character, and the last response character predicts EOS.

The small alignment below uses invented token IDs so the offset is easy to see. Its prefix has three positions, followed by two response tokens and EOS. Ignored prompt labels remain ignored after the shift. Dropping the first response label by applying an extra shift would train the wrong prediction task. This implementation rule is model-specific: Hugging Face GPT2LMHeadModel performs the shift inside its loss when full labels are supplied. The later pretrained extension therefore gives that API unshifted labels. Confirm where shifting happens before reusing a loss function, rather than assuming every model interface has the same contract.

Try it

  1. Construct the six-position illustrative training sequence.
  2. Shift its labels once to match prediction positions.
  3. Plot the supervised prediction positions rather than target positions.
Python · run in order
toy_ids=torch.tensor([[1,10,11,20,21,2]])
toy_labels=torch.tensor([[-100,-100,-100,20,21,2]])
shifted=toy_labels[:,1:]
prediction_positions=torch.arange(toy_ids.shape[1]-1)
supervised_positions=prediction_positions[shifted[0]!=-100]
fig=heat_plot((shifted!=-100).long(),'Which logit positions predict response tokens?','Logit position','Toy record','Supervised: 1')

Read the result

The first supervised logit lies at the last prompt position. The target EOS is paired with the final visible response character, not a padded position.

Guided task 05

Protect the complete response budget

A context limit is a data policy as well as a tensor shape. Truncating a joined sequence blindly can remove every response token, or remove EOS while retaining a misleading partial target. The supplied collator takes a simple conservative policy: the entire prompt, complete nonempty response and EOS must fit. Otherwise it raises an error and asks the data preparer to shorten or reject the record.

This policy avoids silently changing the desired answer. Other applications may support carefully defined truncation, but must preserve usable supervision and account for what was removed. A sequence containing only prompt tokens contributes no response objective. A sequence containing only EOS as its response teaches termination without the requested content. Neither is accepted as a valid replacement for these examples. Inspect the measured lengths before choosing a budget, and keep the same declared policy for training and held-out loss. An error at collation is easier to diagnose than an unexplained empty-loss batch several steps later.

Try it

  1. Measure each complete training sequence length.
  2. Try a budget of eight positions and capture the rejection.
  3. Verify that a budget of 128 accepts the supplied records.
Python · run in order
training_rows=[row for row in instruction_rows if row['split']=='train']
complete_lengths=[sum(map(len,instruction_parts(row))) for row in training_rows]

Guided task 06

Audit collation with position-level invariants

A collator is easiest to trust when its result can be checked independently for every row. The expected supervised target count is the number of encoded response characters plus one EOS. It does not include the prompt and does not grow when padding width grows. The final valid input position must be the genuine EOS, and its label must also remain EOS.

Check the prefix and suffix separately. All prefix labels must be ignored, but the corresponding input positions remain valid. Every target label must match the input token at the same unshifted position. All remaining labels must be ignored. These checks use the formatter and recorded lengths; they are not learned predictions. They can catch an off-by-one error before training obscures it behind a decreasing loss. Validation records use the same transformation with their own measured boundaries. Although this lab uses right padding, the assertions are not a license to switch to left padding without revisiting position indices and the generation policy.

Try it

  1. Collate the two validation records using the same helper.
  2. Count target tokens independently from response lengths.
  3. Compare expected and measured counts per record.
Python · run in order
validation_rows=[row for row in instruction_rows if row['split']=='validation']
ids,valid,labels=pack_instructions(validation_rows)
measured=(labels!=-100).sum(1)
expected=torch.tensor([len(encode_text(row['response']))+1 for row in validation_rows])
for i,row in enumerate(validation_rows):
    prefix,target=instruction_parts(row)
    assert torch.all(labels[i,:len(prefix)]==-100)
    assert labels[i,len(prefix):len(prefix)+len(target)].tolist()==target
fig,ax=plt.subplots(figsize=(7,3.5))
x=np.arange(len(validation_rows))
ax.bar(x-0.18,expected.numpy(),width=0.36,label='Expected')
ax.bar(x+0.18,measured.numpy(),width=0.36,label='Measured')
ax.set(xticks=x,xticklabels=['val0','val1'],ylabel='Supervised tokens',title='Target count audit')

Counts agree because the objective follows response content and one real termination token. The two bars are an audit of preparation, not a model accuracy measure.

Guided task 07

Inspect gradients under the response objective

The loss mask determines which output prediction positions have a direct cross-entropy term. To inspect that property without a trained model, create an independent tensor of random logits and ask autograd for its gradient. Ignored target positions should have zero gradient with respect to these logits. Supervised positions should contribute finite gradients. Divide the summed loss by the actual number of supervised shifted targets.

This experiment concerns output logits, not a promise that prompt embeddings receive no gradient in a transformer. A response prediction attends to prompt representations, so its error can propagate through that context into earlier computations. Ignoring prompt labels removes direct prompt-prediction terms; it does not erase the request from the network. Similarly, attention padding masks and loss masks solve different problems. Keep the distinction explicit when interpreting gradient plots. A finite scalar loss is necessary but insufficient evidence of correct preparation: it can still be finite when the wrong positions are supervised, which is why the earlier boundary audits matter.

Try it

  1. Create random logits for the audited validation batch.
  2. Compute summed cross entropy over shifted response labels and normalize.
  3. Backpropagate and plot gradient magnitude at each logit position.
Python · run in order
logits=torch.randn(*ids.shape,VOCAB_SIZE,requires_grad=True)
targets=labels[:,1:]
count=int((targets!=-100).sum())
loss_sum=F.cross_entropy(logits[:,:-1].reshape(-1,VOCAB_SIZE),targets.reshape(-1),ignore_index=-100,reduction='sum')
loss=loss_sum/count
loss.backward()
gradient_magnitude=logits.grad.abs().sum(-1)
fig=heat_plot(gradient_magnitude,'Direct logit gradients follow the shifted response mask','Logit position','Record','Sum of absolute gradient')

Read the result

Nonzero gradient regions begin one position before the first response token. The unused final logit has no next-token target in this sequence.

Guided task 08

Keep training context separate from generation context

During teacher-forced training, the input sequence includes the reference response so each response position can use the preceding correct characters. The causal mask prevents it from seeing future characters. This is a computational way to score many next-token predictions at once; it is not permission to provide the whole answer during free generation.

At inference the model receives only the beginning marker and formatted request. It predicts a new token, appends that prediction, and repeats until EOS or an explicit budget stops it. The response must be extracted from newly generated token IDs, not by replacing a prompt substring in decoded text. The model may repeat prompt words legitimately. Preserve the formatter, vocabulary and special-token policy with any later checkpoint because those choices determine the input meaning. Our next lab uses exactly this contract for a small randomly initialized model and a separate real pretrained extension. The same boundaries apply even though the vocabularies and model sizes differ substantially.
