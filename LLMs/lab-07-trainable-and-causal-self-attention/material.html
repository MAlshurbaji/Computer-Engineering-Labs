Trainable and Causal Self-Attention

import numpy as np
import torch
from torch import nn
import matplotlib.pyplot as plt
torch.set_num_threads(1)
torch.manual_seed(107)
tokens = ['please', 'return', 'the', 'book']
features = torch.tensor([[1.,0.,0.5],[0.,1.,0.2],[0.3,0.2,1.],[0.8,0.4,0.]])
def array(tensor):
    return tensor.detach().cpu().numpy()

Guided task 01

Learned Query, Key and Value Projections

A token vector does not have to serve the same role in every attention calculation. A query describes the current position's comparison coordinates, a key supplies coordinates against which queries are compared, and a value supplies the content that will be combined. Three learned linear maps create these roles from the same input. The names describe their computational use; a random query is not yet a meaningful question in ordinary language.

The library message has four tokens, each with three supplied features. Projecting into two coordinates gives a four-by-two tensor for each role. PyTorch stores a Linear layer's weight as output features by input features, so the matrix has shape (2,3), and the forward operation corresponds to input @ weight.T. The same matrix acts at every token position. Its parameters are shared across positions, while the projected values differ because the inputs differ.

Create separate modules for Q, K and V, with biases disabled to make the accounting clear. There are three matrices with six parameters each. All are trainable, but initialization alone has not trained them. Inspecting the three plots should establish which axes survive the projection and which axis changes width. A later task will compute gradients and update these actual matrices.

Try it

  1. Create three independent Linear layers.
  2. Project the same feature matrix through each layer.
  3. Compare their outputs on one signed scale.
Python · run in order
query = nn.Linear(3,2,bias=False)
key = nn.Linear(3,2,bias=False)
value = nn.Linear(3,2,bias=False)
q, k, v = query(features), key(features), value(features)
parameter_count = sum(p.numel() for layer in [query,key,value] for p in layer.parameters())
fig,axes = plt.subplots(1,3,figsize=(11,3.4))
limit = max(float(z.detach().abs().max()) for z in [q,k,v])
for ax,z,name in zip(axes,[q,k,v],['Queries','Keys','Values']):
    view = ax.imshow(array(z),vmin=-limit,vmax=limit,cmap='coolwarm',aspect='auto')
    ax.set(xticks=[0,1],yticks=range(4),yticklabels=tokens,xlabel='Projected feature',title=name)
fig.colorbar(view,ax=axes.tolist(),label='Projected value')

Read the result

All three maps preserve token order. A common color scale lets you compare coordinates, but the colors do not identify learned grammatical roles: these maps have only been initialized.

Guided task 02

Scaled Scores and Unrestricted Context

A query-key dot product measures compatibility in the learned projection coordinates. For four queries and four keys, Q @ K.T produces a four-by-four score matrix. Row i belongs to query i, and column j belongs to source key j. Divide by the square root of the projected width, which is two here, before applying softmax across the key columns. Scaling moderates dot-product magnitude; it does not itself make the scores probabilities.

Multiply the resulting weights by V. This sums over source positions and leaves one value-width vector for each query. You can inspect one row manually as a weighted sum, then compare it with the matrix result. Changing a value affects the combined content through its weight, whereas changing a key affects compatibility scores and therefore can alter which values are emphasized.

This task deliberately allows every query to use every supplied key. That can be suitable when representing a complete input, but it violates the directional requirement of a decoder trained to predict unseen continuations. The word please can currently consult book even though book is later in the message. The next task changes permitted information flow while keeping the same learned projections, making the effect of masking directly comparable.

Try it

  1. Compute the scaled query-key scores.
  2. Normalize across keys, then multiply by values.
  3. Verify one context vector by an explicit sum.
Python · run in order
scores = (q @ k.T) / math.sqrt(q.shape[-1])
full_weights = scores.softmax(dim=-1)
full_context = full_weights @ v
manual_first = (full_weights[0,:,None] * v).sum(0)
fig,ax = plt.subplots(figsize=(6,4))
view = ax.imshow(array(full_weights),vmin=0,vmax=1,cmap='viridis')
ax.set(xticks=range(4),yticks=range(4),xticklabels=tokens,yticklabels=tokens,xlabel='Source key',ylabel='Query',title='Unrestricted attention weights')
fig.colorbar(view,ax=ax,label='Pre-dropout weight')
fig.tight_layout()

Read the result

Each row sums to one, but that alone does not make the computation causal. Positive weights above the diagonal show that earlier queries can use later values.

  • Reconstruct the third context vector as an explicit weighted sum.
  • Multiply all queries by five and inspect how the weight distribution changes.

Guided task 03

Causal Masking Before Softmax

A causal query may consult its own position and earlier positions. With query rows and key columns, forbidden pairs occupy the strictly upper triangle. Create a Boolean mask whose True entries mean forbidden, then replace those scores with negative infinity before softmax. The exponential of a forbidden score becomes zero, while allowed scores are normalized together.

Do not replace forbidden scores with zero: a zero score has an exponential of one and still receives weight. Likewise, removing weights after softmax without renormalizing generally changes the row sum. Masking the scores gives each row the intended distribution over allowed keys. The diagonal remains available, so every row in this unpadded example has at least one valid score and the normalization remains defined.

Keep the query, key and value parameters unchanged from the previous task. The difference in context vectors then comes entirely from the visibility rule. The first query has only one available key and must place weight one on it before dropout. Later queries have progressively larger sets of allowed sources. This is a constraint on information access, not a guarantee of factual output or useful language learning. Those properties require suitable data, training and evaluation.

Try it

  1. Mark strictly later source positions.
  2. Fill forbidden scores with negative infinity.
  3. Compare masked contexts with the unmasked computation.
Python · run in order
future = torch.triu(torch.ones(4,4,dtype=torch.bool),diagonal=1)
masked_scores = scores.masked_fill(future,float('-inf'))
causal_weights = masked_scores.softmax(-1)
causal_context = causal_weights @ v
context_change = (causal_context-full_context).abs().amax(1)
fig,axes = plt.subplots(1,2,figsize=(9,3.8))
view=axes[0].imshow(array(causal_weights),vmin=0,vmax=1,cmap='viridis')
axes[0].set(xticks=range(4),yticks=range(4),xticklabels=tokens,yticklabels=tokens,xlabel='Source key',ylabel='Query',title='Causal weights')
fig.colorbar(view,ax=axes[0],label='Weight')
axes[1].bar(tokens,array(context_change))
axes[1].set(ylabel='Maximum absolute context change',title='Effect of the visibility rule')
fig.tight_layout()

Read the result

The final query retains all four keys, so its context matches the unrestricted result. Earlier positions change because some previously available sources are excluded.

Change and compare

  • Change diagonal=1 to diagonal=0 and inspect the first row; explain why excluding every source is invalid here.
  • Compute the sum of weights after masking an already normalized matrix and compare it with the causal softmax result.

Guided task 04

Batched Causal Attention

A batch adds an example axis without allowing different messages to attend to one another. Stack the original token features with a second four-token feature sequence. Linear projections act on the final feature dimension, so each output has shape B,T,D. Transposing only the last two key dimensions forms one query-by-key matrix per example.

The product Q @ K.transpose(-2,-1) has shape B,T,T. A shared T-by-T causal mask can broadcast across B because both sequences use the same positional visibility rule. Softmax must still normalize the last axis, which represents source keys. Normalizing over the batch axis instead would make each example's result depend on the other examples present in the batch and would not implement self-attention within a message.

Both sequences have equal real lengths in this lesson, so no padding mask is needed. Unequal lengths require an additional validity policy; the causal mask alone does not distinguish real tokens from storage padding. Keep those concerns separate when you encounter batching in the classification and instruction labs. Here, compare the first batched result with the previously computed single-message result. Agreement verifies the intended broadcasting and axes for this particular equal-length calculation.

Try it

  1. Stack two equal-length feature sequences.
  2. Transpose the final key dimensions only.
  3. Compare the first batch member with its earlier single-message context.
Python · run in order
second = features * torch.tensor([0.8,1.2,1.]) + 0.1
batch = torch.stack([features,second])
bq,bk,bv = query(batch),key(batch),value(batch)
batch_scores = (bq @ bk.transpose(-2,-1)) / math.sqrt(2)
batch_weights = batch_scores.masked_fill(future,float('-inf')).softmax(-1)
batch_context = batch_weights @ bv
fig,axes = plt.subplots(1,2,figsize=(9,3.8))
for i,ax in enumerate(axes):
    view=ax.imshow(array(batch_weights[i]),vmin=0,vmax=1,cmap='viridis')
    ax.set(xticks=range(4),yticks=range(4),xlabel='Source position',ylabel='Query position',title=f'Message {i+1}')
fig.colorbar(view,ax=axes.tolist(),label='Pre-dropout attention weight')

Read the result

Each message gets its own weight matrix. Shared parameters and a shared visibility rule do not create cross-message attention; changing the second input leaves the first computation unchanged.

Change and compare

  • Append another equal-length message and check which tensor dimension grows.
  • Deliberately transpose the wrong axes, then explain either the shape error or the altered semantics.

Guided task 05

Attention Dropout and Evaluation

Attention dropout operates on the normalized weights during training. With dropout probability p, each retained entry is divided by 1−p, while dropped entries become zero. An individual row can therefore sum to a value other than one. Its expectation agrees with the original weight row under the sampling rule; expectation does not describe every realized matrix.

Apply dropout to a detached copy of the causal weights so this task isolates stochastic behavior from gradients. Detaching is a choice for this demonstration, not a requirement of trainable attention. Causal zeros remain zero because dropout multiplies entries rather than filling masked positions. A retained weight can exceed one, especially in the first row, which initially has just one source with weight one. Display the training and evaluation matrices on a common scale that includes the retained-value multiplier.

Switching the dropout module to eval disables this randomness and returns its input unchanged. Evaluation mode and gradient recording are independent controls: no_grad does not switch a model into evaluation mode, and eval does not prevent gradients. In training, dropout belongs inside the differentiable model path. During repeatable evaluation, normally use eval together with a gradient-disabling context. The next task temporarily omits dropout so an observed update cannot be confused with a different random mask.

Try it

  1. Apply dropout in training mode.
  2. Switch the same module to evaluation mode.
  3. Compare zeros, retained weights and row sums.
Python · run in order
drop = nn.Dropout(p=0.3)
drop.train()
train_weights = drop(causal_weights.detach())
drop.eval()
eval_weights = drop(causal_weights.detach())
row_sums = train_weights.sum(-1)
fig,axes=plt.subplots(1,2,figsize=(9,3.8))
for ax,z,title in zip(axes,[train_weights,eval_weights],['One training draw','Evaluation']):
    view=ax.imshow(array(z),vmin=0,vmax=1/0.7,cmap='viridis')
    ax.set(xticks=range(4),yticks=range(4),xlabel='Source position',ylabel='Query position',title=title)
fig.colorbar(view,ax=axes.tolist(),label='Post-dropout weight')
print('Training row sums:',row_sums.tolist())

Read the result

The training matrix is one sampled realization. Compare its printed row sums with the pre-dropout sums, and avoid treating this one pattern as a permanent learned preference.

Change and compare

  • Call the training-mode dropout twice and compare the retained entries.
  • Use dropout probability zero, then verify equality in both modes.

Guided task 06

Gradients and a Real Projection Update

Trainable projections become useful through a loss and an optimizer, not through their names. To inspect the mechanism without introducing language-model cross entropy early, use a deliberately simple objective: reduce the mean squared magnitude of the returned context vectors. This is an arithmetic exercise, not an objective that would teach a model to respond well to a library request.

Construct an optimizer from all three projection modules. Clear old gradients, recompute the forward path with the current parameters, calculate the scalar objective, call backward, and then perform one optimizer step. Recomputing the forward path matters because intermediate tensors from a previous notebook cell can belong to an old graph or outdated parameter values. Store parameter copies before the update so the comparison measures changes to actual learned state.

Gradients can reach Q and K through the attention weights and V through the value aggregation. Inspect their norms and the parameter differences separately. A nonzero gradient indicates sensitivity of this objective to that parameter; it does not measure a parameter's semantic importance. Gradient norms across differently sized tensors also require care when comparing magnitude. The chart reports what this one run computed. Later language-model training replaces the mechanics objective with next-token cross entropy and evaluates unseen text.

Try it

  1. Collect all three parameter matrices.
  2. Recompute a causal forward pass and backpropagate a scalar loss.
  3. Perform one step and compare parameter values.
Python · run in order
layers=[query,key,value]
parameters=[p for layer in layers for p in layer.parameters()]
optimizer=torch.optim.SGD(parameters,lr=0.05)
before=[p.detach().clone() for p in parameters]
optimizer.zero_grad(set_to_none=True)
new_q,new_k,new_v=query(features),key(features),value(features)
train_scores=(new_q@new_k.T)/math.sqrt(2)
train_attention=train_scores.masked_fill(future,float('-inf')).softmax(-1)
objective=(train_attention@new_v).square().mean()
objective.backward()
gradient_norms=[float(p.grad.norm()) for p in parameters]
optimizer.step()
changes=[float((p.detach()-old).norm()) for p,old in zip(parameters,before)]
fig,axes=plt.subplots(1,2,figsize=(9,3.5))
axes[0].bar(['Query','Key','Value'],gradient_norms)
axes[0].set(ylabel='Gradient norm',title='Sensitivity of the mechanics loss')
axes[1].bar(['Query','Key','Value'],changes)
axes[1].set(ylabel='Parameter-change norm',title='One SGD update')
fig.tight_layout()

Read the result

All three projection matrices participate in this objective. The parameter-change norms follow the stated SGD step size; useful language behavior has not been tested by this calculation.

Change and compare

  • Repeat with a fresh initialization and a smaller learning rate.
  • Omit zero_grad for two backward calls on fresh graphs and inspect gradient accumulation.

Guided task 07

A Reusable Causal Attention Module

Package the inspected operations into an nn.Module so projection matrices are registered and discoverable by an optimizer. Constructor arguments define input width, projected width and dropout probability. The forward method accepts a batch shaped B,T,C and returns context shaped B,T,D along with pre-dropout weights shaped B,T,T. Returning the pre-dropout weights makes row-sum checks meaningful even when training dropout is active.

Create the causal mask from the actual sequence length and on the input device. A CPU-only mask combined with GPU scores would cause a device mismatch. Use transpose on the final key axes so the method handles arbitrary batch size while keeping messages separate. A runtime check rejects empty sequences and incorrect feature width before those cases become obscure matrix errors. This minimal module expects every token position to be real and does not implement padding.

Copy the updated Q, K and V matrices into a fresh module and disable dropout. Compare its outputs with the same operations written outside the class. The class adds organization and parameter registration, not a new mathematical rule. Checking equality connects the compact implementation to the individual operations you have already inspected, and provides a useful starting point before the next lab introduces multiple heads and an output projection.

Try it

  1. Define and instantiate the module.
  2. Copy the current projection parameters.
  3. Compare context vectors under matching evaluation settings.
Python · run in order
class SingleHead(nn.Module):
    def __init__(self,input_width=3,head_width=2,dropout=0.0):
        super().__init__()
        self.q=nn.Linear(input_width,head_width,bias=False)
        self.k=nn.Linear(input_width,head_width,bias=False)
        self.v=nn.Linear(input_width,head_width,bias=False)
        self.drop=nn.Dropout(dropout)
    def forward(self,x):
        if x.ndim!=3 or x.shape[1]==0 or x.shape[-1]!=self.q.in_features:
            raise ValueError('Expected nonempty B,T,C with the configured feature width.')
        q,k,v=self.q(x),self.k(x),self.v(x)
        scores=(q@k.transpose(-2,-1))/math.sqrt(q.shape[-1])
        future=torch.triu(torch.ones(x.shape[1],x.shape[1],dtype=torch.bool,device=x.device),diagonal=1)
        weights=scores.masked_fill(future,float('-inf')).softmax(-1)
        return self.drop(weights)@v,weights
module=SingleHead().eval()
with torch.no_grad():
    for destination,source in zip([module.q,module.k,module.v],layers):
        destination.weight.copy_(source.weight)
    modular_context,modular_weights=module(features[None])
    direct_q,direct_k,direct_v=query(features),key(features),value(features)
    direct_weights=((direct_q@direct_k.T)/math.sqrt(2)).masked_fill(future,float('-inf')).softmax(-1)
    direct_context=direct_weights@direct_v
error=(modular_context[0]-direct_context).abs()
fig,ax=plt.subplots(figsize=(6,3.8))
view=ax.imshow(array(error),vmin=0,vmax=max(float(error.max()),1e-8),cmap='viridis',aspect='auto')
ax.set(xticks=[0,1],yticks=range(4),yticklabels=tokens,xlabel='Context feature',ylabel='Token',title='Module versus explicit computation')
fig.colorbar(view,ax=ax,label='Absolute difference')
fig.tight_layout()

Read the result

The modular and explicit computations agree for the same parameters. This check supports the stated equal-length input contract; padding and multiple heads still require additional design.

  • Create a module with four projected features and verify the output dimensions and new parameter count.

Guided task 08

Testing Future-to-Past Independence

A causal implementation should preserve earlier outputs when only a later suffix changes. This is stronger than visually checking that one saved mask looks triangular: the test exercises the complete forward path, including projections, matrix products and returned context. A hidden token-axis permutation could violate the intended behavior even when the mask variable itself is correct.

Keep the first two token vectors fixed and replace the final two vectors with clearly different values. Run both sequences through the same module in evaluation mode and under no_grad. The first two output context vectors should match, because their permitted keys and values are unchanged. Later outputs may change, since they can consult the changed positions. Use a small tolerance for floating-point comparison instead of demanding a particular output difference at every later position.

As a counterexample, compute the same two inputs with the same learned projections but omit masking. Earlier outputs can now react to the altered suffix. Compare maximum feature differences by query position for the causal and unrestricted paths. This diagnostic establishes a focused information-flow property; it is not a test of helpfulness, grammar or factual correctness. Keep such structural checks alongside later performance measurements, so a plausible generated sentence cannot hide an implementation that leaks future tokens during training.

Try it

  1. Modify only the final two input positions.
  2. Evaluate both visibility rules under fixed weights.
  3. Locate which outputs depend on the changed suffix.
Python · run in order
original=features[None]
modified=original.clone()
modified[:,2:]=torch.tensor([[[2.,-1.,0.],[0.,3.,-2.]]])
module.eval()
with torch.no_grad():
    causal_a,_=module(original)
    causal_b,_=module(modified)
    def unrestricted(x):
        q,k,v=module.q(x),module.k(x),module.v(x)
        return ((q@k.transpose(-2,-1))/math.sqrt(2)).softmax(-1)@v
    full_a=unrestricted(original)
    full_b=unrestricted(modified)
causal_delta=(causal_a-causal_b).abs().amax(-1)[0]
full_delta=(full_a-full_b).abs().amax(-1)[0]
fig,ax=plt.subplots(figsize=(8,3.8))
positions=np.arange(4)
ax.bar(positions-0.18,array(causal_delta),width=0.36,label='Causal')
ax.bar(positions+0.18,array(full_delta),width=0.36,label='Unrestricted')
ax.set(xticks=positions,xticklabels=tokens,ylabel='Maximum absolute context difference',title='Effect of changing the final two inputs')
ax.legend()
fig.tight_layout()

Read the result

Only the unrestricted path reacts to the changed suffix at the fixed prefix in this run. Later causal positions are allowed to change, so those differences do not indicate a causal failure.

Change and compare

  • Change only the final input and identify which prefix must remain invariant.
  • Enable dropout during this comparison and explain why unmatched random masks would confound the test.
