Building a Small GPT Model

MaterialPracticeQuiz

Connect the transformer blocks to token IDs and a vocabulary output. You will build a complete small GPT-style forward pass and inspect its behavior before any language-model training.

What you will learn

  • Trace token IDs through embeddings, blocks and vocabulary logits.
  • Preserve a consistent vocabulary and context contract.
  • Generate bounded continuations using the final-position logits.
  • Count tied parameters once and verify full-model causality.

import math
import json
import tempfile
from pathlib import Path
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
import matplotlib.pyplot as plt
torch.set_num_threads(1)
torch.manual_seed(111)
rng = np.random.default_rng(111)
def as_array(tensor):
    return tensor.detach().cpu().numpy()
class CausalHeads(nn.Module):
    def __init__(self, width=16, heads=4, dropout=0.0):
        super().__init__()
        if width % heads:
            raise ValueError("width must be divisible by heads")
        self.width, self.heads, self.head_dim = width, heads, width // heads
        self.qkv = nn.Linear(width, 3*width, bias=False)
        self.proj = nn.Linear(width, width, bias=False)
        self.attn_drop = nn.Dropout(dropout)
    def forward(self, x):
        b,t,c = x.shape
        packed = self.qkv(x).reshape(b,t,3,self.heads,self.head_dim)
        q,k,v = packed.permute(2,0,3,1,4).unbind(0)
        scores = (q @ k.transpose(-2,-1)) / math.sqrt(self.head_dim)
        future = torch.triu(torch.ones(t,t,device=x.device,dtype=torch.bool),diagonal=1)
        weights = scores.masked_fill(future,float("-inf")).softmax(dim=-1)
        context = self.attn_drop(weights) @ v
        merged = context.transpose(1,2).contiguous().reshape(b,t,c)
        return self.proj(merged), weights
class FeedForward(nn.Module):
    def __init__(self,width=16,expansion=4):
        super().__init__()
        self.up = nn.Linear(width,expansion*width)
        self.act = nn.GELU()
        self.down = nn.Linear(expansion*width,width)
    def forward(self,x):
        return self.down(self.act(self.up(x)))
class TransformerBlock(nn.Module):
    def __init__(self,width=16,heads=4,dropout=0.0):
        super().__init__()
        self.norm1 = nn.LayerNorm(width)
        self.attention = CausalHeads(width,heads,dropout)
        self.norm2 = nn.LayerNorm(width)
        self.ff = FeedForward(width)
        self.drop = nn.Dropout(dropout)
    def forward(self,x):
        x = x + self.drop(self.attention(self.norm1(x))[0])
        return x + self.drop(self.ff(self.norm2(x)))
class TinyGPT(nn.Module):
    def __init__(self,vocab_size,context=12,width=16,heads=4,layers=2,dropout=0.0):
        super().__init__()
        self.config = dict(vocab_size=vocab_size,context=context,width=width,heads=heads,layers=layers,dropout=dropout)
        self.token = nn.Embedding(vocab_size,width)
        self.position = nn.Embedding(context,width)
        self.drop = nn.Dropout(dropout)
        self.blocks = nn.ModuleList([TransformerBlock(width,heads,dropout) for _ in range(layers)])
        self.final_norm = nn.LayerNorm(width)
    def forward(self,ids):
        if ids.ndim != 2 or ids.shape[1] == 0 or ids.shape[1] > self.config["context"]:
            raise ValueError("Expected nonempty B,T IDs within context")
        positions = torch.arange(ids.shape[1],device=ids.device)
        x = self.drop(self.token(ids) + self.position(positions)[None])
        for block in self.blocks:
            x = block(x)
        x = self.final_norm(x)
        return F.linear(x,self.token.weight)  # Tied input/output weights.
vocab = ["<pad>","<eos>","<unk>","library","opens","at","nine","ten","room","is","free","busy","please","return","the","book","today","tomorrow","desk","closes","six","seven","reserve","a","quiet","seat","now"]
stoi = {word:i for i,word in enumerate(vocab)}
def encode(text,eos=False):
    ids = [stoi.get(word,stoi["<unk>"]) for word in text.lower().split()]
    return ids + ([stoi["<eos>"]] if eos else [])
def decode(ids):
    return " ".join(vocab[int(i)] for i in ids)
train_documents = ["library opens at nine","please return the book today","room is free today","reserve a quiet seat","desk closes at six","room is busy now"]
validation_documents = ["library closes at seven","please return the book tomorrow"]
test_documents = ["room is free tomorrow","desk opens at ten"]

Guided task 01

Configuration and Vocabulary Identity

A complete model needs a contract linking text, token IDs and output coordinates. The fixed vocabulary in setup gives each word or special token one stable integer. Input embedding row i and output logit coordinate i must refer to the same token. Two vocabularies of equal size are not interchangeable if their order differs.

Create a model with context length 12, width 16, four heads and two blocks. Its configuration describes structural dimensions, not learned language knowledge. The supplied encode helper performs a deliberately simple lowercase whitespace lookup and maps unknown words to an explicit unknown token. It is not a production subword tokenizer. Inspect the IDs for a short library announcement and decode them back. This is the point to catch vocabulary mismatches before any generated output or loss calculation is interpreted.

Try it

  1. Encode a four-word announcement.
  2. Create TinyGPT from the stated configuration.
  3. Connect each ID with its vocabulary entry.
Python · run in order
ids = torch.tensor([encode("library opens at nine")],dtype=torch.long)
model = TinyGPT(len(vocab),context=12,width=16,heads=4,layers=2,dropout=0)
fig,ax = plt.subplots(figsize=(7,3))
ax.bar(range(ids.shape[1]),ids[0].tolist())
ax.set_xticks(range(ids.shape[1]),decode(ids[0]).split())
ax.set(ylabel="Vocabulary ID",title="Input token identity")
fig.tight_layout()

Read the result

The bar heights are identifiers, not magnitudes of meaning or probabilities. Reordering the vocabulary would change what these numbers refer to even if the model's vocabulary dimension stayed the same.

Guided task 02

Token and Position Contributions

A token embedding supplies a learned feature vector for each input ID. A position embedding supplies a separate vector for the token's location within the current context. Their sum has the same B,T,C shape as either broadcast contribution. The position vector changes when the same word appears at another location, allowing a causal architecture to distinguish order rather than seeing only an unordered collection of words.

The tiny model uses learned absolute position embeddings indexed from zero. A sequence cannot exceed the number of stored position rows. Inspect token, position and summed arrays using a common signed scale; they are random feature values at this stage. Do not assign a natural-language meaning to a coordinate simply because it has a large value. The vocabulary and position tables are both trainable, but they represent different indexing systems and have different row counts.

Try it

  1. Look up token vectors and current position vectors.
  2. Broadcast positions across the batch.
  3. Inspect both contributions and their sum.
Python · run in order
positions = torch.arange(ids.shape[1])
token_features = model.token(ids)
position_features = model.position(positions)[None]
embedded = token_features + position_features
fig,axes = plt.subplots(1,3,figsize=(12,3.4))
limit=max(float(embedded.detach().abs().max()),float(token_features.detach().abs().max()),float(position_features.detach().abs().max()))
for ax,value,title in zip(axes,[token_features[0],position_features[0],embedded[0]],["Token embeddings","Position embeddings","Sum"]):
    artist=ax.imshow(as_array(value),cmap="coolwarm",vmin=-limit,vmax=limit,aspect="auto")
    ax.set(title=title,xlabel="Feature",ylabel="Token position")
    ax.set_xticks([0,4,8,12,15])
    ax.set_yticks(range(ids.shape[1]))
fig.colorbar(artist,ax=axes.tolist(),label="Embedding value")

Read the result

The two tables contribute to the same feature coordinates, so addition preserves width 16. Position IDs index the sequence, not the vocabulary, and are reused for another example occupying the same positions.

  • Check the model's rejection of a sequence longer than its configured context.

Guided task 03

The Complete Forward Path

The embedding sum enters the registered transformer blocks in order. Each block preserves the residual-stream dimensions while updating its contextual representation. A final LayerNorm prepares the feature vector that will be compared with vocabulary embeddings. The output projection then produces V logits at each of the T positions, rather than one score for the whole message.

Trace the path manually using the same model components, then compare it with model(ids). Dropout is zero here, so the two evaluations should match numerically. This catches mistakes such as skipping a block, using a different normalization site or projecting an earlier stream. Shape checks alone would not detect every one of those errors. The result is a functioning computation graph, but a complete architecture with random weights is still not a trained language model. Its role is to make later objectives and updates possible.

Try it

  1. Run the embedding stream through both blocks.
  2. Apply final normalization and the vocabulary projection.
  3. Compare with the complete forward method.
Python · run in order
stream = embedded
for block in model.blocks:
    stream = block(stream)
final_features = model.final_norm(stream)
manual_logits = F.linear(final_features,model.token.weight)
logits = model(ids)
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(logits[0])
limit = max(float(np.abs(shown).max()),1e-8)
artist = ax.imshow(shown,cmap="coolwarm",vmin=-limit,vmax=limit,aspect="auto")
ax.set(title="Vocabulary logits at every input position",xlabel="Vocabulary ID",ylabel="Token position")
ax.set_xticks(range(shown.shape[1]))
ax.set_yticks(range(shown.shape[0]))
fig.colorbar(artist,ax=ax,label="Value")
fig.tight_layout()

Read the result

Each row is a different next-token prediction site and each column refers to the fixed vocabulary. Logits can be positive or negative and do not need to sum to one. Their absolute scale will matter when probabilities are formed later.

Guided task 04

Tied Input and Output Weights

This teaching model ties the vocabulary output projection to the input embedding table. F.linear(final_features, model.token.weight) compares each feature vector with the same vocabulary rows used for token lookup. The table has shape V,C, which is exactly the weight shape required to map C features to V logits. No second learned V-by-C output matrix is allocated.

Weight tying is an architectural choice, not a universal requirement of every language model. It reduces separately stored parameters and couples the input and output roles during learning. A gradient for the shared table can contain contributions from both uses. Count it once when reporting model size. Tied random weights can also favor patterns such as repeating a current token; that does not indicate learned knowledge. Inspect one logit as a dot product to connect the parameter-sharing design with the actual score calculation.

Try it

  1. Select the final feature vector.
  2. Recompute all vocabulary scores with the shared table.
  3. Inspect several resulting scores with token labels.
Python · run in order
last_features = final_features[0,-1]
tied_scores = model.token.weight @ last_features
top_values,top_ids = torch.topk(tied_scores,5)
fig,ax=plt.subplots(figsize=(8,3.4))
ax.bar(range(5),as_array(top_values))
ax.set_xticks(range(5),[vocab[i] for i in top_ids.tolist()])
ax.set(ylabel="Unnormalized logit",title="Top shared-table dot products")
fig.tight_layout()

Read the result

The plotted scores come from one shared table, not from a separately initialized classifier head. The ranking reflects the current random architecture and should not be read as a meaningful answer to the announcement.

Guided task 05

Final-Position Next-Token Probabilities

To continue a prompt, use the logits at its final input position. That row predicts the token that follows the entire available prompt. Earlier rows correspond to shorter prefixes; selecting an earlier row would ask a different prediction question. Apply softmax over the vocabulary axis, not over time or examples.

Probabilities are normalized scores under the current model. They are not a guarantee that a statement is true, and random initialization does not supply meaningful confidence. Inspect the full distribution and record its largest entry. A narrow distribution can arise from the numerical scale of logits even in an untrained model. Greedy decoding chooses the largest logit or probability; softmax preserves that ordering. Keeping probability construction separate from the architecture will make temperature and top-k sampling easier to analyze in a later lesson.

Try it

  1. Select logits from the last prompt position.
  2. Normalize over the vocabulary.
  3. Compare the argmax of logits and probabilities.
Python · run in order
next_probabilities = logits[0,-1].softmax(dim=-1)
greedy_id = int(next_probabilities.argmax())
fig,ax=plt.subplots(figsize=(10,3.4))
ax.bar(range(len(vocab)),as_array(next_probabilities))
ax.set(xlabel="Vocabulary ID",ylabel="Probability",title=f"Next-token distribution; argmax={vocab[greedy_id]}")
ax.set_xticks(range(0,len(vocab),3))
fig.tight_layout()

Read the result

The probability sum is one because of the normalization rule, not because the model understands the prompt. The selected ID must still be decoded with the exact vocabulary used by the model's embedding and output table.

  • Multiply logits by two and inspect concentration without changing their argmax.

Guided task 06

Bounded Greedy Continuation

Autoregressive generation repeatedly predicts one next token and appends it to the prompt. The next call sees the extended sequence, so a four-token continuation requires four model calls in this straightforward implementation. Set eval mode and use no_grad for a deterministic inference path without storing training graphs. Stop at EOS or at an explicit maximum number of new tokens.

A context-limited model cannot accept an indefinitely growing prefix. The example keeps only the most recent configured number of IDs for each forward call, while retaining the full generated sequence for display. With learned absolute positions, this simple cropping resets position indices within the retained window. It is a documented small-model policy, not an unlimited-memory mechanism. The untrained output may repeat tokens or emit special tokens; keep those limitations visible instead of presenting the generated string as a useful assistant response.

Try it

  1. Start from a three-token library prompt.
  2. Append at most four greedy tokens.
  3. Record the chosen probability at each completed step.
Python · run in order
model.eval()
generated = torch.tensor([encode("library opens at")],dtype=torch.long)
chosen_ids,chosen_probabilities = [],[]
with torch.no_grad():
    for step in range(4):
        window = generated[:,-model.config["context"]:]
        step_logits = model(window)[:,-1]
        probabilities = step_logits.softmax(-1)
        next_id = step_logits.argmax(-1,keepdim=True)
        chosen_ids.append(int(next_id[0,0]))
        chosen_probabilities.append(float(probabilities[0,next_id[0,0]]))
        generated = torch.cat([generated,next_id],dim=1)
        if int(next_id[0,0])==stoi["<eos>"]:
            break
fig,ax=plt.subplots(figsize=(8,3.4))
ax.bar(range(len(chosen_ids)),chosen_probabilities)
ax.set_xticks(range(len(chosen_ids)),[f"{i+1}: {vocab[t]}" for i,t in enumerate(chosen_ids)])
ax.set(ylabel="Chosen-token probability",title="Bounded untrained greedy continuation")
fig.tight_layout()

Read the result

The chart reports actual chosen tokens and their model probabilities. Repetition or unusual output is expected from this untrained system. The explicit loop bound guarantees termination even if EOS is never selected.

Change and compare

  • Set the maximum new-token count to one and verify the final-position rule.
  • Use a prompt near the context limit and inspect which positions are retained after cropping.

Guided task 07

Full-Model Causal Consistency

The vocabulary head and final normalization must preserve the causal boundary established by the blocks. Compare two prompts with an identical three-token prefix and a different fourth token. Logits at the first three positions should match, because those positions cannot see the changed final input. The last row is allowed to change.

This full-model invariant checks embeddings, position handling, block order and output projection together. It complements the earlier component tests rather than replacing them. A vocabulary mismatch could still produce semantically wrong IDs while passing a causal test, and a faulty data split could still contaminate evaluation. Use different tests for different contracts. Keep dropout disabled during the comparison; otherwise random variation can obscure a genuine causal property. The model remains untrained, so this exercise validates information flow rather than linguistic accuracy.

Try it

  1. Create two four-token prompts differing only at the end.
  2. Run both in eval mode without gradients.
  3. Measure logit differences at each position.
Python · run in order
first_ids = torch.tensor([encode("library opens at nine")])
second_ids = torch.tensor([encode("library opens at ten")])
with torch.no_grad():
    first_logits = model(first_ids)
    second_logits = model(second_ids)
differences = (first_logits-second_logits).abs().amax(-1)[0]
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(list(range(4)),as_array(differences))
ax.set(title="Changing the last input token",ylabel="Maximum logit difference")
fig.tight_layout()

Read the result

A zero prefix difference is the expected architectural result. The last row can respond to the replacement word, but the test does not require any particular predicted token or claim that the two announcements are understood.

Change and compare

  • Change only the first input token and identify all positions allowed to respond.
  • Repeat with a second batch example to verify examples remain independent.

Guided task 08

Parameter Accounting and Gradient Reachability

Count trainable storage by registered parameter tensors, not by how many times a tensor is used during forward. The tied token table appears in both embedding lookup and output projection but is counted once. Separate the token table, position table, transformer blocks and final normalization so the architecture's storage cost is explainable.

Run a scalar mechanics objective on the logits and backpropagate to verify that the complete graph reaches the shared token table and block parameters. This objective is only a connectivity probe; next-token cross-entropy is introduced in the following lesson. A nonzero gradient does not show useful training progress. The tiny configuration makes every count inspectable and inexpensive, while a real pretrained checkpoint will have very different shapes, tokenizer identity and storage requirements. Do not assume that weights from a larger architecture can be loaded merely because both models are called GPT.

Try it

  1. Count parameters by architectural component.
  2. Backpropagate a finite scalar logit objective.
  3. Check the shared table and a block gradient.
Python · run in order
model.zero_grad(set_to_none=True)
probe_logits = model(ids)
probe_loss = probe_logits.square().mean()
probe_loss.backward()
component_counts = [model.token.weight.numel(),model.position.weight.numel(),sum(p.numel() for p in model.blocks.parameters()),sum(p.numel() for p in model.final_norm.parameters())]
total_count = sum(p.numel() for p in model.parameters())
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(["Token / tied head","Positions","Blocks","Final norm"],component_counts)
ax.set(title="Registered parameter accounting",ylabel="Trainable scalars")
fig.tight_layout()

Read the result

The counts describe actual allocated parameter elements in this model. The output head has no separate bar because it reuses the token table. Gradients confirm that this shared tensor participates in the complete computation.

Change and compare

  • Calculate the extra count for an untied bias-free output matrix.
  • Double the context length while keeping width and blocks fixed, then identify which component count changes.
