Normalization and Feed-Forward Layers

MaterialPracticeQuiz

Inspect the layers that stabilize and reshape each token's feature vector. Small numerical examples will make normalization, nonlinear activations and feed-forward computation visible.

Python · shared setup
import math
import json
import tempfile
from pathlib import Path
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
import matplotlib.pyplot as plt
torch.set_num_threads(1)
torch.manual_seed(109)
rng = np.random.default_rng(109)
def as_array(tensor):
    return tensor.detach().cpu().numpy()
class FeedForward(nn.Module):
    def __init__(self,width=16,expansion=4):
        super().__init__()
        self.up = nn.Linear(width,expansion*width)
        self.act = nn.GELU()
        self.down = nn.Linear(expansion*width,width)
    def forward(self,x):
        return self.down(self.act(self.up(x)))

Guided task 01

Per-Token Feature Statistics

Each token position carries a feature vector, not a single scalar. Layer normalization computes statistics over selected feature dimensions within that position. For a B,T,C tensor and normalized_shape=C, the batch and token axes remain separate. A room-booking message can therefore contain positions with very different means without borrowing statistics from another message.

Begin with supplied four-feature vectors so the reduction axes are inspectable. Mean over the last axis gives one value per token; keepdim=True retains a singleton feature axis for broadcasting. This is different from the training-dataset channel statistics used in image preprocessing. LayerNorm is an operation inside the model, using the current token vector whenever it runs. It does not fit a dataset mean and then freeze that mean for held-out inputs. Its learned affine parameters, introduced later, are a separate part of the layer.

Try it

  1. Create two batches with three four-feature positions.
  2. Reduce only the final axis and retain its dimension.
  3. Display one mean per example and token.
Python · run in order
x = torch.tensor([[[1.,2,3,4],[10,12,14,16],[-2,0,2,4]],[[4,3,2,1],[0,4,8,12],[3,3,3,3]]])
token_means = x.mean(dim=-1,keepdim=True)
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(token_means[...,0])
artist = ax.imshow(shown,cmap="viridis",aspect="auto")
ax.set(title="Mean within each token vector",xlabel="Token position",ylabel="Example")
fig.colorbar(artist,ax=ax)
ax.set_xticks(range(shown.shape[1]))
ax.set_yticks(range(shown.shape[0]))
fig.tight_layout()

Read the result

The matrix has one cell per token, not one cell per feature. No statistic combines the two examples. The constant final vector is legal input even though its variance will be zero, motivating an explicit numerical safeguard.

Change and compare

  • Reduce over the token axis instead and explain the changed meaning.
  • Add a constant to one token vector and inspect which mean changes.

Guided task 02

Variance, Epsilon and a Manual Calculation

Center the features, compute their mean squared deviation, add epsilon to that variance, and take the square root for the denominator. LayerNorm uses the population-style variance over the normalized features, equivalent to correction=0 or unbiased=False. Dividing by a sample standard deviation with an N−1 denominator would produce a different result, especially for these tiny vectors.

Epsilon belongs inside the square root in this definition. Adding it after the square root or replacing a small denominator with one is another rule. Compare a transparent tensor calculation against nn.LayerNorm with elementwise_affine=False. Agreement tests the axes, variance convention and epsilon placement together. The normalized mean is near zero, but the variance is generally slightly below one because epsilon increases the denominator. This matters when writing precise assertions: an exact unit-variance claim is not the formula being implemented.

Try it

  1. Compute centered values and population variance.
  2. Use sqrt(variance+1e−5).
  3. Compare with the matching PyTorch LayerNorm.
Python · run in order
centered = x - x.mean(dim=-1,keepdim=True)
variance = centered.square().mean(dim=-1,keepdim=True)
manual = centered / torch.sqrt(variance+1e-5)
layer = nn.LayerNorm(4,eps=1e-5,elementwise_affine=False)
automatic = layer(x)
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(manual[0])
limit = max(float(np.abs(shown).max()),1e-8)
artist = ax.imshow(shown,cmap="coolwarm",vmin=-limit,vmax=limit,aspect="auto")
ax.set(title="Manually normalized token features",xlabel="Feature",ylabel="Token position")
fig.colorbar(artist,ax=ax)
ax.set_xticks(range(shown.shape[1]))
ax.set_yticks(range(shown.shape[0]))
fig.tight_layout()

Read the result

Signed normalized values describe each coordinate relative to the other features of the same token. The constant vector in the second example becomes zero rather than creating NaN values, because epsilon keeps its denominator positive.

Change and compare

  • Compare unbiased=True with the population variance on one four-feature token.
  • Increase epsilon and observe why the normalized variance changes.

Guided task 03

Learned Scale and Shift

LayerNorm normally includes one learned scale and one learned shift for each normalized feature. After normalization, output=gamma×normalized+beta. With width four, that adds eight trainable scalar parameters, shared across every batch item and token position. They do not create a separate set of parameters for each token.

The initial gamma values are one and beta values are zero, but training can change them. Set explicit values under no_grad to study their roles without recording the assignment as a differentiable operation. Different feature scales can reshape the normalized pattern and different shifts can move its mean away from zero. Therefore the final affine LayerNorm output is not required to have zero mean or unit variance. The normalization calculation and the learned affine transformation should be inspected as two distinct stages of one layer.

Try it

  1. Create an affine LayerNorm with width four.
  2. Assign the supplied gamma and beta arrays.
  3. Compare its output with explicit feature-wise arithmetic.
Python · run in order
affine = nn.LayerNorm(4,eps=1e-5)
with torch.no_grad():
    affine.weight.copy_(torch.tensor([1.,2.,.5,1.]))
    affine.bias.copy_(torch.tensor([0.,.2,-.3,.1]))
affine_output = affine(x)
expected = manual*affine.weight + affine.bias
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(affine_output[0])
limit = max(float(np.abs(shown).max()),1e-8)
artist = ax.imshow(shown,cmap="coolwarm",vmin=-limit,vmax=limit,aspect="auto")
ax.set(title="LayerNorm after learned affine parameters",xlabel="Feature",ylabel="Token position")
fig.colorbar(artist,ax=ax)
ax.set_xticks(range(shown.shape[1]))
ax.set_yticks(range(shown.shape[0]))
fig.tight_layout()

Read the result

A shifted output mean is expected under these explicitly assigned beta values. The parameters operate on feature coordinates, so their meaning depends on keeping the final tensor axis consistent throughout the architecture.

Change and compare

  • Count scale and shift parameters for width 32.
  • Set gamma to zero and predict which values remain in the output.

Guided task 04

Constant Features and Finite Gradients

A constant feature vector has zero centered values and zero variance. Epsilon allows the forward normalized result to remain finite. The derivative can still depend strongly on epsilon: perturbing one coordinate breaks the equality among features, and the small denominator controls the sensitivity to that perturbation. A zero forward value does not imply a zero derivative for every possible objective.

Use a four-feature constant vector and backpropagate only the first normalized output coordinate. Compare epsilon 1e−5 with 1e−3 in otherwise identical, non-affine layers. These are actual autograd derivatives, not finite-difference estimates. Their norms should be finite, but the smaller epsilon allows larger sensitivity near this degenerate input. This illustrates why epsilon is a numerical design choice and why checking only the forward output can miss important behavior. It does not prescribe a universal optimum for a trained model.

Try it

  1. Create independent constant vectors requiring gradients.
  2. Normalize with two explicitly stated epsilons.
  3. Backpropagate one output coordinate and inspect gradients.
Python · run in order
gradient_rows = []
constant_outputs = []
for eps in [1e-5,1e-3]:
    constant = torch.full((1,4),3.,requires_grad=True)
    normalized = nn.LayerNorm(4,eps=eps,elementwise_affine=False)(constant)
    normalized[0,0].backward()
    gradient_rows.append(constant.grad[0].clone())
    constant_outputs.append(normalized.detach())
gradient_matrix = torch.stack(gradient_rows)
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(gradient_matrix)
limit = max(float(np.abs(shown).max()),1e-8)
artist = ax.imshow(shown,cmap="coolwarm",vmin=-limit,vmax=limit,aspect="auto")
ax.set(title="Derivative of first normalized coordinate",xlabel="Input feature",ylabel="Epsilon setting")
fig.colorbar(artist,ax=ax,label="Derivative")
ax.set_xticks(range(shown.shape[1]))
ax.set_yticks([0,1], ["1e-5", "1e-3"])
fig.tight_layout()

Read the result

One feature contributes positively and the others compensate through centering. Both output vectors are zero, yet the derivative arrays differ. This is a useful example of why forward values and sensitivity answer different questions.

Change and compare

  • Backpropagate the sum of normalized coordinates and explain the cancellation.
  • Perturb one input feature slightly and compare the finite output changes.

Guided task 05

Independence from Batch Companions

LayerNorm over the final feature dimension does not compute statistics across examples. A booking-message token should therefore receive the same normalized result whether another example in the batch has modest or extreme feature values. Test that statement directly by replacing only the second example and comparing the first one's output.

Unlike a training-mode BatchNorm layer, this LayerNorm has no running mean or running variance accumulated from batches. Its normalization rule is the same in train and eval modes; the mode difference seen in a larger model can instead come from components such as dropout. This distinction is important when reading an architecture: replacing LayerNorm with a similarly named normalization can change information dependencies and behavior. Learned gamma and beta remain shared parameters, but shared parameters do not mean shared per-batch statistics. Keep the normalized axes and the module's stateful behavior separate in your reasoning.

Try it

  1. Normalize a two-example input.
  2. Replace only its second example with large values.
  3. Compare the first output and train/eval behavior.
Python · run in order
norm = nn.LayerNorm(4)
pair = torch.randn(2,3,4)
changed_pair = pair.clone()
changed_pair[1] = changed_pair[1]*100+500
first = norm(pair)
second = norm(changed_pair)
norm.eval()
evaluation = norm(pair)
delta = (first-second).abs().amax(dim=-1)
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(delta)
artist = ax.imshow(shown,cmap="viridis",aspect="auto")
ax.set(title="Effect of changing one batch companion",xlabel="Token position",ylabel="Example")
fig.colorbar(artist,ax=ax)
ax.set_xticks(range(shown.shape[1]))
ax.set_yticks(range(shown.shape[0]))
fig.tight_layout()

Read the result

The unchanged example's difference row should be zero. The other example can change, though an exact positive scale-and-shift transformation is largely removed by LayerNorm apart from epsilon. That behavior follows from the feature-wise formula, not from a language interpretation.

Change and compare

  • Replace the companion with unrelated random values instead of a scale-and-shift change.
  • Add dropout after the layer and identify which component introduces a train/eval difference.

Guided task 06

GELU as a Smooth Nonlinearity

A feed-forward layer needs a nonlinearity between its two linear projections. Without one, the composition could be collapsed into a single affine transformation. GELU weights an input by the standard normal cumulative distribution at that input. It smoothly suppresses much of the negative range while allowing some negative outputs, unlike a hard zeroing rule.

Use PyTorch's exact GELU option, approximate='none', and plot both output and derivative over a supplied grid from−3 to 3. Backward on the sum yields each independent point's local derivative because each output depends only on its matching input. The derivative is not a probability and can exceed one or become slightly negative. Those properties are compatible with a smooth activation function. A plot explains the transformation's shape; it does not show learned token probabilities or establish why a particular trained language model performs well.

Try it

  1. Create a differentiable grid over−3..3.
  2. Evaluate exact GELU and backpropagate its sum.
  3. Plot outputs and derivatives on labeled axes.
Python · run in order
grid = torch.linspace(-3,3,121,requires_grad=True)
activation = F.gelu(grid,approximate="none")
activation.sum().backward()
fig,axes = plt.subplots(1,2,figsize=(9,3.5))
axes[0].plot(as_array(grid),as_array(activation))
axes[0].set(xlabel="Input",ylabel="GELU output",title="Smooth feature activation")
axes[1].plot(as_array(grid),as_array(grid.grad))
axes[1].set(xlabel="Input",ylabel="Derivative",title="Autograd sensitivity")
fig.tight_layout()

Read the result

The output curve is not a gate that chooses whole tokens. It transforms each feature value independently. The derivative panel is especially useful for distinguishing activation behavior from a normalized attention distribution.

Change and compare

  • Compare exact GELU with the tanh approximation on the same grid.
  • Remove GELU from a two-linear-layer calculation and derive the combined affine map.

Guided task 07

Expansion and Contraction

The feed-forward module expands the feature width, applies GELU and projects back to the original width. With C=8 and expansion factor 4, the intermediate width is 32. The batch and token dimensions pass through unchanged because nn.Linear transforms only the final axis. This creates additional nonlinear feature combinations without increasing the sequence length.

Count weights and biases explicitly: the first layer has 32×8 weights and 32 biases, while the second has 8×32 weights and 8 biases. GELU adds no trainable parameters. The output projection can combine the activated hidden coordinates, so the feed-forward module is not simply selecting or discarding one original feature. Expansion factor is a design choice; this small example explains its mechanics rather than claiming that more hidden units always improve a model. Returning to width 8 prepares the output for a residual connection in the next lesson.

Try it

  1. Run the setup FeedForward module with width 8.
  2. Inspect the expanded and activated intermediate arrays.
  3. Count all registered weights and biases.
Python · run in order
ff = FeedForward(8,expansion=4)
tokens = torch.randn(2,4,8)
expanded = ff.up(tokens)
activated = ff.act(expanded)
contracted = ff.down(activated)
ff_count = sum(p.numel() for p in ff.parameters())
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(activated[0])
limit = max(float(np.abs(shown).max()),1e-8)
artist = ax.imshow(shown,cmap="coolwarm",vmin=-limit,vmax=limit,aspect="auto")
ax.set(title="Expanded activated features",xlabel="Hidden feature",ylabel="Token position")
fig.colorbar(artist,ax=ax)
ax.set_xticks(range(shown.shape[1]))
ax.set_yticks(range(shown.shape[0]))
fig.tight_layout()

Read the result

Thirty-two hidden coordinates exist for each of the four token positions. The final projection reduces feature width again; it does not merge neighboring positions or shorten the message.

Change and compare

  • Change expansion factor to 2 and recount parameters.
  • Verify that applying the module to one token alone matches that token's output in the batch.

Guided task 08

Token-Wise Computation and Gradient Locality

A feed-forward layer reuses its parameters at every position but does not exchange information among positions. Attention provides that exchange elsewhere in the transformer. Altering one token's feature vector should therefore leave all other feed-forward outputs unchanged. The same property appears in gradients: an objective depending on only one output token has zero input gradients at other token positions.

Use the complete module to test both claims. Parameter gradients can still accumulate contributions whenever several tokens appear in an objective, because the same matrices are shared. That does not contradict input-gradient locality; shared learning and cross-token data flow are different ideas. This distinction prepares you to read a transformer block as a combination of contextual mixing and per-token feature processing. The test uses a scalar mechanics objective and newly initialized weights, so it measures the computational structure rather than any language skill.

Try it

  1. Change one token and compare other outputs.
  2. Backpropagate an objective on only token 2.
  3. Measure the input gradient norm at every position.
Python · run in order
probe = torch.randn(1,4,8,requires_grad=True)
result = ff(probe)
loss = result[:,2].square().sum()
loss.backward()
token_gradient_norms = probe.grad.norm(dim=-1)[0]
changed = probe.detach().clone()
changed[:,2] += 1
with torch.no_grad():
    changed_result = ff(changed)
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(list(range(4)),as_array(token_gradient_norms))
ax.set(title="Input gradients from one output token",ylabel="Gradient norm")
fig.tight_layout()

Read the result

Only the selected token should receive an input gradient in this standalone feed-forward calculation. In a full transformer, earlier attention may already have mixed contextual information into the vector before the feed-forward layer receives it.

Change and compare

  • Use an objective over all output tokens and inspect accumulated parameter gradients.
  • Compare this locality test with the causal-attention prefix test from the preceding lesson.
