Classification Data and Batching

MaterialPracticeQuiz

Turn short room requests into a well-defined classification dataset. You will make every batching choice visible before a model learns from it.

What you will learn

  • Define labels and independent request groups.
  • Build vocabulary without held-out records.
  • Track truncation and right-padding explicitly.
  • Audit batches without dropping evaluation examples.

torch.set_num_threads(1)

pairs = [
    (0, ('reserve a quiet room', 'please reserve the quiet room')),
    (1, ('cancel my quiet room', 'please cancel the quiet room')),
    (0, ('reserve a large room', 'please reserve the large room')),
    (1, ('cancel my large room', 'please cancel the large room')),
    (0, ('reserve a room today', 'please reserve my room today')),
    (1, ('cancel a room today', 'please cancel my room today')),
    (0, ('reserve the room tomorrow', 'please reserve a room tomorrow')),
    (1, ('cancel the room tomorrow', 'please cancel a room tomorrow')),
    (0, ('reserve a sunny room', 'please reserve the sunny room')),
    (1, ('cancel my sunny room', 'please cancel the sunny room')),
    (0, ('reserve a corner room', 'please reserve the corner room')),
    (1, ('cancel my corner room', 'please cancel the corner room')),
]
records = [dict(id=f'g{g}_v{v}', group=g, text=text, label=label)
           for g, (label, texts) in enumerate(pairs) for v, text in enumerate(texts)]
split_groups = {'train': set(range(8)), 'validation': {8, 9}, 'test': {10, 11}}
def words(text):
    return re.findall(r"[a-z]+", text.lower())
# Small plotting helpers display measured tensors and counts.
def bar_plot(labels, values, title, ylabel):
    fig, ax = plt.subplots(figsize=(7, 3.5))
    ax.bar(labels, np.asarray(values))
    ax.set(title=title, ylabel=ylabel)
    if np.all(np.asarray(values)==0):
        ax.set_ylim(0,1)
        ax.text(0.5,0.5,'All values are zero',transform=ax.transAxes,ha='center')
    fig.tight_layout()
    return fig

def heat_plot(values, title, xlabel, ylabel, label):
    array = values.detach().cpu().numpy() if isinstance(values, torch.Tensor) else np.asarray(values)
    fig, ax = plt.subplots(figsize=(7, 3.5))
    if np.any(array < 0):
        bound = max(float(np.abs(array).max()), 1e-8)
        view = ax.imshow(array, aspect='auto', interpolation='nearest', cmap='coolwarm', vmin=-bound, vmax=bound)
    else:
        view = ax.imshow(array, aspect='auto', interpolation='nearest', cmap='viridis', vmin=0, vmax=max(float(array.max()),1e-8))
    ax.set_xticks(np.unique(np.linspace(0,array.shape[1]-1,min(8,array.shape[1])).astype(int)))
    ax.set_yticks(np.unique(np.linspace(0,array.shape[0]-1,min(8,array.shape[0])).astype(int)))
    ax.set(title=title, xlabel=xlabel, ylabel=ylabel)
    fig.colorbar(view, ax=ax, label=label)
    fig.tight_layout()
    return fig

Guided task 01

Labels describe the requested action

A classifier produces one label for a complete message, rather than one next-token target at every position. Our two labels mean reserve a room and cancel a room request. The numeric mapping is part of the dataset contract: zero means reserve and one means cancel. These integers are category identifiers, not a statement that cancel is a larger quantity than reserve.

Each pair in setup contains two phrasings of the same request. The group identifies that shared origin, while the record ID identifies one wording. Keeping both fields prevents us from confusing the number of messages with the number of independent requests. The examples are deliberately small and keyword-rich so that batching decisions are easy to inspect. They are not a representative service-desk benchmark. A real collection would also need a policy for ambiguous messages, multiple actions and requests outside these two categories. Do not silently assign every possible sentence one of the two labels merely because the model has two output units.

Try it

  1. Inspect the label mapping and the first related pair.
  2. Count records and distinct request groups per class.
  3. Plot both counts with explicit units.
Python · run in order
label_names = ['reserve', 'cancel']
record_counts = [sum(r['label'] == c for r in records) for c in range(2)]
group_counts = [len({r['group'] for r in records if r['label'] == c}) for c in range(2)]
fig, ax = plt.subplots(figsize=(7, 3.5))
positions = np.arange(2)
ax.bar(positions-0.18, record_counts, width=0.36, label='Messages')
ax.bar(positions+0.18, group_counts, width=0.36, label='Request groups')
ax.set(xticks=positions, xticklabels=label_names, ylabel='Count', title='Messages and independent request groups')
ax.legend()
fig.tight_layout()

Compare message counts with group counts. Counting two phrasings as two independent requests would overstate how much different evidence the collection contains.

Guided task 02

Split related requests before processing

A held-out message should not be a lightly reworded copy of a training request when the intended question concerns new requests. Assign groups first, then collect all their records. The supplied split uses groups zero through seven for training, eight and nine for validation, and ten and eleven for test. Every view inherits its group's role.

This explicit assignment is useful for a teaching fixture because membership can be checked without relying on hidden random state. In larger datasets, a seeded group allocation may be appropriate, but saving the resulting IDs is still important. Class counts and group coverage should be inspected after splitting. Equal class counts here do not prove equal difficulty or establish statistical reliability. Validation supports development choices; the final test collection stays untouched while selecting settings. Creating variants before a row-level random split would undermine these roles because related evidence could cross the boundary even when all filenames are different. Preserve source relationships before tokenization makes near-identical records less obvious.

Try it

  1. Collect records from the three supplied group sets.
  2. Check disjoint groups and complete record coverage.
  3. Plot message counts by split and class.
Python · run in order
parts = {name: [r for r in records if r['group'] in groups] for name, groups in split_groups.items()}
counts = np.array([[sum(r['label']==c for r in parts[name]) for c in range(2)] for name in split_groups])
fig = heat_plot(counts, 'Actual split class counts', 'Class: 0 reserve, 1 cancel', 'Split: train, validation, test', 'Messages')

Read the result

The matrix summarizes the declared allocation. Disjoint group IDs and complete coverage are separate checks from a visually balanced class matrix.

  • Add a hypothetical third wording to one group and determine its split.
  • Explain why unique filenames alone cannot prove independence.

Guided task 03

Fit a vocabulary on training messages

A small word vocabulary makes the data flow transparent. Lowercase the text, extract alphabetic words, and assign stable IDs to the sorted training vocabulary. Reserve zero for padding and one for unknown words. These choices are a teaching tokenizer, not a claim that word splitting handles arbitrary language as well as a pretrained subword tokenizer.

Only training messages contribute vocabulary entries. Validation can therefore contain a word that maps to the unknown ID, which is expected under this contract. Expanding the vocabulary after inspecting held-out text would change the fitted preprocessing rule. Measure unknown coverage without quietly repairing it with evaluation data. In a real pretrained route, the checkpoint's existing tokenizer remains authoritative instead of fitting this toy vocabulary. The token IDs have no useful numeric ordering beyond lookup: a large ID is not more important than a small one. Record the normalization rule and special IDs along with the vocabulary, since changing any of them can invalidate previously saved model inputs.

Try it

  1. Create sorted training words with PAD and UNK IDs.
  2. Encode training and validation messages without refitting.
  3. Compare the fraction of unknown word tokens.
Python · run in order
training_words = sorted({w for r in parts['train'] for w in words(r['text'])})
vocab = {'<pad>':0, '<unk>':1, **{w:i+2 for i,w in enumerate(training_words)}}
def encode(text):
    return [vocab.get(w,1) for w in words(text)]
unknown_rates = []
for name in ['train','validation']:
    flat = [token for r in parts[name] for token in encode(r['text'])]
    unknown_rates.append(sum(token==1 for token in flat)/len(flat))
fig = bar_plot(['Training','Validation'], unknown_rates, 'Unknown tokens under one training vocabulary', 'Fraction of word tokens')

Read the result

Unknown validation words reveal the declared vocabulary boundary. They do not justify refitting on validation, and their frequency alone is not a classification score.

Change and compare

  • Find one held-out word that maps to UNK.
  • Change the case of a training sentence and inspect the normalization rule.

Guided task 04

Truncation is a content decision

A maximum length bounds memory and the model's positional range, but also decides which text survives. Prefix truncation keeps the first tokens and discards the suffix. That policy can lose the actual requested action when a message begins with polite context and ends with a correction. The effect is semantic, even when the resulting tensor has the expected shape.

Inspect a deliberately longer request before adopting a limit. Count the retained and discarded words and show their positions. The demonstration does not change the dataset's labels or claim that this particular truncated message should remain a valid training example. A production collection needs a declared strategy: choose a justified limit, reject overly long examples, or use a task-appropriate alternative. Fit any length choice using training-side evidence and development requirements, not repeated test inspection. Preserve lengths after truncation so later pooling selects a real retained position. Padding added afterward is not recovered context, and it should never be described as making the shortened message complete.

Try it

  1. Tokenize the supplied long request.
  2. Keep its first six words and record what was discarded.
  3. Display word positions with the retention decision.
Python · run in order
long_words = words('please read this update about my room request cancel it')
limit = 6
retained = long_words[:limit]
discarded = long_words[limit:]
fig, ax = plt.subplots(figsize=(9,3.5))
ax.bar(np.arange(len(long_words)), [1 if i<limit else 0.25 for i in range(len(long_words))])
ax.set(xticks=np.arange(len(long_words)), xticklabels=long_words, ylabel='1 retained; 0.25 discarded', title='Prefix truncation and missing action words')
ax.tick_params(axis='x', rotation=35)
fig.tight_layout()

Read the result

The action near the end is lost under this prefix limit. Legal tensor length does not establish that the original label is still supported by the retained text.

  • Describe a rejection policy for requests whose decisive content is truncated.

Guided task 05

Right padding carries an attention mask

Batching requires rectangular tensors even when messages have different lengths. Right padding appends a reserved value after the real tokens. Store a separate boolean valid mask based on lengths; this is the authoritative record of which positions contain message content. Padding is not a word and should not become a training label or a useful feature merely because it occupies storage.

Construct one short and one longer message, pad only to the longest member of the batch, and retain lengths explicitly. For classification, labels form a one-dimensional vector with one entry per row. A later causal model will combine its future-token restriction with the key-padding mask. The two masks answer different questions: which positions occur later, and which positions are not real input at all. With right padding, the last valid index is length minus one. Reject empty token sequences before using that formula, because zero length would produce a negative index that silently selects the wrong position. The next lesson will verify padding invariance at the model boundary.

Try it

  1. Encode two differently sized requests.
  2. Build right-padded token IDs and a length-derived boolean mask.
  3. Inspect the mask independently from the stored padding values.
Python · run in order
sequences = [encode('reserve room'), encode('please cancel the quiet room')]
lengths = torch.tensor([len(s) for s in sequences], dtype=torch.long)
ids = torch.zeros((2,int(lengths.max())), dtype=torch.long)
for i, sequence in enumerate(sequences):
    ids[i,:len(sequence)] = torch.tensor(sequence)
valid = torch.arange(ids.shape[1])[None,:] < lengths[:,None]
labels = torch.tensor([0,1], dtype=torch.long)
fig = heat_plot(valid.int(), 'Real tokens in a right-padded batch', 'Position', 'Message row', '1 real; 0 padding')

Read the result

The shorter row has storage positions that do not represent words. Its class label remains one scalar, and the later classifier must pool from its final real token.

Change and compare

  • Pad both rows to eight positions and keep their real lengths unchanged.
  • Explain why an attention mask is still necessary when padding reuses an EOS token in a pretrained tokenizer.

Guided task 06

A reusable collator has boundary checks

A collator turns a list of dataset records into one batch. Keep tokenization, truncation, padding and label construction together so their assumptions cannot drift between training and inference. The helper below accepts a positive token limit, rejects an empty batch, and rejects a message whose normalized token sequence is empty. It returns IDs, validity and class labels in a fixed order.

These checks are useful because silent defaults can hide data problems. An empty message is not equivalent to a one-token unknown message, and an empty batch should not enter a maximum-length reduction. The supplied labels are already validated by our fixed fixture; a larger ingestion pipeline would validate their mapping too. A collator should not randomly change the label or fit a vocabulary every time it is called. All rows share one previously fitted mapping. Examine the mask for several real training records and compare its row sums with their truncated lengths. This makes a reusable function testable without requiring a classifier or an optimizer.

Try it

  1. Implement the collator using the frozen vocabulary.
  2. Check the limit and reject empty inputs explicitly.
  3. Collate three training records and inspect their real-position counts.
Python · run in order
def collate(rows, limit=12):
    if not rows or limit < 1:
        raise ValueError('Require records and a positive limit.')
    sequences = [encode(r['text'])[:limit] for r in rows]
    if any(len(s)==0 for s in sequences):
        raise ValueError('Empty token sequence.')
    lengths = torch.tensor([len(s) for s in sequences])
    ids = torch.zeros((len(rows),int(lengths.max())), dtype=torch.long)
    for i, sequence in enumerate(sequences):
        ids[i,:len(sequence)] = torch.tensor(sequence)
    valid = torch.arange(ids.shape[1])[None,:] < lengths[:,None]
    labels = torch.tensor([r['label'] for r in rows], dtype=torch.long)
    return ids,valid,labels
batch_ids,batch_valid,batch_labels = collate(parts['train'][:3])
fig = bar_plot(['Row 0','Row 1','Row 2'], batch_valid.sum(1).numpy(), 'Real token counts returned by the collator', 'Tokens')

Read the result

The count for each row describes retained content rather than padded width. The function returns the same label order as the incoming record list.

Change and compare

  • Call the collator with an empty list and inspect the exception.
  • Use a smaller positive limit and check the resulting mask lengths.

Guided task 07

Data loaders preserve evaluation coverage

A data loader selects groups of records and calls the collator for each batch. Training may shuffle record order, while evaluation should use a fixed order and include every intended example. Set drop_last to False for evaluation so a short final batch is not silently removed. Losing a few records can change a small dataset's measured accuracy considerably.

The demonstration uses five records and a batch size of three, making the remainder visible. Iterating over the loader should therefore produce batches of three and two. The final batch does not need to be padded with extra examples; only token positions inside each actual message batch need padding. Use num_workers equal to zero for this small portable classroom run. Larger throughput settings belong to measured optimization rather than correctness. Keep record selection separate from shuffling: changing a random seed must not move a request from training into test. Count consumed labels to verify coverage, and later aggregate loss using example counts rather than averaging batch means equally when batch sizes differ.

Try it

  1. Build a five-record demonstration loader with batch size three.
  2. Use fixed order and retain the final partial batch.
  3. Measure how many examples each batch contains.
Python · run in order
loader = torch.utils.data.DataLoader(parts['train'][:5], batch_size=3, shuffle=False, drop_last=False, num_workers=0, collate_fn=collate)
batch_sizes = [len(y) for x,mask,y in loader]
fig = bar_plot(['Batch 0','Batch 1'], batch_sizes, 'Evaluation-style loader retains the remainder', 'Examples')

Read the result

The second batch is smaller but still contributes real examples. A later loss calculation should weight batch contributions by the number of examples they contain.

Change and compare

  • Explain why token padding must not create extra classification labels.

Guided task 08

Audit the complete preparation

A dataset audit combines structural checks with documented meanings. Count groups, messages, class labels and retained token lengths for each split, then preserve the vocabulary and preprocessing configuration. These facts let a later classifier interpret its tensors correctly and make it possible to diagnose changes when the dataset grows.

This final check does not train a model or establish useful real-world classification performance. The toy messages have clear repeated keywords, and their limited variety makes them unsuitable for broad conclusions. The audit instead verifies that the intended examples survive preparation, related phrasings remain together, and the mapping stays fixed. Save the label names, lowercasing rule, special IDs, token limit and right-padding convention as plain data. A model state alone cannot reconstruct these meanings. When moving to a pretrained tokenizer, replace this vocabulary contract with the checkpoint tokenizer identity and its exact padding policy, while retaining the same group and evaluation principles. The next lesson builds a head on representations without changing these data roles.

Try it

  1. Prepare every split with the same collator.
  2. Record sample counts and maximum retained lengths.
  3. Build a JSON-safe configuration of label and tokenizer meanings.
Python · run in order
audit = {}
for name, rows in parts.items():
    x,mask,y = collate(rows)
    audit[name] = {'messages':len(rows), 'groups':len({r['group'] for r in rows}), 'max_length':int(mask.sum(1).max())}
configuration = {'labels':{'reserve':0,'cancel':1},'vocab':vocab,'normalization':'lowercase alphabetic words','pad_id':0,'unk_id':1,'max_tokens':12,'padding_side':'right'}
configuration_text = json.dumps(configuration)
fig = bar_plot(list(audit), [a['max_length'] for a in audit.values()], 'Maximum retained length per split', 'Word tokens')

Read the result

These lengths document the actual prepared fixture. They are not a reason to adjust the preprocessing policy after examining final test performance.
