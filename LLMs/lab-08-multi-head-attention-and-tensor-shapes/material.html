Multi-Head Attention and Tensor Shapes

MaterialPracticeQuiz

Follow several attention heads through one small message batch. You will connect every tensor axis to a concrete role and test that future tokens cannot affect earlier outputs.

What you will learn

  • Trace B,T,C and B,H,T,D representations.
  • Compute scaled causal attention independently in each head.
  • Merge head outputs without mixing token positions.
  • Check dropout behavior, gradients and prefix consistency.

Before this lab: Use trainable queries, keys, values, causal masking and basic PyTorch tensors.

Python · shared setup
import math
import json
import tempfile
from pathlib import Path
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
import matplotlib.pyplot as plt
torch.set_num_threads(1)
torch.manual_seed(108)
rng = np.random.default_rng(108)
def as_array(tensor):
    return tensor.detach().cpu().numpy()
class CausalHeads(nn.Module):
    def __init__(self, width=16, heads=4, dropout=0.0):
        super().__init__()
        if width % heads:
            raise ValueError("width must be divisible by heads")
        self.width, self.heads, self.head_dim = width, heads, width // heads
        self.qkv = nn.Linear(width, 3*width, bias=False)
        self.proj = nn.Linear(width, width, bias=False)
        self.attn_drop = nn.Dropout(dropout)
    def forward(self, x):
        b,t,c = x.shape
        packed = self.qkv(x).reshape(b,t,3,self.heads,self.head_dim)
        q,k,v = packed.permute(2,0,3,1,4).unbind(0)
        scores = (q @ k.transpose(-2,-1)) / math.sqrt(self.head_dim)
        future = torch.triu(torch.ones(t,t,device=x.device,dtype=torch.bool),diagonal=1)
        weights = scores.masked_fill(future,float("-inf")).softmax(dim=-1)
        context = self.attn_drop(weights) @ v
        merged = context.transpose(1,2).contiguous().reshape(b,t,c)
        return self.proj(merged), weights

Guided task 01

Naming the Tensor Axes

Imagine two short room-booking messages, each represented by five token vectors. Their feature tensor has shape (2,5,12): two examples, five positions and twelve features per position. A head split with three heads gives four features per head. The divisibility condition concerns model width and head count, not the number of tokens or messages.

Use sequential numbers before random embeddings so every element can be traced. Reshaping B,T,C into B,T,H,D partitions the last dimension; transposing the middle axes then yields B,H,T,D. The numbers are demonstration coordinates, not learned language features. Inspecting one position makes a shape error visible even when the total number of elements remains unchanged. A successful reshape proves only that the element count fits. It cannot prove that the new axes carry the intended meaning.

Try it

  1. Create a traceable two-message feature tensor.
  2. Split width twelve into three groups of four.
  3. Inspect head slices from the first token.
Python · run in order
x = torch.arange(2*5*12,dtype=torch.float32).reshape(2,5,12)
split = x.reshape(2,5,3,4).transpose(1,2)
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(split[0,:,0,:])
artist = ax.imshow(shown,cmap="viridis",aspect="auto")
ax.set(title="First token partitioned across heads",xlabel="Within-head feature",ylabel="Head")
fig.colorbar(artist,ax=ax)
fig.tight_layout()

Read the result

Read each row as one head's slice of the first token. The next token must remain the next position in every head; a tensor with the correct overall size can still scramble this relationship.

  • Try width twelve with five heads and explain why the split is invalid.

Guided task 02

Packed Query, Key and Value Projections

Three learned projections produce queries, keys and values. Packing them into one linear layer is an implementation choice: a width-twelve input is projected to thirty-six features, which are then unpacked into the three roles. Each role still contains all twelve projected coordinates before the head split. The three roles must not be confused with the three heads.

A linear layer acts on the last dimension, so the same projection parameters are reused at every token and in every example. The output's other axes are preserved. The setup implementation arranges packed output as B,T,3,H,D and permutes to 3,B,H,T,D before unpacking. Its weight matrix has shape (36,12) because PyTorch stores output features first. These random weights demonstrate the computation; visually different query and key arrays do not yet represent discovered grammatical relationships.

Try it

  1. Project a small random batch into packed QKV features.
  2. Unpack the role axis before using attention.
  3. Check one query slice against the matching packed coordinates.
Python · run in order
features = torch.randn(2,5,12)
projection = nn.Linear(12,36,bias=False)
packed = projection(features)
roles = packed.reshape(2,5,3,3,4).permute(2,0,3,1,4)
q,k,v = roles.unbind(0)
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(q[0,0])
limit = max(float(np.abs(shown).max()),1e-8)
artist = ax.imshow(shown,cmap="coolwarm",vmin=-limit,vmax=limit,aspect="auto")
ax.set(title="Query features: message 0, head 0",xlabel="Within-head feature",ylabel="Token position")
fig.colorbar(artist,ax=ax)
fig.tight_layout()

Read the result

The query display contains five positions and four head features. Its signed values are projection outputs rather than attention probabilities. Inspect the corresponding key and value slices before moving on to pairwise scores.

  • Replace the packed projection with three copied weight slices and compare outputs.
  • Count parameters with and without a projection bias.

Guided task 03

Scores Within Each Head

Each query compares with every key in its own head and example. The matrix product Q@Kᵀ therefore has shape B,H,T,T. Its final two axes are query position and key position; the head axis is not summed away. Scaling by the square root of D uses the number of features contributing to each dot product, not the total model width.

This scaling moderates the typical size of dot products as head dimension changes. It does not constrain scores to a probability range, and it does not guarantee equal distributions across trained heads. Before masking or softmax, scores can be negative and future positions are still present. Inspect all heads on a common symmetric color scale so automatic rescaling does not hide differences. The example remains untrained: variations reveal distinct learned-parameter slots, not established semantic specialization.

Try it

  1. Compute all pairwise scores without collapsing heads.
  2. Divide by sqrt of the head dimension four.
  3. Display three score matrices with shared limits.
Python · run in order
scores = (q @ k.transpose(-2,-1)) / math.sqrt(4)
fig,axes = plt.subplots(1,3,figsize=(11,3.4))
limit = max(float(scores[0].detach().abs().max()),1e-8)
for head,ax in enumerate(axes):
    artist = ax.imshow(as_array(scores[0,head]),cmap="coolwarm",vmin=-limit,vmax=limit)
    ax.set(title=f"Head {head}",xlabel="Key",ylabel="Query")
fig.colorbar(artist,ax=axes.tolist(),label="Scaled dot-product score")

Read the result

A row describes one query's comparisons, while a column identifies a possible source key. No causal rule has been imposed yet. The shared color scale supports a numerical comparison without suggesting that one head is inherently more useful.

Change and compare

  • Verify one score using an explicit four-term dot product.
  • Compare scaling by sqrt(4) and sqrt(12) while keeping the projected tensors fixed.

Guided task 04

One Causal Rule Broadcast Across Heads

The causal mask excludes key positions later than the current query. With rows representing queries, the forbidden region is the strictly upper triangle. A T-by-T Boolean mask broadcasts across the batch and head axes because every example uses the same positional rule in this equal-length exercise. Each head may assign different weights within the allowed region.

Fill forbidden scores with negative infinity before softmax along the key axis. Their exponentials become zero, while every row retains at least its own position and therefore has a valid normalization denominator. Masking after softmax without renormalizing would remove probability mass and produce a different computation. The weights shown here are before attention dropout, so each row sums to one. Later dropout changes that per-realization property while preserving the causal zeros.

Try it

  1. Create the strictly upper-triangular forbidden mask.
  2. Apply it before softmax along the last axis.
  3. Verify zeros on every future key in every head.
Python · run in order
future = torch.triu(torch.ones(5,5,dtype=torch.bool),diagonal=1)
weights = scores.masked_fill(future,float("-inf")).softmax(dim=-1)
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(weights[0,1])
artist = ax.imshow(shown,cmap="viridis",aspect="auto")
ax.set(title="Causal weights: head 1",xlabel="Key position",ylabel="Query position")
fig.colorbar(artist,ax=ax)
fig.tight_layout()

Read the result

The first row has exactly one allowed source, while later rows can distribute weight over longer prefixes. Zero weights in the future triangle encode the architecture's information restriction, not an empirical pattern learned from the sample messages.

  • Check row sums in all six example/head combinations.
  • Change only the final input token and predict which earlier outputs should remain unchanged.

Guided task 05

Context Vectors and Head Merging

Attention weights multiply values, producing one context vector per query in each head. The product has shape B,H,T,D: the source-key axis is summed, while query position remains. Before concatenating heads, move the token axis back ahead of the head axis. Merging B,T,H,D then restores B,T,C without blending different token positions.

A transpose usually changes strides rather than physically rearranging the storage. Calling contiguous before view or reshape makes the intended layout explicit. The final learned output projection can combine information across the concatenated head features; attention inside each head did not do that mixing. The width remains constant so a later residual path can add tensors position by position. Correct shape and a traceable slice are both valuable checks, because a mistaken reshape may return the desired dimensions while scrambling their meaning.

Try it

  1. Combine causal weights with values.
  2. Transpose back to token-major order and concatenate heads.
  3. Apply a width-preserving output projection.
Python · run in order
context = weights @ v
merged = context.transpose(1,2).contiguous().reshape(2,5,12)
output_projection = nn.Linear(12,12,bias=False)
output = output_projection(merged)
fig,ax = plt.subplots(figsize=(6,3.7))
shown = as_array(merged[0])
limit = max(float(np.abs(shown).max()),1e-8)
artist = ax.imshow(shown,cmap="coolwarm",vmin=-limit,vmax=limit,aspect="auto")
ax.set(title="Merged contexts before output projection",xlabel="Concatenated feature",ylabel="Token position")
fig.colorbar(artist,ax=ax)
fig.tight_layout()

Read the result

The first four columns belong to one head, the next four to another, and the last four to the third. The output projection that follows is free to mix those groups while keeping each token at its original position.

  • Reshape without the transpose as a deliberate fault and identify the scrambled coordinates.

Guided task 06

Attention Dropout and Evaluation Mode

Attention dropout randomly zeros some normalized weights during training and scales retained entries by one divided by the keep probability. Individual post-dropout rows do not generally sum to one. Their expected values match the original weights, but expectation is not a promise about any one displayed matrix. Causal zeros remain zero because multiplying a forbidden zero by any dropout factor still gives zero.

Use the same pre-dropout matrix for a training-mode and evaluation-mode comparison. Evaluation mode disables the dropout operation; it does not disable gradient tracking. Conversely, no_grad prevents graph recording but does not switch a module out of training mode. These controls answer different questions and both matter when reproducible evaluation is introduced later. Avoid interpreting a sparse training realization as a head permanently abandoning those keys. The next call can retain a different subset.

Try it

  1. Create dropout with probability 0.4.
  2. Compare one training realization with evaluation output.
  3. Inspect row sums before and after the random operation.
Python · run in order
drop = nn.Dropout(.4)
drop.train()
torch.manual_seed(608)
dropped = drop(weights.detach())
drop.eval()
evaluation_weights = drop(weights.detach())
fig,axes = plt.subplots(1,2,figsize=(8,3.4))
upper = max(float(dropped.max()),1.0)
for ax,array,title in zip(axes,[dropped[0,1],evaluation_weights[0,1]],["Training dropout","Evaluation weights"]):
    artist=ax.imshow(as_array(array),vmin=0,vmax=upper)
    ax.set(title=title,xlabel="Key",ylabel="Query")
fig.colorbar(artist,ax=axes.tolist(),label="Weight after selected mode")

Read the result

Retained training weights can exceed their original values because of inverse-keep scaling. The evaluation panel equals the normalized matrix. Neither mode changes the structural mask or the meaning of the head and position axes.

Change and compare

  • Use probability zero as an identity boundary check.
  • Call dropout under no_grad while it remains in train mode and distinguish the two controls.

Guided task 07

A Registered Multi-Head Module

The setup's CausalHeads class packages the operations you have inspected: packed projection, head split, scaled scores, causal softmax, optional dropout, context merge and output projection. Assigning linear layers as module attributes registers their parameters so an optimizer can find them. A plain tensor stored without Parameter or a registered submodule would not behave the same way.

Create a width-twelve, three-head instance and run a small differentiable objective: mean squared output magnitude. This is a mechanics probe, not a language-model training goal. Backward populates gradients for both projection matrices and the input when requires_grad is enabled. Gradient existence shows that the paths participate in the computation; it does not demonstrate useful language learning. Count parameters directly from the module and compare with the two matrix shapes. With no biases, the total is 3C²+C².

Try it

  1. Run the complete module on a differentiable input.
  2. Backpropagate a scalar mechanics objective.
  3. Inspect registered projection gradients and parameter count.
Python · run in order
module = CausalHeads(12,3,dropout=0)
probe = torch.randn(2,5,12,requires_grad=True)
result,attention = module(probe)
objective = result.square().mean()
objective.backward()
parameter_count = sum(p.numel() for p in module.parameters())
gradient_norms = [float(module.qkv.weight.grad.norm()),float(module.proj.weight.grad.norm()),float(probe.grad.norm())]
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(["QKV weight","Output weight","Input"],gradient_norms)
ax.set(title="Measured gradient paths",ylabel="Gradient norm")
fig.tight_layout()

Read the result

The plotted norms come from one real backward pass through this newly initialized module. Nonzero gradients verify a connected computation, while the separate parameter count verifies that the intended learned matrices are actually registered.

Change and compare

  • Set the input to require no gradient and check that parameter gradients still exist.
  • Compare parameter counts for one head and three heads at the same total width.

Guided task 08

Prefix Consistency as a Structural Test

A causal module should give the same earlier outputs when only later input positions change. Evaluate one sequence and a copy whose final two token vectors are replaced, keeping weights and mode fixed. Positions before the changed suffix have identical allowed keys and values, so their outputs should match up to floating-point precision. A later position can change because it is allowed to use the altered content.

This checks the complete module rather than only inspecting its mask variable. A correct-looking mask does not help if another implementation path accidentally bypasses it or mixes token axes during merging. Disable dropout to avoid confusing random variation with information leakage. The test does not prove that all padding policies or variable-length cases are correct; those require their own contracts. It establishes one focused causal invariant for the equal-length, unpadded tensors used throughout this lesson.

Try it

  1. Switch the complete module to evaluation mode.
  2. Modify only positions three and four.
  3. Plot per-position maximum output differences.
Python · run in order
module.eval()
original = torch.randn(1,5,12)
changed = original.clone()
changed[:,3:] += 4
with torch.no_grad():
    before,_ = module(original)
    after,_ = module(changed)
position_error = (before-after).abs().amax(dim=-1)[0]
fig,ax = plt.subplots(figsize=(7,3.4))
ax.bar(list(range(5)),as_array(position_error))
ax.set(title="Suffix-change effect by position",ylabel="Maximum absolute output change")
fig.tight_layout()

Read the result

Earlier positions should remain unchanged, while later outputs may respond. This is a test of permitted information flow, not a test of whether the random module knows how to interpret a booking message.

Change and compare

  • Change only the first position and explain why every later position is permitted to respond.
  • Deliberately remove the causal mask in a copy and use the invariant to expose the fault.
